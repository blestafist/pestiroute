---
description: Complete up to N ready tasks, optionally restricted to one milestone in an isolated worktree
agent: orchestrator
subagent: false
---

Execute `/next $ARGUMENTS` for this PestiRoute checkout. Accept exactly `N` or `N MILESTONE`, for example `/next 10`, `/next 10 M8`, or `/next 10 M9`. N must be one positive decimal integer. An optional milestone must exactly match a registered milestone prefix (for example M8, M9, or M5.1), not a task ID. Reject missing/malformed counts, unknown milestones, or extra arguments before changing anything. N is the maximum number of **newly completed** registered tasks, not a time budget or permission to expand scope.

With a milestone, select only task IDs with that exact prefix followed by `-`: M8 matches M8-001, not M80-001. Apply the filter to preparation, dispatch, closure, counting, and commits throughout the invocation. Stop when that lane cannot progress; do not fall through to another milestone. Without a milestone, retain the original coordinated single-checkout backlog workflow. Parallel sessions must supply the milestone and use separate Git worktrees as documented in `docs/implementation/PARALLEL.md`.

Continue autonomously, one task at a time, until that many tasks are DONE, the user stops you, or no in-scope task can make progress. Do not end after a single task merely to ask whether to continue. This command starts a bounded session workflow; it does not schedule background execution after the session ends.

1. Read `docs/implementation/CURRENT.md`, the relevant `docs/implementation/TASKS.md` rows, and the working-tree status. Have git-worker verify the worktree path, branch, base revision, and upstream. For M8/M9 lanes require `dev-m8`/`dev-m9` respectively; stop on a mismatch instead of switching branches beneath another session. Require independent worktree files/index/HEAD, a lane-specific TMPDIR and `GOFLAGS=-p=1` for simultaneous process checks. Preserve unrelated changes. Resume an ACTIVE task only if its owner and work state can be reconciled; never silently take over another owner's work.
2. Ask the planner to select the next task whose dependencies are DONE. A DRAFT row is not executable: have the planner prepare its card and concrete check, then require READY before dispatch. If a decision or dependency prevents readiness, record the blocker and consider another independent in-scope candidate. Do not invent new milestones or expand task scope to fill the quota.
3. Assign exactly one READY task to the worker. Require it to claim ACTIVE ownership, implement the card, run applicable checks, and record evidence. Give the reviewer the actual task-specific diff and acceptance criteria for independent review. Require an explicit PASS on the current diff; treat REJECT, missing or ambiguous verdicts, and stale reviews as non-approval. Resolve findings through the worker and obtain focused re-review as needed.
4. Only after that PASS, ask the planner to verify every acceptance criterion and mark DONE with evidence. Count the task toward N only after the registry says DONE. A BLOCKED or still ACTIVE task does not count. Refresh the handoff before choosing the next task; serialize writes and task registry updates within this worktree. In a milestone lane update only that lane's rows/cards and CURRENT lane section. Do not archive another lane, rewrite the shared baseline, or treat another branch's completion as integrated evidence.
5. Immediately after each task is DONE and its planner/card/handoff updates are complete, require a fresh git-worker session to create exactly one scoped commit containing only that task's verified changes and associated updates. Verify the actual commit hash before starting the next task. One task, one commit; never combine tasks into a batch commit. If a clean scoped commit is impossible, stop and report the blocker without disturbing unrelated changes. Do not create empty commits.
6. Repeat steps 2–5 within the selected milestone without waiting for routine user confirmation. Stop when no eligible task can be made READY, a necessary decision is outside existing authority, verification or the task commit cannot be completed, or the same problem remains unresolved after a bounded correction attempt. Do not loop or claim completion to reach the quota. Shared source/specification edits require a named owner and sequencing plan before overlapping work; separate worktrees alone do not resolve design or merge conflicts.

After the loop, if the batch produced verified task commits, explicitly require a fresh git-worker session to push them once to the established upstream, unless the user prohibited pushing. This workflow authorizes that end-of-batch push, not a push after every task. For named M8/M9 lanes without a matching upstream, it also authorizes first publication with `git push -u origin dev-m8` or `git push -u origin dev-m9` after verifying origin is this repository, branch identity, base, and outgoing task scope. A worktree created from origin/main may inherit origin/main as its upstream: that is NOT a valid lane destination; publish the matching lane branch explicitly. Never push a lane to main or another lane. For other missing destinations or unrelated outgoing commits, report the specific blocker and request only missing input. Do not push when no task commits were created. Do not merge, rebase, force-push, deploy, or perform other external writes unless separately authorized.

Respect `AGENTS.md`, the agent permissions, the accepted contract, and the user's current scope. At the end, report the worktree/branch and milestone, completed task IDs, checks and evidence, the count versus N, each task's commit hash, the batch push result, and the concrete reason if you stopped early. Never claim work continues after the session stops.
