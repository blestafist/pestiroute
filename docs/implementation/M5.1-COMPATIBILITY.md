# M5.1 Codex Compatibility Profile

This is an evidence-scoped Codex profile, not a general OpenAI or ChatGPT
compatibility or account-entitlement claim. M5.1-001..039 provide deterministic
evidence using synthetic credentials/accounts and local fake upstreams.
M5.1-040 records one operator-reported device login, a gateway-only auth
continuation, and local read-only credential decryption; its duplicate direct
login comparison was deferred and live refresh was not run. M5.1-041 records
one successful matched plain-text direct/gateway pair under the opt-in Lite
profile. These bounded results do not establish general service, account, model,
or feature availability.

## Profile

| Profile | Default | Scope / live evidence |
| --- | --- | --- |
| `codex-responses-http-sse-v1` | Yes | Standard, non-Lite profile; exact configured `gpt-5.4-mini`; native and translation modes. Local deterministic streaming evidence. Historical standard-profile direct requests returned HTTP 400; no successful standard-profile live inference is established. |
| `codex-responses-http-sse-lite-v1` | No (explicit opt-in) | Exact configured `gpt-6-luna`; native Responses only. One matched plain-text direct/gateway pair completed HTTP 200 on both legs; live claims are limited to the observed request and selected account. |

Both profiles target `POST https://chatgpt.com/backend-api/codex/responses`,
use one explicitly configured account per Connector and its scoped runtime
credential, and never fall back implicitly. Responses SSE is incremental;
the client owns tool execution and conversation history. Lite is not a default
or a model-name inference. DEC-011 forbids Chat Completions translation for Lite;
non-native Lite routes reject before dispatch. No model catalog/discovery or
account entitlement is inferred from static source catalogs.

## Live evidence and limits

- The sanitized M5.1-041 direct and gateway artifacts are stored outside Git at
  `/tmp/opencode/pestiroute-live-evidence/pair-final-{direct,gateway}.json`.
  On 2026-10-06, Go `http.Client` 1.27.1 made one request per leg for the same
  `gpt-6-luna` native plain-text fixture. Both returned HTTP 200 and completed
  through `response.completed`/EOF; SSE arrived before completion, event order
  matched, encrypted reasoning content was present but redacted, usage was
  reported, target dispatches were one per leg, and retries were zero. Strict
  artifact validation passed. This is one paired request, not general model or
  account compatibility.
- The separate sanitized direct `luna-7-completion.json` records HTTP 200,
  completed through EOF, one reasoning item, and 27 reported reasoning tokens
  with effort `high` and context `all_turns`. It is direct-only and does not
  establish every Lite option or multi-round encrypted-reasoning continuation.
- The pair procedure used a 30-second deadline, 1 MiB response ceiling, and
  256-byte visible-text client observation cap. These client-side limits do not
  guarantee an upstream generation or billing limit. Pair artifacts retain no
  output text, raw bodies, identifiers, ciphertext, or numeric token counts.
- M5.1-040's sanitized auth artifact records one gateway device-continuation
  response (HTTP 200). CLI completion is operator-reported; local validation
  separately confirmed read-only credential decryption and future-expiry
  metadata. The duplicate direct login comparison was explicitly deferred;
  live refresh was not run because the credential was not near expiry; no
  expiry/revocation was forced. No paired-auth or live-refresh claim is made.
- M5.1-044 directly probed a single function emission and fresh two-request
  roundtrip (HTTP 200 and HTTP 200/200); no live gateway tool round was run.
  Its parallel request was rejected HTTP 400, so no parallel support is claimed.
  That direct observation is not a one-call output limit. M5.1-046 verifies only
  deterministic local multi-call behavior with `parallel_tool_calls:false`;
  provider emission of multiple calls under that setting remains unverified.
  Historical
  standard-profile direct HTTP 400s remain failures, not evidence of the exact
  provider rejection reason or of general standard-profile incompatibility.

## Request field policy

Connector profile errors below are HTTP 400. Malformed JSON, duplicate JSON
keys, malformed values, model mismatch and profile-size violations map to
`invalid_request`; valid but unimplemented features map to
`unsupported_feature`. Capability requirements are checked before Connector
execution and map to `unsupported_capability`. No error classification is
provider-live evidence.

| Field / shape | Policy | Rejection / consequence |
| --- | --- | --- |
| `model` | Required and must equal the request route model and configured model exactly. | Missing, malformed or mismatched: `invalid_request`; scoped route mismatch is rejected before dispatch. |
| `input` | Required, non-null; ordinary text messages, supported function-call/result history, and locally supported opaque encrypted reasoning history are admitted. Order and item/call identities are retained. | Missing/malformed: `invalid_request`; image/audio/video, resource/hosted-tool history and unrepresentable content: `unsupported_feature`. |
| `instructions` | Optional and passed through; initial instructions are preserved across client-owned rounds. | No provider behavior/type claim beyond JSON/profile validation; no server-side prompt rewrite is inferred. |
| Request size / JSON | At most 1 MiB; recursively duplicate JSON keys and case-fold aliases of governed fields are rejected. | `invalid_request`. |
| `stream` | Native requires literal `true`. Translation defaults an omitted value to `true`; explicit true is retained. | Invalid type/false: `invalid_request` for malformed value, `unsupported_feature` for non-streaming. |
| `store` | Native requires literal `false`. Translation defaults omission to `false`; explicit false is retained. | Invalid type: `invalid_request`; true/server-side storage: `unsupported_feature`. |
| `tools` / `additional_tools` | Standard input accepts flat Responses function tools; Lite accepts `additional_tools` developer items with direct function definitions or the official `functions` namespace containing only functions. Definitions and ordered function call/result history are preserved; execution remains client-owned. | Malformed shapes/definitions: `invalid_request`; custom, hosted, other namespace and unproven forms: `unsupported_feature`; standard-profile required `llm.tools` Unknown fails admission as `unsupported_capability`. |
| `tool_choice` | `auto`, `none`, `required`, or a named function present in `tools`. | Malformed value: `invalid_request`; unsupported choice/name: `unsupported_feature`. |
| `parallel_tool_calls` | Optional boolean, preserved exactly; no force-false rewrite. False does not request parallel capability. True requires `llm.tools.parallel`. | Non-boolean: `invalid_request`; true and Unknown capability: `unsupported_capability`, zero provider sends. |
| `include` / reasoning history | Native request bytes stay unchanged. Translation preserves full ordered history and opaque encrypted reasoning bytes, adding `reasoning.encrypted_content` to `include` when absent. | Malformed include: `invalid_request`; unsupported previous-response/session resource fields: `unsupported_feature`. Reasoning capability is profile/mode/model scoped as shown above; full-history live continuation is not established. |
| `background` | Omitted, null or false only. | Other non-null values: `unsupported_feature`. |
| `previous_response_id`, `conversation`, `context_management`, `compaction_trigger`, `max_output_tokens`, `temperature`, `top_p`, `presence_penalty`, `frequency_penalty`, `text`, `truncation`, `modalities`, `audio`, `image`, `video`, `file_search`, `attachments` | No profile mapping. Null is treated as absent by profile validation. | Non-null values: `unsupported_feature`; no silent dropping. |
| `prompt_cache_key` | Translation validates bounded printable-ASCII form and preserves it; native body is unchanged. Cache affinity is metadata, not cross-account resource reuse. | Invalid value: `invalid_request`; account isolation and affinity boundaries are covered by [M5.1-032](tasks/M5.1-032.md) and [M5.1-034](tasks/M5.1-034.md). |
| Other top-level fields | Native bytes, including unknown fields, are preserved. Translation retains unknown JSON fields while injecting only its documented defaults/include. | Duplicate keys or invalid JSON: `invalid_request`; extensions are not used to infer capabilities. |

## Responses, usage and unsupported boundaries

Native execution preserves request and response body bytes. Translation modifies
only the request defaults/include it owns and returns Responses-compatible SSE;
stream observations do not rewrite user-facing bytes. Streaming is incremental,
cancellable and bounded. Completed, incomplete, failed, error and missing
terminal/EOF outcomes remain distinct; provider usage is nullable, partial usage
survives interruption, and settlement is exactly once. These properties have
deterministic local evidence only.

The opt-in Lite implementation is limited to native Responses and the exact
`gpt-6-luna` route; it does not implement WebSockets, conversation/session
resumption, `previous_response_id`, server compaction, background execution,
server-hosted tools, vision/audio, or other protocols. The successful Lite pair
does not verify the default standard profile, general live subscription access,
or all M5.1 release acceptance. M5.1-043 handoff/review remains pending.
