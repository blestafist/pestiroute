# M3-012 — Generate, verify and revoke persistent virtual keys

## Outcome

Implement a persistent virtual key lifecycle repository in SQLite storage providing key generation, digest verification, constant-time validation, safe metadata queries, optimistic revision updates, and monotonic revocation. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Implement pure Go SQLite virtual key repository in `internal/storage/sqlite` (`keys.go` and `keys_test.go`), keeping SQL persistence outside of Core.
- Model `VirtualKey` safe metadata entity matching schema v3 columns: `ID string` (internal primary key), `KeyID string` (public identifier), `Digest string` (cryptographic digest), `PolicyID string`, `PolicyRevision int64`, `Revision int64`, `Enabled bool`, `Revoked bool`, `CreatedAt time.Time`, `RevokedAt *time.Time`.
- Model `IssuedVirtualKey` containing `VirtualKey` metadata plus `Secret string` (raw key), returned strictly to the creation caller.
- Model `TrustedPrincipal` matching `M3-RUNTIME.md` (`KeyID, PolicyID string`, `KeyRevision, PolicyRevision int64`) returned by verification.
- Implement key generation and digest calculation:
  - Generate high-entropy keys using `crypto/rand` (e.g. 256 bits entropy) with separate public `key_id` prefix/identifier.
  - Calculate cryptographic digest (e.g. SHA-256) for stored comparison; never store or log the raw key.
- Implement repository operations on `*sql.DB` opened with `sqlite.Open`:
  - `Create(ctx context.Context, params CreateVirtualKeyParams) (IssuedVirtualKey, error)`: generates key and digest, validates target policy existence, inserts row with initial `revision = 1`, `enabled = true`, `revoked = false`, integer UTC Unix-millisecond `created_at`. If insertion fails (collision or constraint error), rolls back and never returns raw secret.
  - `Get(ctx context.Context, id string) (VirtualKey, error)` / `GetByKeyID(ctx context.Context, keyID string) (VirtualKey, error)`: queries by internal ID or public identifier; returns safe metadata only or typed `ErrVirtualKeyNotFound`.
  - `List(ctx context.Context, filter VirtualKeyFilter) ([]VirtualKey, error)`: lists safe metadata matching optional filter (`PolicyID string`, `Enabled *bool`, `Revoked *bool`) sorted deterministically (`created_at ASC, id ASC`).
  - `Verify(ctx context.Context, presentedKey string) (TrustedPrincipal, error)`: computes digest of presented key, performs constant-time comparison (`crypto/subtle.ConstantTimeCompare`), validates `enabled = true` and `revoked = false`, and returns `TrustedPrincipal`. Returns typed errors (`ErrInvalidVirtualKey`, `ErrVirtualKeyDisabled`, `ErrVirtualKeyRevoked`) on failure.
  - `Revoke(ctx context.Context, id string) (VirtualKey, error)`: monotonic revocation. Sets `revoked = 1`, `revoked_at = now` (UTC Unix ms), increments `revision = revision + 1`. Cannot be undone: once revoked, key remains permanently revoked and immutable.
  - `SetEnabled(ctx context.Context, id string, enabled bool) (VirtualKey, error)`: updates enabled state, incrementing monotonic revision = revision + 1 when state changes; setting the existing enabled value is an idempotent no-op that preserves revision. Rejects if key is already revoked.
  - `UpdatePolicy(ctx context.Context, id string, policyID string, policyRevision int64, expectedRevision int64) (VirtualKey, error)`: optimistic CAS update reassigning key to a new immutable policy revision (`WHERE id = ? AND revision = ?`), incrementing `revision = revision + 1`. Rejects if key is revoked, returning typed `ErrVirtualKeyRevisionMismatch` or `ErrVirtualKeyNotFound`.
- Explicit limits:
  - Key policy repository persistence belongs to [M3-013](M3-013.md).
  - CLI management commands (`pestictl key create/revoke/list`) belong to [M3-016](M3-016.md).
  - HTTP header extraction and authentication middleware belong to [M3-018](M3-018.md).
  - RPM/TPM limit admission checks belong to [M3-019](M3-019.md) and [M3-020](M3-020.md).
  - Core remains standard-library only and does not import `internal/storage/sqlite`.

## Acceptance

- [x] High-entropy key generation uses `crypto/rand` producing distinct internal `id`, public `key_id`, and cryptographic digest; raw key secret is returned only to the initial creation caller.
- [x] Virtual key persistence uses integer UTC Unix-millisecond timestamps (`created_at`, `revoked_at`) that survive `db.Close()` and reopen with `sqlite.Open`.
- [x] Foreign key constraints enforce referential integrity: creating a key with nonexistent `(policy_id, policy_revision)` fails under SQLite `FOREIGN KEY ... ON DELETE RESTRICT`.
- [x] Uniqueness constraints reject duplicate internal `id`, public `key_id`, or `digest`; creation errors or collisions roll back atomically and never issue partial keys.
- [x] Verification matches presented raw keys via constant-time comparison (`subtle.ConstantTimeCompare`), resolving to `TrustedPrincipal{KeyID, PolicyID, KeyRevision, PolicyRevision}` for active keys.
- [x] Verification fails safely for unknown, malformed, empty, disabled (`enabled = 0`), or revoked (`revoked = 1`) keys, returning typed errors without leaking internal state.
- [x] Revocation is monotonic and terminal: setting `revoked = 1` records `revoked_at`, increments `revision`, survives restart, and permanently blocks re-enabling or policy mutations.
- [x] Policy reassignment enforces optimistic revision checks (`expectedRevision`), increments monotonic `revision = revision + 1`, and fails with `ErrVirtualKeyRevisionMismatch` on stale revision.
- [x] Safe metadata guarantee: queries, lists, error messages, and string formats contain only safe public metadata and never expose raw key secrets.
- [x] Raw SQLite database file and WAL inspection confirms zero plaintext secret tokens in storage or logs.
