# M11-004 — Expose account and write-only credential management

## Outcome

Expose authenticated account lifecycle management (`GET /admin/v1/accounts`, `POST /admin/v1/accounts`, `GET /admin/v1/accounts/{account_id}`, `PUT /admin/v1/accounts/{account_id}/enabled`) and write-only credential management (`POST /admin/v1/accounts/{account_id}/credentials`, `PUT /admin/v1/accounts/{account_id}/credentials/{credential_id}`) conforming to the frozen binding and OpenAPI specification. Delivers the account and credential management step for [Administrative HTTP API](../M11-ADMIN-API.md) in [TASKS.md](../TASKS.md#m11--administrative-http-api) under [ROADMAP.md](../ROADMAP.md#m11--administrative-http-api).

## Scope

- Implement HTTP handlers and JSON serializers/deserializers in `internal/admin`:
  - `GET /admin/v1/accounts`: paginated list of accounts with query filters `connector` (string), `enabled` (boolean string `true` or `false`), `limit` (default 50, max 500), `offset` (default 0). Emits `{ items, limit, offset, total }`. Query parameters must be strictly validated; reject unknown parameters, non-integer or out-of-range pagination, and invalid boolean values with 400 `invalid_request`.
  - `POST /admin/v1/accounts`: creates account with JSON body `{ id: string, connector: string, enabled?: boolean }` (additionalProperties: false). Validates required non-empty `id` and `connector`. Returns 201 `Account` (`{ id, connector, enabled, created_at, updated_at }`). Returns 400 on malformed input or extra properties; returns 409 Conflict on duplicate account ID.
  - `GET /admin/v1/accounts/{account_id}`: returns `Account` metadata. Returns 404 Not Found if missing.
  - `PUT /admin/v1/accounts/{account_id}/enabled`: updates account enabled state with body `{ enabled: boolean }`. Uses existing `sqlite.Accounts.SetEnabled`; disabling atomically invalidates active interactive sessions and quarantines refresh under DEC-007. Returns 200 `Account` or 404 Not Found.
  - `POST /admin/v1/accounts/{account_id}/credentials`: creates write-only credential. Body `{ id: string, secret: string, expires_at?: string|null }` (additionalProperties: false). Validates required `id`, non-empty `secret` (up to 64 KiB), and optional RFC3339 `expires_at`. Checks account exists. Seals `secret` using `crypto.Seal` with master key; zeroes transient plaintext memory; persists to `sqlite.Credentials`. Returns 201 `Credential` (`{ id, account_id, revision: 1, expires_at, updated_at }`). Secret is never echoed in response. Returns 404 if account not found, 409 if credential ID already exists.
  - `PUT /admin/v1/accounts/{account_id}/credentials/{credential_id}`: replaces credential with CAS precondition. Body `{ secret: string, expected_revision: int >= 1, expires_at?: string|null }` (additionalProperties: false). Validates account exists. Seals `secret` with master key; zeroes memory; updates via `sqlite.Credentials.Update` using `expected_revision`. Returns 200 `Credential` with incremented revision. Returns 404 if account or credential not found, 409 Conflict on revision mismatch (`sqlite.ErrRevisionMismatch`).
- Extend `admin.Config` in `internal/admin/server.go` to receive `MasterKey *crypto.MasterKey` (or equivalent holder) and wire `c.runtimeKey` from `cmd/gateway/main.go`.
- Boundaries:
  - Credentials are write-only: no credential read, list, or delete routes exist.
  - Secret bytes are never returned, decrypted for responses, or leaked in logs or error messages.
  - No virtual key or policy mutations (deferred to M11-005).
  - No auth coordinator bridging (deferred to M11-006).
  - Mutations do not reload in-memory route or connector configuration; routing changes require restart.

## Acceptance

- [x] `GET /admin/v1/accounts` lists accounts with pagination (`items`, `limit`, `offset`, `total`) and optional `connector` and `enabled` filters; invalid pagination (limit < 1 or > 500, offset < 0), unknown query parameters, and non-boolean enabled strings are rejected with 400 Bad Request.
- [x] `POST /admin/v1/accounts` creates account with 201 for valid payload; rejects missing/empty ID or connector, extra properties, or malformed JSON with 400 Bad Request; duplicate account ID returns 409 Conflict.
- [x] `GET /admin/v1/accounts/{account_id}` returns 200 with account metadata for existing account; returns 404 Not Found for non-existent account ID.
- [x] `PUT /admin/v1/accounts/{account_id}/enabled` updates account enabled status with 200; disabling invokes existing storage logic that invalidates interactive sessions and quarantines refresh; non-existent account returns 404 Not Found.
- [x] `POST /admin/v1/accounts/{account_id}/credentials` seals secret into AES-256-GCM envelope under master key, zeroes transient plaintext buffers, and returns 201 with write-only metadata (`id`, `account_id`, `revision: 1`, `expires_at`, `updated_at`); secret bytes are never echoed; duplicate credential ID returns 409 Conflict; missing account returns 404 Not Found.
- [x] `PUT /admin/v1/accounts/{account_id}/credentials/{credential_id}` performs CAS credential replacement with `expected_revision` and returns 200 with bumped revision; revision mismatch returns 409 Conflict; missing account or credential returns 404 Not Found; secret is write-only.
- [x] Encrypted persistence and restart: verify stored credential in SQLite is an encrypted envelope that cannot be read without master key, and subsequent restart/read using master key decrypts to expected secret while GET/status/error endpoints never reveal secret bytes.
