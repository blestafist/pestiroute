## Scope

- Create `docs/implementation/M9-BINDING.md`: exact protocol/component IDs,
  admitted request metadata/capabilities, raw-byte preservation, JSON/SSE framing,
  terminal `[DONE]`, optional usage chunks, error/commit and cancellation behavior.
- Pin authoritative public Chat Completions references and version/source date.
  Define native Connector scope explicitly; do not reuse a Responses declaration
  for Chat traffic or translate in the adapter/Core.
- Specify protected route/config/admin behavior and whether any shared contract
  decision is required. Record an ADR proposal before semantic contract changes.
- Name M8 shared-file ownership and keep initial source work in separate packages.
  Prepare M9-002's exact fixture subset and checks without inventing support.

## Acceptance

- [ ] Binding maps JSON, text SSE, tool deltas/results, usage-only chunks,
  malformed/unterminated streams, upstream failure, and client disconnect.
- [ ] Adapter and Connector responsibilities, capabilities, model/account scope,
  accounting source, and route mismatch behavior are explicit.
- [ ] Native unknown fields remain opaque; no universal messages or implicit
  Chat-to-Responses conversion is proposed.
- [ ] Shared edits and any required ADR are resolved before affected code is READY.
