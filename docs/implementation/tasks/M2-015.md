# M2-015 — Move model allowlisting from Responses Decode to routing

## Outcome

The Adapter extracts a valid opaque model ID while runtime configuration decides whether it is routable. This task proves the direct route-table boundary; production gateway composition remains on the M1 dispatcher until the separately scoped M2 startup/migration tasks. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Replace fixed `gpt-5.4-mini` equality check in `internal/adapter/responses/decode.go` with model syntax validation (reject missing, non-string, empty, or whitespace-only model fields; retain extracted string in `core.ExecutionRequest.Model`).
- Update `internal/adapter/responses/decode_test.go` to verify decoding multiple valid model strings with exact byte preservation, and rejection of missing, non-string, empty, and whitespace-only values.
- Verify through `core.RouteTable.Select` that an unconfigured valid model decodes but fails route admission without reaching upstream targets.
- Retain existing feature extraction, duplicate-key detection, body byte preservation, hop-header filtering, and size limits. No production changes to `cmd/gateway` or dispatch topology; migration remains separately scoped to M2-016/M2-019/M2-020.
