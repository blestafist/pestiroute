# M10-019 — Add operator prompt, TTY echo-off protection, and --debug forwarding to Antigravity auth launcher

## Outcome

Delivers operator usability and secret safety in `scripts/antigravity-auth.sh`: explicit prompt on interactive TTY, terminal echo suppression with exact saved-settings restoration on cancellation or exit, interactive empty-input rejection without autosend/retry, and CLI-positioned `--debug` argument forwarding. Preserves the standalone CLI's existing `--callback-stdin` pipe contract and non-interactive piping without temporary files, shell arguments, or log leakage. ## Scope

- In `scripts/antigravity-auth.sh`:
  - Accept an optional `--debug` flag for `start` and `continue` actions (or via `PESTIROUTE_AUTH_DEBUG=1`) and forward it immediately after `auth` in CLI invocations: `"$gateway" admin ... auth ${debug_flag} <start|continue> ...`.
  - Maintain the existing CLI pipe contract (`--callback-stdin`); do not add complex TTY logic or contract changes to the gateway binary.
  - Interactive TTY handling for `continue`:
    - When stdin is a terminal (`[ -t 0 ]`):
      - Emit an explicit prompt to stderr (`printf 'Paste the OAuth callback URL or authorization code: ' >&2`).
      - Disable terminal echo (`stty -echo 2>/dev/null`) before reading to prevent sensitive URLs or codes from displaying on screen.
      - Capture the original terminal settings and arm cleanup before changing them; traps on EXIT, INT, TERM, and HUP restore the exact saved settings, including echo state, on cancellation or exit.
      - Read one line from TTY; emit a trailing newline to stderr (`echo >&2`).
      - Reject empty, whitespace-only, or EOF input immediately with exit status 2, preventing gateway invocation or accidental empty submission.
      - Pipe the read input into the gateway via `printf '%s\n' "$callback" | "$gateway" ... --callback-stdin`.
    - When stdin is not a terminal (pipe or redirected input):
      - Pass stdin directly to the gateway `--callback-stdin` without prompts, terminal manipulation, or launcher-side empty/EOF rejection (preserve the pre-existing pipe contract).
    - Evaluate POSIX `/bin/sh` pipeline exit status: in `printf '%s\n' "$callback" | "$gateway" ...`, the pipeline exit status in standard POSIX shells is that of the rightmost command (`$gateway`), ensuring proper failure propagation without bash-specific `PIPESTATUS`.
    - Never write the callback to temporary files, environment variables, command arguments, or logs.
- In `scripts/test-antigravity-auth-launcher.sh`:
  - Extend synthetic test harness to verify:
    - Forwarding of `--debug` to the correct CLI position (`auth --debug start` / `auth --debug continue`).
    - Interactive prompt and echo suppression behavior (or mocked TTY harness).
    - Immediate rejection of empty input without invoking the gateway stub.
    - Restoration of terminal settings on trapped cancellation.
    - Non-interactive piping passthrough.
    - Absence of callback data in command arguments or environment.
- Explicit limits:
  - No contract ADR needed: CLI and launcher operator UX only.
  - No operator database, master key, secret fixture reads, or live network calls.
  - Rebuilding clean versioned gateway binary occurs only AFTER git commit (no `+dirty` in build info); external wrapper promotion strictly follows reviewed, committed source. No user action until passed.

## Acceptance

- [x] `scripts/antigravity-auth.sh` accepts optional `--debug` flag for `start` and `continue`, forwarding it directly after `auth` (`gateway admin ... auth --debug <start|continue> ...`).
- [x] In interactive mode (stdin is TTY), `continue` displays an explicit prompt on stderr and disables echo (`stty -echo`) while reading sensitive callback input.
- [x] Signal traps (EXIT, INT, TERM, HUP) restore the exact original terminal settings, including echo state, even if the operator cancels or reading fails.
- [x] Interactive TTY empty, whitespace-only, or EOF callback input is rejected immediately with non-zero exit status without invoking the gateway binary or consuming the session.
- [x] Non-interactive stdin (pipe/redirect) passes directly to the gateway without prompting, terminal manipulation, or launcher pre-invocation input checks, preserving the existing pipe contract.
- [x] The callback is piped securely to `--callback-stdin` without writing to command-line arguments, environment variables, temporary files, or logs.
- [x] Pipeline exit status correctly reflects gateway exit code under POSIX `/bin/sh` without requiring bash-specific `PIPESTATUS`.
- [x] Synthetic harness in `scripts/test-antigravity-auth-launcher.sh` passes offline without live calls or reading real operator credentials/databases.
