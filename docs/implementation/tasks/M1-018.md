# M1-018 — Request timeout phases

## Outcome

Stalled phases terminate predictably while healthy long-running streams remain incremental. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Scope

- In `internal/connector/responses`:
  - Add `StreamIdleTimeout` to `connector.Config` and wire it into streaming attempts.
  - Enforce `stream_idle_timeout` while awaiting upstream response body chunks in `sseStream.Next`; ensure downstream write stalls do not advance the idle clock.
  - Classify pre-commit timeouts (including `ResponseHeaderTimeout` and `net.Error.Timeout()`) as `core.CategoryTimeout` (`upstream_timeout`), mapped to HTTP 504 Gateway Timeout.
  - On stream idle timeout after commit, close the stream body and cancel the upstream request context, terminating the response so Core finalizes the attempt as incomplete.
- In `cmd/gateway`:
  - Pass validated `c.StreamIdleTimeout` from startup configuration into `connector.Config`.
  - Add end-to-end integration tests in `cmd/gateway/main_test.go` covering upstream response header timeout before commit, stream idle timeout after commit, healthy long-running stream preservation, and client request deadline cancellation.
- Stop before server drain/graceful shutdown of active inference (M1-019), retries/fallback policies, or new timeout configuration fields beyond the M1 binding note.

## Acceptance

- [x] Upstream response header stall triggers pre-commit failure returning HTTP 504 Gateway Timeout with `CategoryTimeout` without retry.
- [x] Upstream body stall exceeding `stream_idle_timeout` during active streaming closes the stream, cancels the upstream request context, and finalizes the attempt once as incomplete.
- [x] Stalled downstream consumer (backpressure) does not trip upstream `stream_idle_timeout` while gateway is blocked writing to client.
- [x] Healthy incremental streams with total duration longer than phase timeouts succeed as long as inter-event intervals remain within `stream_idle_timeout`.
- [x] Client request deadline expiry propagates prompt cancellation to upstream before and after Head.
