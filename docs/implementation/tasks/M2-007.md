# M2-007 — Close registry components safely and idempotently

## Outcome

Registry teardown stops new component work and releases initialized or partial resources once. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Component Close/shutdown](../CONTRACT.md#component-descriptor-and-lifecycle) and [Component API](../M2-BINDING.md#component-api).
- Existing `internal/core/registry.go` and `internal/core/registry_test.go` implemented in M2-005 and M2-006.

## Scope

- Implement registry `Close(ctx context.Context) error` in `internal/core/registry.go` and unavailable-after-close behavior.
- Ensure repeated or concurrent `Registry.Close` calls are safe and release each owned component once.
- Aggregate/join errors so one component's Close failure does not skip closing remaining components.
- Post-close registry refuses admission and operations (`Register`, `Init`, `Admit` fail/reject; `Health` returns unavailable).
- Prevent double-release for components that already executed cleanup during failed `Init`.
- Keep active-request drain policy at runtime/composition layer (deferred to M2-021); no reload or process supervisor.
- Lifecycle calls are serialized; `Close` may wait for an in-progress `Init` and cannot bound a component call that ignores its context. Bounded shutdown is not promised here.

## Acceptance

- [x] Repeated and concurrent `Registry.Close` calls are safe and release each registered component exactly once.
- [x] Failed `Init` and subsequent registry Close do not double-release partial resources or panic.
- [x] A component `Close` error does not abort closing remaining components; all components are closed and errors are returned.
- [x] Closed registry refuses subsequent work: `Admit` denies execution, `Init` and `Register` return errors, and `Health` reports unavailable.
