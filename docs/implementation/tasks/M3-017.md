# M3-017 — Supply persistent credentials to selected invocations

## Outcome

Supply persistent credentials to selected invocations via a durable `InvocationServices` provider backed by persistent storage and encrypted credential envelopes. This replaces static environment credential maps for managed accounts while strictly isolating account credentials, verifying account enablement, enforcing context cancellation, redacting decrypted secrets from logs, and preserving `internal/core` independence from storage/driver packages. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Define runtime-owned account and credential reader/source interfaces in `internal/core` without importing non-standard packages (`internal/storage` or `internal/crypto`).
- Implement the durable `InvocationServices` provider (e.g. `PersistentServices` or `PersistentInvocationServices`) accepting runtime-defined reader interfaces, configured HTTP transports, and base logger:
  - Invocation scoping: `ForAttempt(AttemptScope)` produces `InvocationServices` restricted strictly to `AttemptScope.AccountID`. Connector receives only `core.CredentialAccess.Get(ctx, name)` and cannot select or inspect another account.
  - Account eligibility: Verifies target account exists and is enabled before returning or decrypting credentials. Disabled or missing accounts fail closed with explicit errors (`ErrCredentialUnavailable` or classified account error) before execution.
  - Dynamic resolution with cancellation: `CredentialAccess.Get(ctx, name)` propagates context cancellation (`ctx.Err()`); aborted or canceled context fails immediately.
  - Secret redaction: Plaintext credential values decrypted during invocation are registered with the scoped redacting logger (`slog.Logger`), ensuring logs never expose secrets.
  - Freshness and lifecycle: Updates to stored accounts (e.g. disabling an account) or replaced credentials in SQLite apply to subsequent invocations immediately; an active in-flight invocation retains its resolved credentials.
- Wire the persistent provider at the composition root (`cmd/gateway`):
  - Adapt `sqlite.Accounts`, `sqlite.Credentials`, and `crypto.MasterKey` into the runtime-owned interfaces.
  - Retain legacy `EnvironmentServices` for unmigrated single-target/environment configuration paths.
- Explicit limits:
  - No SQL, SQLite driver, or database package imports in `internal/core`.
  - No provider branching, payload parsing, model rewriting, or fallback execution in the credential supplier.
  - Core does not manage secret generation, OAuth exchange, or token refresh in this task (reserved for [M3-033](M3-033.md) and [M3-035](M3-035.md)).
  - Request admission and durable accounting ledger integration belong to [M3-027](M3-027.md).

## Acceptance

- [x] Two accounts sharing a connector or gateway cannot read each other's credentials or access another account's credentials through `InvocationServices`.
- [x] Attempting credential access for a missing, non-existent, or disabled account fails closed with an explicit error before any upstream execution.
- [x] Credential decryption errors (corrupted ciphertext, invalid key, or missing envelope) fail closed before upstream execution.
- [x] Credential lookup respects context cancellation (`ctx.Err()`) and immediately aborts if the invocation context is canceled.
- [x] Scoped invocation logger redacts decrypted persistent credential values from log output across message, attribute, and group levels.
- [x] Updates to accounts (disabling an account) and replaced credentials apply immediately to subsequent invocations without restarting the gateway.
- [x] Production `internal/core` packages retain zero imports of non-standard packages (`internal/storage/sqlite`, `internal/crypto`, `modernc.org/sqlite`, etc.), verified by `dependencies_test.go`.
- [x] Legacy environment-backed services remain functional for backwards compatibility.
