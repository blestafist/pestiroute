## Scope

- Add approved `AuthUserAction` struct to `internal/core/connector.go` and add `UserAction *AuthUserAction` to `core.AuthResult`, matching accepted DEC-009 and CONTRACT lines 105–115.
- Implement Authenticate(start) state machine in `internal/connector/codex`:
  - When `request.Action == "start"`, verify connector readiness and account scope (`request.AccountID == c.accountID`).
  - Send POST request to `/api/accounts/deviceauth/usercode` using invocation-scoped `services.Transport` (default `https://auth.openai.com/api/accounts/deviceauth/usercode`, with connector-private base URL injection limited to an actual loopback IP for testing); cap the call at the binding's 30s response-header deadline.
  - Send JSON body `{"client_id":"app_EMoamEEZ73f0CkXaXp7hrann"}` with `Content-Type: application/json`.
  - Read provider response with bounded limit (64 KiB) and decode JSON response fields (`device_code` / `device_auth_id`, `user_code`, `verification_uri`, `interval`, `expires_in`).
  - Parse decimal interval as numeric or string, clamp to minimum 1s, and reject zero or negative interval.
  - Return `core.AuthResult` with `Supported: true`, `NextAction: "continue"`, valid `UserAction: &core.AuthUserAction{...}`, and connector-private opaque serialized continuation `State` (containing device code/auth ID and expiry). Candidate credentials remain nil.
  - Fail closed with sanitized `*core.GatewayError` on non-200 HTTP response, malformed payload, invalid interval, or caller context cancellation; release all resources immediately. Do not follow redirects or send a redirected request.
  - Never format or leak client secrets, device codes, or continuation state into logs or error messages.
- Implement comprehensive unit tests in `internal/connector/codex/auth_test.go`:
  - Primary check `TestDeviceAuthStartExchange`: verify start flow against mock HTTP server returning `start-success.json` and `start-string-interval.json`.
  - Negative tests: HTTP error statuses, non-positive interval (`start-invalid-interval.json`), malformed JSON, oversized response, transport failure, and context cancellation.
  - Scope/lifecycle tests: unready connector state and mismatched `AccountID`.
- Explicit limits:
  - Do NOT poll or exchange tokens (belongs to M5.1-010, M5.1-011).
  - Do NOT persist credentials or session state to SQLite (belongs to M5.1-013).
  - Do NOT wire coordinator or admin CLI commands (belongs to M5.1-014).
  - Local mock server only; no live provider network calls.

## Open Questions / Blocker

No blocker to this bounded local exchange. Downstream composition must supply a
RoundTripper-backed service for Codex auth: Core's generic `HTTPDoer.Do` contract
does not guarantee redirect refusal, so this Connector invokes RoundTrip directly
and rejects opaque Do-only transports before sending. M5.1-014 owns that wiring.

## Completion Evidence

Implemented the DEC-009 Core presentation projection and Codex `start` exchange.
The Connector uses invocation-scoped transport, bounds the response at 64 KiB
and each start at 30 seconds, validates only safe URI/code projection fields,
keeps continuation data separate from `UserAction`, and returns sanitized errors.

transport for Codex auth. Core-side projection validation/exposure is not added
here; it remains with M5.1-014's coordinator/operator integration. Tests use
synthetic fixtures/local `httptest`; no provider calls or credentials were used.
