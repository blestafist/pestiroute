# M6-013 — Bridge scoped HTTP request and response streams

## Outcome

Bridge `core.HTTPDoer` over IPC so external child connectors can execute HTTP requests through runtime-controlled host transport with incremental streaming bodies, header bounds, and cancellation. See [registry](../TASKS.md#m6--external-plugin-runtime), [milestone](../ROADMAP.md#m6--external-plugin-runtime), and [binding](../M6-BINDING.md#reverse-services-and-authority).

## Scope

- HostServices proto definition and code generation for reverse `HTTPDo` RPC under [M6-BINDING](../M6-BINDING.md#reverse-services-and-authority).
- Stream framing: carrier message (e.g., `HTTPFrame` with oneof `RecordFragment metadata` and `BodyChunk body`) enabling bidirectional streaming of request metadata, incremental request body chunks, and `HTTPBodyComplete` record marker from child, and response metadata, incremental response body chunks, and `HTTPBodyComplete` record marker from host.
- Host-side reverse service handler on `HostServices`:
  - Validates epoch, invocation ID, monotonic call ID, and callback lease through `invocationRegistry.admitCallback`.
  - Reassembles `HTTPRequest` metadata via `RecordFragment` assembler; validates 16 KiB header limit.
  - Reconstructs `*http.Request` using `HTTPRequestFrom` with incremental streaming `Body` backed by inbound `BodyChunk` stream.
  - Enforces runtime ownership: host executes request via invocation's scoped `core.HTTPDoer` transport. Child cannot override host-managed transport settings (TLS, redirect policy, connection reuse).
  - Streams `HTTPResponse` metadata via `RecordFragment` back to child, followed by incremental `BodyChunk` stream and terminal complete marker.
  - Enforces 64 KiB chunk bounds, 84 KiB wire frame ceiling.
  - Closes streams on parent invocation context cancellation or error, releasing callback lease without blocking.
- Child-side `core.HTTPDoer` client adapter wrapping `HTTPDo` stream:
  - Invocation-bound adapter converting `http.Request` into outbound `HTTPDo` stream with incremental body chunks.
  - Returns `*http.Response` with incremental streaming `Body` reading from inbound `BodyChunk` stream.
  - Propagates cancellation; closes streams on body close or error.
- Limits: Scoped HTTP reverse service only. Logging (M6-014), models/usage (M6-015), auth state (M6-016), and Execute stream bridging (M6-017) are separate tasks. No automatic retry once delivery begins.

## Acceptance

- [x] Round-trip HTTP request and response over IPC with deterministic loopback server; preserve exact method, URL, headers, status code, and opaque body bytes.
- [x] Deliver request and response bodies incrementally using <=64 KiB chunks; support payloads exceeding single-frame limits without whole-response buffering.
- [x] Enforce 16 KiB aggregate header limit; reject malformed metadata or oversized headers with structured failure.
- [x] Correlate authority strictly through host invocation record; reject stale epoch, unknown/revoked invocation ID, duplicate call ID, or post-close invocation.
- [x] Cancelling invocation or request context closes request/response streams promptly and releases callback admission slot without deadlock.

1. Loopback HTTP round-trip with multi-chunk (>64 KiB) streaming bodies in both directions.
2. First small request and response chunks are delivered while the source is gated before later data/EOF; early loopback rejection stops an unbounded upload with explicit HTTPBodyComplete; raw EOF without the marker is rejected.
3. Exact header propagation, response hop-by-hop filtering (including Connection-nominated fields), and rejection of malformed names/values or aggregate headers exceeding 16 KiB.

5. Prompt cleanup and callback slot release on caller cancellation or child response-body close.
