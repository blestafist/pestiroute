# M1-016 — Post-commit failure behavior

## Outcome

Late failures terminate the existing response without replay or replacement output. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-013 streaming path, M1-015 errors, [commit/lifecycle](../CONTRACT.md#execution-response-and-streamframe), [late errors](../TESTING.md#testing-levels).

## Scope

- Exercise drop after Head, drop after first Body, EOF without completion and a native terminal failure event through real HTTP.
- Fix only post-commit transport termination and truthful outcome/finalization.
- Stop before retries/fallback or synthetic SSE recovery events.

## Acceptance

- [x] Client sees only the original response prefix/native events; no second status, JSON error append or fabricated success event appears.
- [x] Upstream attempt count remains one even when the failure is nominally transient.
- [x] Missing completion finalizes incomplete exactly once; native failed completion remains failed and resources close.

## Verification

From root run `go test -race -v -run 'TestResponses.*(PostCommit|LateDrop|LateEOF|LateFailure)' ./cmd/gateway/...`, `go test -race ./internal/adapter/responses/...`, `go test -race ./internal/connector/responses/...`, `go test -race ./internal/core/...`, and `./scripts/check.sh`. Assert exact received bytes, attempt/finalization counts and cleanup. Test Head handoff even before any client-visible Body.

## Open Questions / Blocker

None. Deterministic control of the Head-only phase, midstream drops, EOF without terminal event, and native failure events is confirmed via `fakeupstream.Response` steps and gated flushes.

## Completion Evidence

Implemented and verified the assembled gateway behavior. The Adapter flushes the native Head immediately, so a deterministic gated upstream step can drop after Head while no Body has reached the client. The integration regression also covers drop after a Body prefix, EOF without a terminal event, and a native `response.failed` event. All cases preserve the original 200/SSE response and exact native bytes, make one upstream request, and finalize exactly once (`incomplete` for drops/missing terminal; `failed` for native failure). No synthetic event, appended error, replacement status, or retry is emitted.
