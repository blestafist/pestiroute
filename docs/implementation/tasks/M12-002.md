# M12-002 — Build the WebUI shell with a fixture adapter

## Outcome

Establish the frontend workspace, navigation shell, theme and style primitives, route stubs for all six operator screens, and an in-memory fixture adapter displaying synthetic data. Delivers the client foundation for [M12-WEBUI](../M12-WEBUI.md) tracked in [TASKS](../TASKS.md#m12--webui).

## Read First

- [M12 brief](../M12-WEBUI.md) and [M12-UX](../M12-UX.md) (shell rules, 6 screen layouts, state matrix, and mock adapter requirements).
- [Parallel ownership](../PARALLEL.md) and [registry](../TASKS.md).
- [Architecture](../project/ARCHITECTURE.md) (payload opacity, no direct provider calls, no browser-side routing logic).

## Scope

- Create `web/` React 19 + TypeScript + Vite SPA scaffold with pinned dependencies and committed `package-lock.json`.
- Navigation shell: persistent header with gateway status and session status, desktop side nav, responsive narrow/mobile nav, semantic landmarks, accessible focus states, and light/dark theme toggle.
- Route stubs for all 6 screens from M12-UX: Overview (`/`), Connections (`/connections`), Keys & Policies (`/keys`), Usage (`/usage`), Routing (`/routing`), and Settings & Diagnostics (`/settings`).
- Fixture API adapter providing local view models for all 6 screens, including nullable usage counters, tri-state capabilities (`supported`, `unsupported`, `unknown`), simulated loading/error/conflict states, and in-memory bearer token session handling.
- Persistent visible badge/banner: `DEMO DATA — NOT LIVE`.
- Automated test setup in `web/` (e.g. Vitest + Testing Library) verifying navigation, theme toggle, route rendering, fixture responses, and accessible landmarks.
- Documentation in `web/README.md` defining verified install, typecheck, build, and test commands.
- Out of scope: real M11 admin API integration (waits for M11-007 on main in M12-005), complete CRUD form mutations (M12-003 and M12-004), Go embed packaging (M12-006), external CDN dependencies, or provider SDKs.
