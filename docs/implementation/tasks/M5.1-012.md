## Scope

- Implement `Authenticate` with `request.Action == "refresh"` in `internal/connector/codex`:
  - When `request.Action == "refresh"`, verify connector readiness and account scope (`request.AccountID == c.accountID`).
  - Read existing credential material using invocation services: `services.Credentials.Get(ctx, "oauth")`. If missing, nil, or failing to decode via `decodeOAuthBundle`, fail closed with sanitized `*core.GatewayError` (`auth_invalid_credentials`).
  - Require non-empty prior `bundle.RefreshToken`; if missing or empty, fail closed with sanitized `*core.GatewayError` (`auth_missing_refresh_token`).
  - Require prior `bundle.AccountID` to match configured `c.accountID`; mismatch fails closed (`scope_mismatch`).
  - Send POST request to `/oauth/token` using invocation-scoped `services.Transport` (default base `https://auth.openai.com`, supporting loopback test URL override), capped at the binding's 30s deadline.
  - Send URL-encoded form body (`Content-Type: application/x-www-form-urlencoded`):
    - `grant_type=refresh_token`
    - `refresh_token=<prior refresh token>`
    - `client_id=app_EMoamEEZ73f0CkXaXp7hrann`
  - Refuse redirects fail-closed via `doAuthNoRedirect` (direct RoundTripper execution).
  - Read provider response with bounded limit (64 KiB).
  - Parse provider JSON response (`access_token`, optional `refresh_token`, optional `id_token`, `expires_in`, `token_type`).
  - Token retention / rotation policy:
    - If `refresh_token` is present in provider response, rotate to the new refresh token.
    - If `refresh_token` is omitted in provider response, retain the prior `bundle.RefreshToken` in replacement bundle per M5.1-003 / M5.1-BINDING.
  - Identity verification:
    - If the response includes `id_token` or access token claims, extract account ID via `accountIDFromTokens` and require match with `c.accountID`.
    - If the response omits token claims (as in `refresh-success.json` and `refresh-no-rotation.json`), preserve account ID from the verified prior bundle.
  - Expiry:
    - Validate `expires_in > 0` and compute absolute UTC expiry: `time.Now().Add(time.Duration(expiresIn) * time.Second)`.
  - Encode candidate credentials using `encodeOAuthBundle` into `oauthBundle{Version: 1, AccessToken: newAccessToken, RefreshToken: rotatedOrRetainedRefreshToken, AccountID: bundle.AccountID, ExpiresAt: expiresAt}`.
  - Return `core.AuthResult`:
    - `Supported: true`
    - `NextAction: ""`
    - `State: ""`
    - `UserAction: nil`
    - `Credentials: map[string][]byte{"oauth": encodedBundle}`
    - `CredentialExpiresAt: &expiresAt`
  - Fail closed with sanitized `*core.GatewayError` on HTTP non-200, malformed JSON, oversized response, missing access token, invalid/zero/negative expiry, account mismatch, transport error, or caller context cancellation; return sanitized error without leaking tokens into error strings.
  - Never automatically replay or retry an uncertain or failed refresh exchange.
- Implement comprehensive unit tests in `internal/connector/codex/auth_test.go`:
  - Primary check `TestSelectedAccountRefreshExchange`: verify refresh exchange against mock HTTP server returning `refresh-success.json` (rotating refresh token) and `refresh-no-rotation.json` (retaining existing refresh token); assert URL-encoded form parameters, headers, token retention/replacement, account isolation, and DEC-010 `CredentialExpiresAt`.
  - Negative cases: HTTP terminal errors (`refresh-terminal-error.json`), missing credentials / nil credential service, input bundle with missing refresh token, malformed response, oversized response, missing access token in response, account ID mismatch, redirect refusal, unready connector state, mismatched request account ID, and caller context cancellation.
  - Secret sanitization tests: assert errors do not contain access or refresh tokens.
- Explicit limits:
  - Do NOT implement Core-owned lock/store, coordinator freshness evaluation, or SQLite persistence (belongs to M5.1-013, M5.1-016).
  - Do NOT implement inference retry or account fallback.
  - Local mock server only; no live provider network calls.

## Acceptance

- [x] One selected-account refresh exchange at `/oauth/token` reads existing credentials via `services.Credentials.Get`, sends form-encoded `grant_type=refresh_token`, `refresh_token`, and `client_id`, returning candidate `oauth` credential bundle and DEC-010 `CredentialExpiresAt`.
- [x] Rotated refresh token in provider response replaces old token; omitted refresh token in provider response retains the prior refresh token in replacement bundle.
- [x] Missing prior refresh token, missing access token, zero/negative expiry, wrong account, non-200 HTTP status, malformed payload, oversized response, and caller cancellation return sanitized `*core.GatewayError` with no candidate success.
- [x] Redirect targets are not contacted; no second provider exchange or retry is performed; access/refresh secrets are never leaked into error messages.
