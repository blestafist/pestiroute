## Scope

- Implement persistence-failure handling in Core and the SQLite accounting composition adapter:
  - Pre-commit (admission, intent, pre-Head execution failure): storage failure returns safe infrastructure error `accounting_unavailable` (`CategoryUnavailable`), suppressing upstream execution and preventing automatic alternative dispatch.
  - Post-commit (after Head): storage failure during terminal settlement/EOF preserves response delivery/stream teardown without mutating client status or sending replacement frames; failure leaves attempt/reservation unacknowledged/recoverable.
  - Fail-closed admission: only explicitly classified storage infrastructure failures mark dispatcher/accounting state degraded. Cancellation and expected ledger conflict/not-found outcomes fail the current request safely without permanently degrading the dispatcher.
- Out of scope: restart recovery loop (`M3-029`), protected gateway startup composition (`M3-030`), multi-target fallback candidate selection (`M3-037`/`M3-039`).

## Acceptance

- [x] Injected storage failures at Admit or RecordDispatchIntent abort before Execute with `accounting_unavailable` and trigger no retry or alternate dispatch; cancellation/conflict/not-found do not latch degraded state.
- [x] Injected storage failures at FinalizeAttempt after Head handoff do not alter client stream or send replacement status/body frames; attempt remains unfinalized in storage.
- [x] Post-dispatch terminal persistence failure transitions protected accounting into fail-closed state; subsequent admissions reject with `accounting_unavailable`.
- [x] No unmetered execution occurs under storage faults; secrets and raw payloads are never leaked into returned accounting errors or the dispatcher-local degraded state. No health endpoint is implemented or claimed by this task.
