# M3-015 — Add credential and account administration commands

## Outcome

Add credential and account administration commands to the local CLI (`cmd/gateway`), allowing operators to provision, list, get, enable, and disable accounts, and securely create and update revision-checked encrypted credential envelopes without exposing secret material in arguments, logs, or error streams. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Extend `cmd/gateway` administration commands dispatched under `gateway admin [flags] <subcommand> [args]`:
  - Account administration subcommands:
    - `account create --id <id> --connector <connector> [--disabled]`: provisions an account in the `accounts` table via `sqlite.Accounts.Create`. Default enabled unless `--disabled` is specified. Rejects duplicate IDs or missing/empty arguments.
    - `account get <id>`: displays single account safe metadata (`id`, `connector`, `enabled`, `created_at`, `updated_at`) via `sqlite.Accounts.Get`.
    - `account list [--connector <connector>] [--enabled=true|false]`: lists accounts matching optional filter via `sqlite.Accounts.List`.
    - `account enable <id>`: enables account via `sqlite.Accounts.SetEnabled(ctx, id, true)`.
    - `account disable <id>`: disables account via `sqlite.Accounts.SetEnabled(ctx, id, false)`.
  - Credential administration subcommands:
    - `credential create --account <account_id> --id <credential_id> [--expires-at <RFC3339>]`: reads secret payload from stdin via `readAdminSecret` (max 64 KiB, newline trimmed, buffer overwritten best-effort), seals envelope via `crypto.Seal(masterKey, 1, "v1", "credentials", id, accountID, secretBytes)`, and persists via `sqlite.Credentials.Create`. Enforces foreign key constraint (account must exist).
    - `credential update --account <account_id> --id <credential_id> --expected-revision <N> [--expires-at <RFC3339>]`: reads replacement secret payload from stdin, seals envelope, and atomically replaces via `sqlite.Credentials.Update`. Fails if stored revision does not match `--expected-revision` or credential/account not found.
  - Secret safety and stream input:
    - Secret values are strictly read from injected `stdin` (`io.Reader`); never accepted from command-line arguments (`argv`), flags, or environment variables.
    - Secret byte buffers are overwritten via `zeroAdminSecret` immediately after encryption. This is best-effort only; Go may retain copies outside the reachable slice and this does not guarantee physical erasure.
    - Errors, logs, and command outputs format IDs and safe metadata only; secret tokens and master keys are never exposed.
    - No secret export / plaintext retrieval command is implemented (`GetDecrypted` remains an internal runtime interface).
  - Operational conventions:
    - Admin commands enforce required global flags `--db` and `--master-key`, validate master key file mode/size/regularity, and require the complete current schema before account/credential operations; future, unmigrated, incomplete, and unreadable schemas fail closed before reading stdin or writing. Database handles close cleanly.
- Explicit limits:
  - Virtual-key and policy commands belong to [M3-016](M3-016.md).
  - Runtime invocation credential binding belongs to [M3-017](M3-017.md).
  - Dynamic OAuth token exchange and automated refresh belong to [M3-035](M3-035.md) and [M3-036](M3-036.md) / M5.1.
  - Bulk credential import/export is excluded.
  - Core runtime packages (`internal/core`) remain untouched.

## Acceptance

- [x] `gateway admin account create`, `get`, `list`, `enable`, and `disable` operate against a real file-backed SQLite database across separate invocations, persisting and updating account metadata accurately.
- [x] Duplicate account IDs or empty IDs/connectors return classified errors and non-zero exit without modifying storage.
- [x] `gateway admin credential create` reads secret from stdin, encrypts envelope with the validated master key, and persists initial revision 1; missing account or missing/empty secret fails closed.
- [x] `gateway admin credential update` performs atomic revision-checked replacement; mismatched `--expected-revision` or non-existent credential fails with a classified error leaving stored credentials untouched.
- [x] Secret input bytes are read strictly from stdin, never accepted in flags/argv, and never printed to stdout, stderr, or error strings.
- [x] Account and credential commands enforce `--db` and `--master-key`, validate master key file mode/size/regularity, fail closed on future schema versions, and cleanly close database handles.
