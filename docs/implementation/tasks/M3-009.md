## Outcome

Load the master key and encrypt credential envelopes. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Implement master-key file loading and permission validation in `internal/crypto`: require a regular file owned by the process user with strict mode `0600`, read exactly 32 bytes, and reject symlinks, missing files, wrong lengths, and broader permissions.
- Implement standard AES-256-GCM envelope encryption and decryption helpers in `internal/crypto` using standard library `crypto/aes`, `crypto/cipher`, and `crypto/rand`.
- Envelope structure matches schema v2: format version, key version, 12-byte random nonce, and ciphertext with authenticated tag. AAD strictly binds table/purpose, record ID, account ID, and format version.
- Explicit limits: key rotation, fallback environment key loading, SQLite repository persistence (owned by M3-010), CLI commands (owned by M3-014/M3-015), and Core runtime changes remain outside this task. Never expose key or plaintext bytes in error strings.

## Acceptance

- [x] Master key loader reads 32 bytes from regular file with mode `0600`; fails safely on missing file, non-32 byte size, symlinks, and permissive modes (e.g. `0644`, `0660`, `0777`).
- [x] Envelope encryption generates unique 12-byte nonces via `crypto/rand` on every call and seals plaintext with bound AAD.
- [x] Round-trip decryption recovers original plaintext; tampering with ciphertext, tag, nonce, AAD fields (purpose, record ID, account ID, format version) or decrypting with a wrong key fails with a classified error.
- [x] Decrypting previously sealed envelope using a freshly loaded master key from file succeeds across simulated process restart.
- [x] Errors, formatted representations, and logs expose neither master key bytes nor credential plaintext.
