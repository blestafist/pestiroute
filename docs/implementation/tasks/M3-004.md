## Scope

- Write `docs/implementation/M3-CONFIG.md` specifying the M3 versioned startup YAML schema (`version: 1`), top-level sections (`server`, `storage`, `secrets`, `connectors`, `routes`, `policies`), exact field types, and strict parsing rules rejecting unknown keys, duplicate keys, null values, and YAML alias/merge ambiguity.
- Specify connector settings ownership and isolation: connector-specific fields (`base_url`, `upstream_protocol`, transport timeouts, limits) belong to connector definitions and are validated by the connector; Core validates component kinds, instance IDs, and declared protocols. Reconcile draft names with implemented M2 identifiers (`pestiroute.responses.native`, `openai.responses.v1`, `native` mode).
- Specify persistent entity references: YAML routes and targets reference mutable entities stored in SQLite (`account`, `policy`), without embedded secrets or plaintext credentials.
- Backward compatibility and mode isolation: preserve legacy single-target JSON and M2 topology JSON strictly on numeric loopback (`127.0.0.1` / `::1`) for development; protected YAML configuration requires SQLite storage and master key; storage/auth/policy initialization errors fail closed immediately and never degrade silently to unauthenticated loopback mode.
- Specify live CLI update visibility without topology reload: virtual keys, key policies, and accounts managed through CLI take effect on subsequent request admission based on revision checks without restarting or reloading the YAML topology.
- Define disabled-by-default bounded retry admission: route-level `max_attempts` (>=1, default 1), overall attempt deadline, deterministic target order, strict no-cycling.
- Specify fallback candidate admission: each candidate target requires explicit route authorization, enabled account, capability satisfaction, candidate-specific body/header limits, and separate attempt token reservation in the TPM window.
- Specify stateful request handling and affinity: session-bound requests (e.g., `previous_response_id`) or requests with unknown affinity enforce a fail-closed singleton target rule; cross-target fallback is forbidden without verified affinity evidence. Core does not inspect provider payloads or SSE; adapter populates trusted request metadata.
- Limits: Documentation and semantic specification only. No Go code or migration changes in this card.
