# M1-007 — Bounded Responses Decode

## Outcome

The adapter validates ingress while preserving original bytes in its envelope. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-005 binding, [request](../CONTRACT.md#execution-request), [adapter](../CONTRACT.md#protocol-adapter-contract), [capabilities](../CONTRACT.md#capability-model).

## Scope

- Implement Responses Decode: bounded body/header metadata, selected routing/model/stream/capability extraction and common validation errors.
- Preserve unknown fields and formatting; validate only the declared native ingress requirements.
- Stop before routing, upstream calls or HTTP response encoding. Do not decode a universal conversation/tool model.

## Acceptance

- [ ] Unknown nested fields, whitespace and original model bytes survive exactly; extracted fields do not rewrite the payload.
- [ ] Malformed JSON, missing required model, invalid known fields, unsupported media type and over-limit input fail before execution.
- [ ] Boundary-sized and chunked/unknown-length requests respect the cap; gateway credentials and hop-by-hop metadata do not enter the envelope.

## Verification
