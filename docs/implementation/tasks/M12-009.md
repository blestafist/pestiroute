# M12-009 — Redesign data and diagnostics screens: Usage, Routing, Settings

## Outcome

Apply the restrained operator console visual system to tabular ledger and diagnostics workflows (Usage, Routing, and Settings & Diagnostics) in both live and demo views, delivering an ergonomic filter toolbar, structured request/attempt ledger with expandable fallback details, clear routing topology cards, and safe diagnostic copying. Tracked in [TASKS](../TASKS.md#m12--webui) under [M12](../ROADMAP.md#m12--webui).

## Scope

- Polish `Usage` screen in `web/src/App.tsx`:
  - Compact filter toolbar for date range, account, model, and outcome, maintaining URL query synchronization and pagination reset semantics.
  - Tabular request ledger with monospace request IDs, localized timestamps, status badges, nullable input/output token counts, and attempt counts.
  - Expandable nested detail rows displaying route targets, fallback outcomes, and per-attempt error details.
  - Pagination bar with prev/next buttons, page counts, and page size selector.
  - Polished empty state and reversed-date validation error banner.
- Polish `Routing` screen in `web/src/App.tsx`:
  - Persistent technical banner indicating configuration-backed topology and restart requirement.
  - Route topology cards or table showing protocol, model alias, mode, connector/account targets, and tri-state capability chips.
  - Cross-screen navigation links into Connections and filtered Usage.
- Polish `Settings & Diagnostics` screen in `web/src/App.tsx`:
  - Gateway version, readiness summary, and component health status grid.
  - Endpoints listing and runtime settings table with "Restart required" badges.
  - Diagnostic correlation ID card with copy button and inline copy confirmation.
  - Prominent session termination button with cached view clearance.
- Explicit limits:
  - Do not alter API query parameters, pagination logic, or backend contracts.
  - Do not introduce client-side body/prompt inspection or provider polling.
  - Preserve all existing form labels, button texts, and accessibility attributes.

## Acceptance

- [ ] Usage screen renders a compact filter toolbar, data table with nullable token handling, nested expandable attempt/fallback details, and pagination controls.
- [ ] Invalid date range displays an actionable alert banner without losing entered dates.
- [ ] Routing screen renders configuration-backed topology with clear protocol/model/target groupings and tri-state capability badges.
- [ ] Settings screen renders diagnostic cards, restart-required badges, copyable correlation ID with user feedback, and explicit logout.
- [ ] Existing automated unit and integration tests in `web/src/App.test.tsx` pass without regressions.
