## Outcome

Apply the restrained operator console visual system to tabular ledger and diagnostics workflows (Usage, Routing, and Settings & Diagnostics) in both live and demo views, delivering an ergonomic filter toolbar, structured request/attempt ledger with expandable fallback details, clear routing topology cards, and safe diagnostic copying. ## Scope

- Polish `Usage` screen in `web/src/App.tsx` and `web/src/style.css`:
  - Compact filter toolbar for the accepted live account/key/date controls, maintaining URL query synchronization and server pagination from M12-011. Model/outcome controls remain demo-only.
  - Tabular request ledger with monospace request IDs, formatted timestamps, status chips, nullable token counts, and attempt counts.
  - Expandable nested detail rows displaying route targets, reservation/fallback outcomes, and per-attempt error details without fabricating states or leaking payload data.
  - Pagination bar with prev/next buttons, page counts, and page size selector.
  - Polished empty state and reversed-date validation error banner.
- Polish `Routing` screen in `web/src/App.tsx` and `web/src/style.css`:
  - Persistent technical banner indicating configuration-backed topology and restart requirement.
  - Route topology cards or table showing protocol, model alias, mode, connector/account targets, and tri-state capability chips (`supported`, `unsupported`, `unknown`).
  - Cross-screen navigation links into Connections and filtered Usage.
- Polish `Settings & Diagnostics` screen in `web/src/App.tsx` and `web/src/style.css`:
  - Gateway version, readiness summary, and component health status grid with status chips.
  - Endpoints listing and runtime settings table with "Restart required" badges where present.
  - Diagnostic correlation ID card with copy button and inline copy confirmation. Only present live correlation values when available from error/diagnostic context.
  - Prominent session termination button with cached view clearance.
- Explicit limits:
  - Do not alter API query parameters, pagination logic, or backend contracts established in M12-011.
  - Do not introduce client-side body/prompt inspection or provider polling.
  - Preserve all existing form labels, button texts, and accessibility attributes expected by existing tests in `web/src/App.test.tsx`.
  - Only present fields available from accepted API DTOs in live mode. Missing endpoints/settings/correlation fields must be omitted or shown as unavailable, never filled from demo values.
  - Packaged browser E2E regression and visual/responsive audits are deferred to M12-010.

## Acceptance

- [x] Usage screen (demo and live `UsageLedger`) renders a compact filter toolbar, data table with nullable token handling, nested expandable attempt/fallback details, and pagination controls.
- [x] Invalid date range displays an actionable alert banner without losing entered dates.
- [x] Routing screen renders configuration-backed topology with clear protocol/model/target groupings and tri-state capability badges.
- [x] Settings screen renders diagnostic cards, restart-required badges, copyable correlation ID with user feedback, and explicit logout.
