# M10-033 — Fix uncommitted gateway streaming error handling and add safe precommit debug diagnostics

## Outcome

Prevent uncommitted upstream streaming errors (empty stream, malformed framing, early parse failures) from silently collapsing into implicit HTTP 200 empty responses via gateway composition, ensuring protocol adapters emit structured non-200 errors pre-commit and terminate cleanly post-commit, accompanied by secret-safe fixed-enum streaming phase debug telemetry. See [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [ROADMAP.md](../ROADMAP.md#m10--google-antigravity-connector).

## Scope

- Gateway & Adapter Composition:
  - `cmd/gateway/main.go`: Capture errors from `pa.Encode` and ensure uncommitted failures write structured non-200 responses rather than letting `net/http` default to HTTP 200 OK.
  - `internal/adapter/responses/encode.go` & `internal/adapter/chatcompletions/encode.go`: Map uncommitted stream errors (plain parse/framing errors, unexpected EOF) to client-safe `*core.GatewayError`. Post-commit errors must terminate immediately without rewriting status headers.
- Telemetry & Diagnostics:
  - `internal/connector/antigravity/stream.go`: Under `--debug`, emit fixed-enum streaming phase and error classification (e.g. `precommit_eof`, `precommit_invalid_json`, `precommit_framing`, `postcommit_error`) with zero raw body bytes, URLs, or token text.
- Limits:
  - Zero live provider calls. No buffering of streaming bodies. No universal SSE Core abstractions.
  - Preserve M10-028 runner and helpers. Minimal ownership exception granted to update untracked `live_runner_offline_test.go` expectation from implicit 200 to structured 503 safe error without implicit 200 (not part of M10-033 commit).
