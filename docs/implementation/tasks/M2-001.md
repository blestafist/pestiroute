# M2-001 — Specify the M2 Go binding and migration seams

## Outcome

One contract-preserving binding note fixes the interfaces needed to generalize the working M1 path. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Write `docs/implementation/M2-BINDING.md`: map every v1 operation to a concrete Go signature, owner, and error/unknown representation. Reuse existing envelope/frames/errors; choose the smallest shared package boundary with no concrete imports.
- Define descriptor/API-version validation, lifecycle concurrency, capability/model/account scope, and support-operation results. Define invocation-scoped credential, transport, and logging services; auth storage/refresh remains M3.
- Fix route identity matching, conflicting-route behavior, static model/capability declarations and their evidence scope. Specify a minimal startup JSON extension and legacy single-target mapping; keep inference loopback-only and native-only.
- Define attempt record/finalizer ownership and Complete-to-EOF validation before terminal success, including malformed trailing frames and bounded cancellation. Link the note from STACK. Stop at design; any semantic change needs an ADR and synchronized specifications.

- [x] Package ownership, startup compatibility and lifecycle/finalization walkthroughs are concrete enough to refine each dependent card without inventing behavior.
- [x] No new LLM schema, frame variant, automatic retry, secret persistence, or released capability claim is introduced.
