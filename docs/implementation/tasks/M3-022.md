# M3-022 — Define deterministic admission window arithmetic

## Outcome

Define pure, deterministic admission window and token charge arithmetic for RPM/TPM rate limits and settlement reconciliation, providing checked mathematical operations with injected timestamps and int64 overflow protection without parsing provider payloads. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- In `internal/core`, implement pure admission and window arithmetic helpers with injected clock and counter inputs:
  - 60,000 ms rolling window boundary and cutoff arithmetic with injected timestamps (`now` and `cutoff = now - 60_000`); exact boundary handling (`t == cutoff` is outside, `t == cutoff + 1` is inside, `t > now` is rejected).
  - Pure RPM admission check: non-positive limit denies all, admits iff `current < RPM`, with checked increment overflow protection.
  - Pure TPM admission check: non-positive limit denies all, sums active held reservations, window settled charges, and candidate estimate using checked int64 addition; admits iff `sum <= TPM`; checked addition overflow denies admission.
  - Pure effective charge calculation:
  - Complete usage with both non-nil, nonnegative input and output: effective charge = `input + output`, reflecting actuals above or below estimate. A completeness marker with a missing counter follows the conservative partial/unknown rule.
  - Partial or unknown usage: effective charge = `max(E, lower_bound)`, where lower bound is the sum of present nonnegative input/output counters; retains estimate `E` when both counters are nil.
    - Detail counters (`reasoning_tokens`, `cached_tokens`) are preserved as detail, never added again to `input + output`.
    - Undispatched attempt: effective charge is 0, releasing reservation.
    - Negative counters or malformed counter values return explicit validation errors and fail closed.
  - Explicit request-versus-attempt admission semantics: initial request admission consumes 1 RPM slot and attempt 1 estimate tokens; fallback/subsequent attempts consume 0 RPM slots and attempt N estimate tokens.
- Explicit limits: does not open SQL transactions or access SQLite directly (reserved for [M3-024](M3-024.md) and [M3-026](M3-026.md)); does not estimate token budgets from payload bodies (reserved for [M3-023](M3-023.md)); does not run background timers or persistent stateful daemons; does not parse provider response bodies.

## Acceptance

- [x] Window cutoff arithmetic uses exact 60,000 ms boundaries; timestamps `<= cutoff` or `> now` fall outside the window; clock rollback or negative timestamps fail closed.
- [x] RPM admission admits when `current < limit` and rejects when `current >= limit`; non-positive limits (<= 0) reject all; checked addition prevents int64 overflow.
- [x] TPM admission admits when `held + settled + estimate <= limit` and rejects when exceeding limit; checked addition prevents int64 overflow and fails closed on overflow; non-positive limits reject all.
- [x] Effective charge calculation:
  - Sets exact `input + output` when both counters are present and nonnegative, allowing charges below or above estimate.
  - Evaluates `max(estimate, known_lower_bound)` for partial/unknown usage or a complete marker with missing input/output; retains estimate when both are nil.
  - Preserves detail counters (`reasoning_tokens`, `cached_tokens`) without double-counting them into `input + output`.
  - Returns zero effective charge for undispatched attempts.
  - Rejects negative counter inputs with explicit error.
- [x] Identity distinction: pure functions distinguish initial request admission (charging 1 RPM slot) from subsequent attempt admission (charging 0 RPM slots).
- [x] Focused pure unit tests verify exact boundaries, rollbacks, overflow (including the final TPM addition and partial lower bound), last-slot admission, negative inputs, missing complete counters, partial counters, and extreme int64 values with deterministic fixed-time inputs without I/O or background timers.
