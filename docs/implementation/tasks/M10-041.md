# M10-041 — Implement purpose-separated Antigravity reasoning AEAD codec and composition-root wiring

## Outcome

Implement the purpose-separated AES-256-GCM reasoning continuation codec and constructor composition-root wiring specified in ADR DEC-031 and M10-BINDING. Securely seals and opens strict version-1 opaque Antigravity reasoning carriers with HKDF-derived purpose keys, length-prefixed canonical AAD, strict JSON schema validation, scope binding, and clock bounds, without exposing MasterKey or Core APIs. Links row in [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [M10 brief](../M10-ANTIGRAVITY.md).

## Scope

- Purpose key derivation in `internal/crypto`: derive a 256-bit purpose key from `MasterKey` via HKDF-SHA-256 with info `pestiroute/antigravity/responses-reasoning/v1`; MasterKey value remains private; existing envelope Seal/Open and credential tests remain unchanged.
- Connector-scoped reasoning codec in `internal/connector/antigravity`:
  - Strict version-1 plaintext JSON schema serialization and deserialization (required and nullable fields).
  - Canonical length-prefixed AAD builder: key version `current-master/v1`, cryptosuite, account ID, credential project ID, model, timestamps, and association indices.
  - Injected clock validation: enforce `0 < expires_at - issued_at <= 24h`, reject `issued_at > now + 5m`, reject `now >= expires_at` with no grace.
  - Fixed safe scope-drift sentinel: reject account, project, or model mismatch with `continuation_scope_mismatch`; M10-042 maps it to pre-dispatch `invalid_request` because no replay/dispatch flow is added here.
  - Size limit: enforce 1 MiB per-carrier maximum.
  - Connector constructor / options accepting scoped codec closure or interface.
- Composition-root wiring in `cmd/gateway`: derive the purpose key from `runtimeKey` (`MasterKey`) and inject the scoped codec into Antigravity connector constructor; zero Core API changes.
- Comprehensive offline tests: schema parsing, AAD tampering, tag tampering, TTL boundaries, clock skew, scope mismatch, limits, concurrency race checks, zero secret/canary leaks in logs or errors, and existing crypto envelope compatibility.
- Explicit limits:
  - NO streaming SSE translation or part reconstruction yet (deferred to M10-042).
  - NO Core runtime API or InvocationServices contract modifications.
  - NO live provider requests or budget deduction (M10-028 remains blocked).
  - NO generic keyring, old-key fallback, or cross-account route fallback.
