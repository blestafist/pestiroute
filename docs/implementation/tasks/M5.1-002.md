## Completion Evidence

Implemented the authorized documentation-only binding: DEC-009 accepts
`AuthResult.UserAction *AuthUserAction` with URI, user code and poll interval;
CONTRACT and M3-AUTH define safe projection, transient presentation, pending
poll cadence, fixed expiry, cancellation and unchanged DEC-007 claim ownership.
M5.1-BINDING records compatibility and the operator boundary. No code or live
provider call was changed/run.

Paper-walk: start presents action and creates a fixed-expiry encrypted state;
pending returns one updated action per explicit continuation and requires the
caller to wait its interval; success ends the session and reports persisted
credentials only after acknowledged write; timeout rejects/consumes before
provider work; cancellation before call consumes the session and after call
begins consumes the claimed state; stale/competing continuations cannot call the
Connector after losing DEC-007 claim/CAS. URI/code are separate from state,
device IDs, PKCE, tokens and raw provider data. Older producers may omit the
optional field and older consumers may ignore it.

Invalid-result cases: completed (`NextAction=""`) or unsupported results with
an action, and any refresh result with an action, are rejected with all result
fields discarded; an invoked refresh marker is quarantined. Validation bounds
are 1–2048 printable ASCII URI bytes (absolute HTTPS, host, no userinfo, no
spaces/controls), 1–256 printable ASCII code bytes (no controls), and positive
poll interval. Malformed fields fail before presentation. On
continue, even when action validation fails after the Connector call, Core
consumes the already-claimed session; if that write cannot commit, DEC-007
restart recovery consumes the ambiguous claim. `continue` with nil action stays
valid for old opaque, non-interactive flows. New interactive connectors must
include the action, enforced in connector auth-flow conformance tests; Core
cannot infer omission from opaque state. Nil/non-nil is self-describing result
discovery, so no new capability is necessary.

The Python relative-link/heading-anchor audit passed across CURRENT, CONTRACT,
M3-AUTH, M5.1-BINDING, TASKS, this card and DECISIONS. `git diff --check`
