# M3-029 — Recover interrupted attempts and limit charges

## Outcome

Recover interrupted attempts, unfinalized requests, and reservations after an abrupt gateway restart without contacting upstreams or replaying executions, and guarantee single active gateway process exclusion per SQLite database path while allowing concurrent local CLI access. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- In `internal/storage/sqlite`:
  - Implement transactional recovery (e.g. `Ledger.Recover(ctx context.Context) (RecoverySummary, error)`) executed under a single `BEGIN IMMEDIATE` transaction:
    - Non-terminal attempts without dispatch intent (`dispatched_at IS NULL` / `state = 'reserved'`): transition attempt to `failed` with `error_reason = 'not_dispatched'`, release reservation (`state = 'released'`, `effective_charge = 0`, `reconciled_at = now`), and mark request `failed` (`state = 'failed'`). The request row remains as the sole RPM charge.
    - Non-terminal attempts with durable dispatch intent (`dispatched_at IS NOT NULL` / `state = 'intent'`): transition attempt to `interrupted` with `error_reason = 'interrupted'`, retain conservative reservation charge (`state = 'conservative'`, `effective_charge = estimated_tokens`, `reconciled_at = now`), write an unknown usage record (NULL token counts, `source = 'unknown'`, `completeness = 'unknown'`), and mark request `interrupted` (`state = 'interrupted'`). Never contact upstreams or replay execution.
    - Admitted requests where all attempts are already terminal (crash between non-final attempt failure and retry): mark request terminal using the last attempt's persisted state (`state = last_attempt.state`) without generating new attempts or reservations.
    - Guarantee idempotency: repeated recovery passes on an already recovered database make zero changes and return identical status summaries.
  - Implement exclusive gateway process lock (e.g. `AcquireProcessLock(dbPath)` / `ProcessLock` using descriptor file locking such as non-blocking `syscall.Flock` with cleanup on Close/Unlock):
    - Prevent a second concurrent gateway process from opening or serving the same database file path.
    - Preserve the local CLI writer model: administrative CLI operations access SQLite directly without requiring the exclusive gateway process lock, serializing via SQLite's WAL write lock and busy timeout.
- Explicit limits:
  - Does not wire gateway startup composition or HTTP listener initialization (reserved for [M3-030](M3-030.md)).
  - Does not contact upstream providers or resume/replay inference.
  - Does not implement CLI usage inspection commands (reserved for [M3-031](M3-031.md)).

## Acceptance

- [x] Stale attempts with committed dispatch intent are recovered to `interrupted` with `error_reason = 'interrupted'`, record unknown usage with NULL counters, retain their conservative estimated token charge (`state = 'conservative'`, `reconciled_at` set), and mark their request `interrupted` (`state = 'interrupted'`) without upstream contact or retry.
- [x] Stale attempts without dispatch intent (`reserved`) are marked `failed` with `error_reason = 'not_dispatched'`, release their token reservation (`state = 'released'`, charge 0), and mark their request `failed` (`state = 'failed'`), while preserving the request row RPM window entry.
- [x] Admitted requests where all attempts were already terminal (crash between non-final failure and retry) are terminalized using the last attempt's persisted terminal state without creating new attempts, reservations, or retry evaluations.
- [x] Recovery is strictly transactional under `BEGIN IMMEDIATE` and idempotent: repeated recovery passes produce zero state changes and return identical ledger summaries.
- [x] Exclusive gateway process lock rejects an overlapping second gateway process fail-closed while permitting concurrent SQLite transactions from non-gateway CLI callers.
