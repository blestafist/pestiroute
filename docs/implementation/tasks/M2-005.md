# M2-005 — Validate registry identities and API compatibility

## Outcome

A small in-process registry rejects invalid components before they can execute. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Descriptor/version rules](../CONTRACT.md#component-descriptor-and-lifecycle), [API compatibility](../CONTRACT.md#versioning-and-change-control).
- [M2 component binding](../M2-BINDING.md#package-ownership) and [Component API](../M2-BINDING.md#component-api).
- Shared descriptor and component types in `internal/core/component.go`.

## Scope

- Add instance registration and lookup against interfaces; wire implementations outside the registry.
- Validate unique instance identities, required descriptor fields, supported API versions and declared protocols/extensions. Do not initialize components or dynamically load plugins.

## Acceptance

- [x] Duplicate IDs and incompatible major API versions are rejected before Init/Execute; multiple valid instances of one implementation remain possible.
- [x] Unknown required operations/extensions fail explicitly; optional information follows v1 compatibility rules.
- [x] Lookups expose neither mutable registry storage nor concrete Connector dependencies.

## Open Questions / Blocker

## Completion Evidence

Implemented `internal/core.Registry` for adapter/connector interface registration. It rejects duplicate runtime instance IDs, invalid required descriptors, unsupported exact API pairs, and missing configured required operations before any lifecycle method is called. Reusing one implementation ID across distinct instances is supported. Lookup returns the component interface and a cloned authoritative snapshot of the descriptor validated at registration; later mutation of the component's descriptor does not affect lookup. Optional declared operations remain accepted. The registry exposes neither its maps nor concrete Connector dependencies. A small RWMutex supports concurrent Register/Lookup; registration is still explicit, with no reload or dynamic loading.

Verified with Go 1.27.1: `GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go test -race -count=1 ./internal/core/...` passed; `./scripts/check.sh` passed formatting, vet, tests, race tests, and offline build; `git diff --check` passed; final gopls diagnostics were clean. Direct tests cover duplicate/empty instance IDs; invalid descriptor, nil component, unconfigured and mismatched kinds; invalid constructor kind/zero major/duplicate and empty required operations; exact major-and-minor matching; required versus optional operations; no Init on rejection; repeated implementation IDs; lookup isolation and post-registration descriptor mutation; concurrent Register/Lookup. No real-provider behavior is involved.
