# M3-008 — Create request, attempt and reservation schema

## Outcome

Add versioned migration 4 to the SQLite storage migration engine establishing `requests`, `attempts`, `usage_records`, and `reservations` relational schema, integrity constraints, and indexes. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Add version 4 to `schemaMigrations` in `internal/storage/sqlite/migrate.go` creating:
  - `requests` table: `id TEXT PRIMARY KEY`, `virtual_key_id TEXT REFERENCES virtual_keys(id) ON DELETE SET NULL`, `key_revision INTEGER NOT NULL CHECK (key_revision >= 1)`, `policy_id TEXT NOT NULL`, `policy_revision INTEGER NOT NULL`, `accepted_at INTEGER NOT NULL`, `protocol TEXT NOT NULL`, `model TEXT NOT NULL`, `route_id TEXT NOT NULL`, `state TEXT NOT NULL CHECK (state IN ('admitted', 'succeeded', 'failed', 'cancelled', 'interrupted'))`, `finished_at INTEGER`, with `FOREIGN KEY (policy_id, policy_revision) REFERENCES key_policies(id, revision) ON DELETE RESTRICT`.
  - `attempts` table: `id TEXT PRIMARY KEY`, `request_id TEXT NOT NULL REFERENCES requests(id) ON DELETE RESTRICT`, `ordinal INTEGER NOT NULL CHECK (ordinal >= 1)`, `account_id TEXT REFERENCES accounts(id) ON DELETE SET NULL`, `connector TEXT NOT NULL`, `route_id TEXT NOT NULL`, `budget_policy TEXT NOT NULL`, `estimate_tokens INTEGER NOT NULL CHECK (estimate_tokens >= 0)`, `estimate_method TEXT NOT NULL`, `state TEXT NOT NULL CHECK (state IN ('reserved', 'intent', 'succeeded', 'failed', 'cancelled', 'interrupted'))`, `committed INTEGER NOT NULL DEFAULT 0 CHECK (committed IN (0, 1))`, `error_category TEXT`, `error_reason TEXT`, `dispatched_at INTEGER`, `finished_at INTEGER`, with `UNIQUE (request_id, ordinal)`.
  - `usage_records` table: `attempt_id TEXT PRIMARY KEY REFERENCES attempts(id) ON DELETE RESTRICT`, `input_tokens INTEGER CHECK (input_tokens >= 0)`, `output_tokens INTEGER CHECK (output_tokens >= 0)`, `reasoning_tokens INTEGER CHECK (reasoning_tokens >= 0)`, `cached_tokens INTEGER CHECK (cached_tokens >= 0)`, `source TEXT NOT NULL`, `completeness TEXT NOT NULL`, `recorded_at INTEGER NOT NULL`.
  - `reservations` table: `attempt_id TEXT PRIMARY KEY REFERENCES attempts(id) ON DELETE RESTRICT`, `estimated_tokens INTEGER NOT NULL CHECK (estimated_tokens >= 0)`, `actual_tokens INTEGER CHECK (actual_tokens >= 0)`, `effective_charge INTEGER CHECK (effective_charge >= 0)`, `state TEXT NOT NULL CHECK (state IN ('held', 'settled', 'released', 'conservative'))`, `reconciled_at INTEGER`.
  - Indexes:
    - `idx_requests_key_accepted ON requests(virtual_key_id, accepted_at)`.
    - `idx_attempts_request ON attempts(request_id)`.
    - `idx_reservations_state_reconciled ON reservations(state, reconciled_at)`.
- Use UTC Unix-millisecond integers (`INTEGER`) for `accepted_at`, `finished_at`, `dispatched_at`, `recorded_at`, and `reconciled_at` per M3-STORAGE.md.
- Ensure nullable usage counters (`input_tokens`, `output_tokens`, `reasoning_tokens`, `cached_tokens`) allow `NULL` to distinguish unknown usage from zero.
- Ensure schema compatibility with the existing migration runner, preserving WAL, `synchronous=FULL`, foreign keys, and 500 ms busy timeout.
- Explicit limits: schema migrations, indexes, and DDL checks only; no repository Go structs/methods (belongs to M3-021); no admission window arithmetic or in-memory estimators (belongs to M3-022, M3-023); no atomic admission or dispatch coordinator code (belongs to M3-024, M3-025); no request/response payload or provider error body columns.

## Acceptance

- [x] Version 4 migration applies atomically via `Migrate` on top of version 3 or fresh database, recording version 4 in `schema_migrations`.
- [x] Primary key uniqueness is enforced for `requests(id)`, `attempts(id)`, `usage_records(attempt_id)`, and `reservations(attempt_id)`.
- [x] Attempt ordinal uniqueness is enforced per request via `UNIQUE (request_id, ordinal)`.
- [x] Foreign key constraints enforce referential integrity:
  - `requests` references `(policy_id, policy_revision)` on `key_policies` with `ON DELETE RESTRICT` and `virtual_key_id` on `virtual_keys` with `ON DELETE SET NULL`.
  - `attempts` references `request_id` on `requests` with `ON DELETE RESTRICT` and `account_id` on `accounts` with `ON DELETE SET NULL`.
  - `usage_records` and `reservations` reference `attempt_id` on `attempts` with `ON DELETE RESTRICT`.
- [x] Deleting or disabling an account or key does not delete historical requests, attempts, or ledger records.
- [x] Nullable counters (`input_tokens`, `output_tokens`, `reasoning_tokens`, `cached_tokens`, `actual_tokens`, `effective_charge`) survive round trips; unknown usage remains SQL `NULL` and is distinguishable from 0.
- [x] CHECK constraints reject negative token amounts, non-positive ordinals (`ordinal < 1`), non-positive key revisions (`key_revision < 1`), and invalid boolean/state enum strings (`committed IN (0, 1)`, `requests.state`, `attempts.state`, `reservations.state`).
- [x] Timestamps use `INTEGER` UTC Unix milliseconds (`accepted_at`, `finished_at`, `dispatched_at`, `recorded_at`, `reconciled_at`).
- [x] No request payload, response body, or raw provider error diagnostic columns exist.
- [x] `PRAGMA foreign_key_check` passes with zero violations across sample request/attempt/ledger rows.
- [x] Failed migration statement in a test migration rolls back atomically, leaving the database at version 3 without partial DDL.
- [x] Existing migration idempotency and future-schema refusal tests continue to pass with the new migration version.
