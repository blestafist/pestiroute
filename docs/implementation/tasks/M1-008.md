# M1-008 — Scoped one-attempt HTTP transport

## Outcome

One Connector invocation can send inference only to the selected target with its selected credential. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-005 binding, M1-006 configuration, [Connector](../CONTRACT.md#connector-contract), [HTTP constraints](../STACK.md#http-and-streaming), [HTTP replay scenarios](../TESTING.md#testing-levels).

## Scope

- Build the Connector-owned reusable HTTP transport/request constructor using the scoped runtime credential access.
- Explicitly prevent redirect following, automatic decompression and hidden inference replay; filter transport headers including Connection-nominated fields and replay-triggering inputs.
- Stop before response frame production and full gateway integration. No SDK, account fallback or retry engine.

## Acceptance

- [ ] Captured URL, method and original body match the selected target; only selected upstream authorization is sent.
- [ ] Redirect destination receives zero requests/credentials; a dropped reused connection does not silently resend a replayable inference body, including idempotency-header cases.
- [ ] Response encoding bytes remain untouched; request context cancellation stops transport work and resources can be closed.

## Verification

From root run loopback capture, redirect, connection-drop and compression transport tests, then `./scripts/check.sh`. Audit the actual Go transport replay conditions, not just configured flags. Name tests and any fixture extension at READY.
