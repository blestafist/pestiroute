# M2-023 — Add lifecycle and scoped-service conformance cases

## Outcome

Both native-loopback and scripted Connector implementations pass identical contract scenarios for component lifecycle, health transitions, descriptor discovery, invocation scope, and honest support operations. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Expand `internal/conformance` with shared lifecycle and scoped-service scenarios executed against both native-loopback and scripted connector factories:
  - Descriptor-before-Init: `Descriptor()` reports stable identity, API versions, and declared operations without prior `Init()` or upstream network access.
  - Health state transitions: health reports not-ready before `Init()`, `ready` after successful `Init()`, and `unavailable` after `Close()`.
  - Execution gate before readiness: `Execute()` before `Init()` or after `Close()` fails cleanly with an unavailable gateway error and zero upstream provider/fixture calls.
  - Failed `Init()` cleanup: invalid configuration fails initialization, leaves the component unavailable, releases partial resources, and rejects subsequent execution.
  - Idempotent `Close()`: repeated `Close()` invocations succeed without error or panic.
  - Invocation scope and credential isolation: missing credentials or mismatched account/model/mode scope reject cleanly with gateway errors (`credential_unavailable` or `scope_mismatch`) without leaking cross-scope state or fabricating success.
  - Honest support operations: `Models()`, `EstimateUsage()`, and `Authenticate()` return explicit unsupported or valid scoped results rather than fabricated success or synthetic zero usage.
- Explicit limits:
  - Do not implement payload opacity or incremental chunking (M2-024), stream contract violations (M2-025), error/usage normalization (M2-026), cancellation/partial-close (M2-027), or backpressure (M2-028).
  - No new production packages or runtime core changes; test-only additions under `internal/conformance/`.
  - Local synthetic fixtures only; no live network access or real credentials.

## Acceptance

- [x] Conformance runner executes shared lifecycle scenarios across both native-loopback and scripted connector factories: descriptor discovery before Init, zero upstream calls before Init or after Close, and idempotent repeated Close.
- [x] Failed initialization leaves the connector unavailable, releases partial resources once, and subsequent execution is rejected.
- [x] Invocation scope isolation is enforced: missing credentials or mismatched model/account/mode scope reject cleanly with gateway errors without fabricating success or making upstream calls.
- [x] Support operations (`Models`, `EstimateUsage`, `Authenticate`) return explicit unsupported or strictly scoped results without fabricating success or unmeasured usage.
- [x] Mandatory lifecycle checks cannot be skipped, and deliberate negative mutations in fixtures are rejected by assertion-bearing checks.
