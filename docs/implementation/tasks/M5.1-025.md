# M5.1-025 — Extract inclusive usage without subset double counting

## Outcome

Extract terminal and partial token counters from Codex Responses SSE events into normative `core.UsageReport` metadata without double-counting subsets or altering forwarded body bytes. One bounded deliverable in the [M5.1 Codex registry](../TASKS.md#m51--codex-subscription-connector), under [ROADMAP M5.1](../ROADMAP.md#m51--agent-protocol-connectors).

## Scope

- Parse `response.usage` object from terminal SSE event payloads (`response.completed`, `response.incomplete`, `response.failed`) or intermediate usage events when present.
- Extract inclusive `input_tokens` and `output_tokens` into `*core.UsageReport` with `Source: core.UsageProvider`.
- Extract subset fields `input_tokens_details.cached_tokens` (`CachedTokens`) and `output_tokens_details.reasoning_tokens` (`ReasoningTokens`) without double counting (subsets are contained within input/output totals, not added).
- Handle explicit zero vs absent counters: absent or null usage fields/objects yield `core.UsageUnknown` (`Completeness: core.UsageUnknownCompleteness`), never fabricated zero; zero-valued counters are preserved as `0`.
- Mark complete terminal usage as `core.UsageComplete`; mark interrupted or partial usage as `core.UsagePartial`.
- Validate consistency: negative counters, overflow, or subset exceeding total (e.g. cached > input, reasoning > output) fail closed or treat malformed usage as unknown/invalid rather than corrupting accounting.
- Preserve raw SSE usage bytes verbatim in caller-visible `BodyFrame`s.
- Keep token usage accounting separate from provider quota headers / `codex.rate_limits`; implement no quota dashboard or probe.
- Pass the extracted `*core.UsageReport` to `CompleteFrame.Usage` in `executeStream`.
- Explicit non-scope: route budget estimation belongs to M5.1-026; route composition belongs to M5.1-027.

## Acceptance

- [x] Inclusive totals `input_tokens` and `output_tokens` are mapped directly to `UsageReport` fields; `cached_tokens` and `reasoning_tokens` are extracted as subsets without addition/double counting.
- [x] Absent, missing, or null usage counters produce `core.UsageUnknown` / `UsageUnknownCompleteness`; explicit zeros are preserved as `0` tokens.
- [x] Complete terminal event produces `UsageComplete`; interrupted, failed, or premature streams retain partial or unknown usage without fabricating zero or free usage.
- [x] Inconsistent counters (negative values, integer overflow, cached > input, reasoning > output) fail closed or revert to unknown without corrupting accounting.
- [x] Original SSE chunks and usage JSON payload bytes in `BodyFrame` remain verbatim and unmodified.
- [x] Exactly one `CompleteFrame` is emitted carrying the final `UsageReport`, preventing duplicate usage reporting or charging.
