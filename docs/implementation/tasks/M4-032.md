## Scope

- Publish `docs/implementation/M4-COMPATIBILITY.md` documenting the full evidence-backed compatibility matrix for `openai.responses.v1` translation to Anthropic Messages (`claude-opus-5-5`):
  - Profile scope: protocol `openai.responses.v1`, mode `translation`, target `https://api.anthropic.com/v1/messages`, version `2023-06-01`, backend model `claude-opus-5-5`.
  - Capability vocabulary: audit and document statuses (`supported`, `unsupported`, `unknown`) for all standard CONTRACT capabilities (`llm.streaming`, `llm.tools`, `llm.tools.parallel`, `llm.reasoning`, `llm.structured_output`, `llm.vision`, `llm.audio`, `auth.oauth`, `usage.exact`).
  - Request/response field policy: full table of admitted, defaulted, and rejected fields with exact error behaviors (`invalid_request` pre-dispatch vs `unsupported_capability` at admission vs `unsupported_feature`).
  - Concrete local proof vs live status: link specific fixture and scenario tests from M4-001 through M4-031; explicitly mark live provider entitlement and wire compatibility as unverified/unknown until M4-036/M4-037.
- Audit and synchronize Connector `Capabilities` and `Models` declarations in `internal/connector/anthropic/component.go`:
  - Confirm `llm.streaming: Supported` and `llm.tools: Supported`.
  - Confirm unproven or unsupported features (`llm.tools.parallel`, `llm.reasoning`, `llm.vision`, `llm.audio`, `llm.structured_output`, `auth.oauth`, `usage.exact`) remain undeclared (`Unknown`) or `Unsupported` as justified.
- Add or verify negative capability tests in `internal/connector/anthropic/component_test.go` and `cmd/gateway/` ensuring unsupported or unknown capability requests fail closed at Core eligibility with HTTP 400 `unsupported_capability`.
- Index `docs/implementation/M4-COMPATIBILITY.md` in `docs/README.md`.
- Explicit limits: Do not make live provider network calls; do not alter Core routing or Adapter public contracts; do not weaken existing native or translation conformance checks.
