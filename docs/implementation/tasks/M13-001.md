Bind single-node deployment and recovery acceptance for [M13 — Deployment and Recovery](../M13-OPERATIONS.md) and [Roadmap Stage 13](../ROADMAP.md#m13--deployment-and-recovery). ## Scope

- Audit existing flags/config (`-config`, `-config-format`, `-listen`, `-shutdown-timeout`), protected YAML runtime requirements (`storage.path`, `secrets.master_key_file`), the gateway's exclusive `flock` sidecar (not SQLite `PRAGMA locking_mode=EXCLUSIVE`), migrations, and signal handling (`SIGINT`, `SIGTERM`).
- Specify in `docs/implementation/M13-BINDING.md`:
  - Linux/amd64 target prerequisites and unprivileged user model (no root required, non-root system user).
  - Explicit file paths, permissions (master key 0600, DB 0600/0700 dir), and environment requirements.
  - Consistent SQLite backup/restore procedure using stopped gateway or online vacuum/backup API constraints (no raw WAL copy during active writes).
  - Clean shutdown lifecycle, socket/process lock release, and failure recovery.
  - Acceptance checklist for downstream packaging (M13-002), backup/restore tests (M13-003), and offline release acceptance (M13-004).
- Limits: Documentation and binding specification only; no new Go code, Dockerfile, systemd unit, or CI edits in this task. No remote orchestrators (Kubernetes) or multi-node clustering.
