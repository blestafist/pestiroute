# M6-008 — Implement child process launch and resource cleanup

## Outcome

Launch and reap one configured child with owned private Unix-socket resources. See [registry](../TASKS.md#m6--external-plugin-runtime) and [binding](../M6-BINDING.md#ownership-topology-versions).

## Read First

- [M6-BINDING](../M6-BINDING.md#ownership-topology-versions)
- [M6-EXTERNAL](../M6-EXTERNAL.md#binding-gate)
- `internal/core/registry.go`; repository process-launch conventions

## Scope

- External supervisor/process package only; explicit executable/argv, working directory, allowlisted environment, private directory and paired Connector/HostServices sockets, bounded diagnostics and process-tree cleanup.
- No gateway config/startup wiring or handshake implementation; those remain separate tasks.

## Acceptance

- [x] Launch absolute executable/literal argv/working directory without a shell; inherit no environment and inject only the two named socket-path variables (`PESTIROUTE_CONNECTOR_SOCKET`, `PESTIROUTE_HOST_SERVICES_SOCKET`); both socket peers/ownership are checked and only owned resources are removed.
- [x] Own a new process group (`Setpgid=true`, PGID=child PID); stop/drain, TERM, KILL after 2 s, direct-child Wait exactly once, group disappearance by 5 s, and owned socket cleanup follow M6-BINDING. Child reaps its descendants on orderly close; no claim that host reaps orphan descendants' wait statuses.
- [x] Bound diagnostic retention to 64 KiB; close/reap on startup error, cancellation and shutdown.
- [x] Linux-only same-user process supervision; no OS sandbox or cross-platform claim.
