## Scope

- Exercise the assembled Codex Connector under configured multi-candidate fallback topologies:
  - Local non-retryable rejection (e.g. malformed profile or validation error in `validateResponsesProfile`).
  - Conclusively unsent failure if provable vs. ambiguous send (transport failure without proof of not-sent stays non-retryable / retry disposition denied; no fallback).
  - HTTP rejection (e.g. HTTP 401, 403, 429, 500: pre-head rejection, non-retryable / retry disposition denied; exactly one upstream call occurs, no switch to second candidate).
  - Committed SSE stream failure (e.g. `response.failed`, `error`, truncated stream, or malformed SSE after `FrameHead`: `RetryCommitted` denies fallback; exactly one candidate attempt).
  - Client cancellation / disconnect after dispatch (no hidden inference replay).
  - Stateful / unknown affinity boundaries: verify that opaque encrypted reasoning or session-bound requests fail closed before dispatch against multi-candidate routes and execute only on configured singleton target routes without candidate cycling.
  - Accounting and admission: verify attempt counts, single RPM admission across attempts, per-attempt reservations, and deadline bounds.
- Explicit limits: No speculative client retry, no heuristic replay for HTTP 429/5xx, no session directories, and no cross-account state migration.

## Acceptance

- [x] Only conclusively safe no-send plus explicit runtime policy can start a new eligible attempt; validation, ambiguous transport failure, HTTP 401/403/429/5xx, and committed SSE stream failure cause exactly one call without fallback.
- [x] Ambiguous send, response.failed after commit, 401 and client cancellation cause no hidden inference replay or account switch.
- [x] Opaque replay cannot fan out to another account/profile; attempt counts, one request admission, per-attempt reservations and configured deadline remain correct.
