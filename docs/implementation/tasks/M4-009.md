# M4-009 — Bind translation usage estimates to existing admission budgets

## Outcome

Bind translation usage estimates to existing admission budgets. One bounded deliverable in the [M4 registry](../TASKS.md#m4--first-translation-connector)
toward the original [M4](../ROADMAP.md#m4--first-translation-connector).

## Read First

- [Usage and retry decisions](../M4-TRANSLATION.md#usage-and-retry-decisions).
- [Per-route estimate budget](../M3-CONFIG.md#per-route-estimate-budget).
- `internal/core/estimate.go` and `internal/core/estimate_test.go`.
- `internal/connector/anthropic/component.go` and `internal/connector/anthropic/translate.go`.

## Scope

- Implement scoped `EstimateUsage` on the Anthropic Connector (`internal/connector/anthropic/component.go`):
  - Validate scope (protocol `"responses"`, mode `"translation"`, configured model, and configured account ID) and readiness (`HealthReady`), returning predictable `*core.GatewayError` on mismatch or unavailability.
  - Return honest unknown estimate (`core.EstimateResult{Supported: true, Known: false, Method: "conservative"}`) to integrate with Core's existing `RouteBudget` admission path without inventing an exact local tokenizer or calling external count services.
  - Reject unsupported protocols or execution modes pre-admission with client-safe `*core.GatewayError`.
- Verify Core admission behavior with `RouteBudget`:
  - When route budget specifies `unknown_estimate: reject`, unknown translation estimates fail admission with `estimate_unavailable` before upstream dispatch.
  - When route budget specifies `unknown_estimate: reserve`, Core reserves `budget.ConservativeTokens` (bounded arithmetic, non-positive reservation forbidden).
- Enforce opaque payload bytes and input immutability throughout estimation.
- Allocation of output floor enforcement:
  - Route-level budget floor enforcement (`conservative_tokens >= 4096` matching M4-008's sent `max_tokens` ceiling) is assigned to configuration binding in [M4-014](M4-014.md) to preserve Core payload opacity without inventing speculative `EstimateResult` fields or ADRs.
- Out of scope: Route config validation and `conservative_tokens` floor enforcement (M4-014), HTTP transport error classification (M4-010), SSE parsing (M4-011), streaming execution (M4-013), and durable settlement/accounting integration (M4-028).

## Acceptance

- [x] `EstimateUsage` validates scope (protocol, mode, model, account ID) and readiness; mismatches and unavailable state fail with appropriate `*core.GatewayError`.
- [x] Translation usage is never reported as zero or exact without an offline tokenizer; honest unknown estimates (`Known: false`, method `"conservative"`) integrate with Core `RouteBudget`.
- [x] Routes configured with `unknown_estimate: reject` reject translation requests pre-admission with `estimate_unavailable`.
- [x] Routes configured with `unknown_estimate: reserve` admit translation requests reserving `conservative_tokens`.
- [x] Invalid route budgets (e.g. non-positive conservative tokens with `reserve`, or conservative tokens with `reject`) fail predictably.
- [x] Request payload bytes are preserved immutably throughout estimation.
