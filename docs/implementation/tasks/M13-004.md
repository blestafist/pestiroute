## Scope

- Create standalone automated release acceptance test script `scripts/verify-release.sh` verifying on the packaged Linux/amd64 artifact:
  1. Unprivileged runtime execution using protected YAML (`-config-format yaml -config <path>`) with explicit DB, master key, listener, and timeout paths.
  2. Protected JSON request/response and SSE stream delivery to a deterministic fake upstream with complete request/response byte comparisons against expected fixtures.
  3. Client cancellation handling during streaming (early disconnect), confirming gateway aborts upstream call, recovers cleanly, and cleans up sockets and descriptors.
  4. Authentication failure cases: nonexistent virtual key and revoked virtual key fail closed with 401/403 and zero upstream delivery.
  5. Accounting durability across restart: snapshot stable request/attempt IDs and usage values before restart, compare the exact historical set after restart, then prove a new request creates exactly one expected usage record.
  6. Consistent online backup and distinct-path restore lifecycle: compare the complete historical usage snapshot across online backup and restored DB, start gateway against restored DB, and prove authenticated traffic creates exactly one expected new record.
  7. Process and socket cleanup: assert child processes, locks, and temporary sockets clean up without lingering background processes.
- Author `docs/implementation/M13-HANDOFF.md` documenting:
  1. Tested platform (Linux/amd64), pinned Go 1.27.1 toolchain, prerequisites, and resource bounds (CPU, memory, file descriptors, zero GPU/account).
  2. Operator commands for build, packaging, backup, recovery, and release verification.
  3. Clean shutdown, lock release, and restore outcomes.
  4. Explicit release limitations: UI packaging deferred until M12-006 is on main; provider live gates (M4-036, M4-041, M5.1-049, M5.2-025, M8-008) remain deferred/blocked and are not satisfied by fake-upstream tests.
- Update `deploy/README.md` if necessary to reference release acceptance commands.
- Limits: Single-node Linux/amd64 only; no real provider calls, GPUs, or external network access. No changes to core contracts, schema, or CLI flags. No edits to other lanes' files (`internal/connector/antigravity/**`, `web/**`, management packages).
