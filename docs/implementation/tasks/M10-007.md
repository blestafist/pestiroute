# M10-007 — Research and bind Antigravity OAuth refresh lifecycle and Authenticate state machine

## Outcome

Produce a bounded research and binding specification (`M10-AUTH-BINDING.md`) defining the Antigravity OAuth token refresh lifecycle and `Connector.Authenticate` (`Action=refresh`) state machine under `CONTRACT.md` and `DEC-010`. See row in [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and milestone in [ROADMAP.md](../ROADMAP.md#m10--google-antigravity-connector).

## Scope

- Within `docs/implementation/`:
  - Create `M10-AUTH-BINDING.md`:
    - Document research on Google Antigravity OAuth refresh payload structure, token lifetime, and synthetic token exchange endpoints.
    - Specify `Connector.Authenticate` state machine for `AuthRequest.Action=refresh`: parsing refresh token from existing credential bundle, executing synthetic exchange against `.invalid` endpoint, and returning updated candidate credentials with absolute expiry per `DEC-010`.
    - Clarify boundary with inference `Execute`: `Execute` only retrieves unexpired credentials via `services.Credentials.Get(ctx, "oauth")`, never triggers token refresh directly, and classifies 401 as non-retryable `unauthenticated` (`false / unsafe`).
    - Design synthetic token refresh fixtures and offline test specifications without live provider access.
    - Explicitly classify unverified OAuth scopes, endpoints, and live refresh flows as BLOCKED.
- Limits:
  - Documentation, research, and synthetic fixture specification only.
  - Strictly within M10 ownership; no runtime code changes in `internal/...` or gateway composition in `cmd/...`.
  - No live network requests or claims of live provider capability.
