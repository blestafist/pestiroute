# M10-007 — Research and bind Antigravity OAuth refresh lifecycle and Authenticate state machine

## Outcome

Produce a bounded research and binding specification (`M10-AUTH-BINDING.md`) defining the Antigravity OAuth token refresh lifecycle and `Connector.Authenticate` (`Action=refresh`) state machine under `CONTRACT.md` and `DEC-010`. Clarifies refresh payload formats, runtime coordination, explicit credential expiry (`CredentialExpiresAt`), and synthetic transport exchange without conflating inference `Execute` (where `services.Credentials.Get` rejects expired tokens and 401 is ambiguous/unauthenticated; no `Execute` token refresh). Delivers auth lifecycle research for [Google Antigravity Connector](../M10-ANTIGRAVITY.md). See row in [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and milestone in [ROADMAP.md](../ROADMAP.md#m10--google-antigravity-connector).

## Scope

- Within `docs/implementation/`:
  - Create `M10-AUTH-BINDING.md`:
    - Document research on Google Antigravity OAuth refresh payload structure, token lifetime, and synthetic token exchange endpoints.
    - Specify `Connector.Authenticate` state machine for `AuthRequest.Action=refresh`: parse refresh material from the single `oauth` credential bundle, execute synthetic exchange against `.invalid`, and return that complete replacement value with explicit absolute expiry (`CredentialExpiresAt`) per `DEC-010`.
    - Clarify runtime coordinator contract vs inference `Execute`: runtime coordinator owns auth-scoped credential resolution, dispatching `Authenticate(Action=refresh)`, and atomic CAS persistence of new credentials and expiry; inference `Execute` remains strictly read-only via `services.Credentials.Get(ctx, "oauth")`, rejects expired tokens, never triggers token refresh directly, and classifies 401 as non-retryable `unauthenticated` (`false / unsafe`).
    - Design synthetic token refresh fixtures and offline test specifications without live provider access.
    - Specify the narrow future Execute parser change (known access/refresh fields only; send access token only), plus negative parser/leakage cases and a synthetic persist-then-Execute test on the same one-entry credential generation.
    - Explicitly classify unverified OAuth scopes, discovery endpoints, and live refresh flows as BLOCKED; exclude speculative scope or quota filler.
- Limits:
  - Documentation, research, and synthetic fixture specification only.
  - Strictly within M10 ownership; no runtime code changes in `internal/...` or gateway composition in `cmd/...`.
  - No live network requests or claims of live provider capability.
