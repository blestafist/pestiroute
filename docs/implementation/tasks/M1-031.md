# M1-031 — Fix upstream ordinary JSON read timeout and dispatch cancellation race

## Outcome

Fix hung upstream ordinary JSON body reads by applying stream idle timeout handling, and eliminate the race condition in `TestDispatchCancelAndPreExecuteFailure`. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- `internal/connector/responses/fixed.go` and `internal/connector/responses/sse.go` (idle timeout handling).
- `internal/core/dispatch.go` and `internal/core/dispatch_test.go` (`attemptStream` cancellation and finalization lifecycle).
- [CONTRACT.md](../CONTRACT.md#streaming-and-backpressure) and [TESTING.md](../TESTING.md#testing-levels).

## Scope

- In `internal/connector/responses/fixed.go`, enforce `streamIdleTimeout` during body reads in `fixedStream.Next`, mirroring `sseStream` timeout semantics, ensuring hung upstream bodies trigger cancellation and timely cleanup.
- In `internal/core/dispatch.go` and/or `internal/core/dispatch_test.go`, synchronize cancellation teardown and attempt finalization so that `TestDispatchCancelAndPreExecuteFailure` does not race between context `AfterFunc` completion and stream close/assertion.
- Stop before modifying public API contracts, introducing unconfigured timeouts, or altering SSE streaming logic.

## Acceptance
