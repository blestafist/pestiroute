## Scope

- Implement Connector-private request validation for standard Responses profile according to M5.1-BINDING field policy: model matching, streaming, store policy, tools, max_output_tokens, unsupported features, and continuation controls.
- Enforce mode-specific invariants: native mode requires `stream: true` and explicit `store: false`; translation mode admits omitted `store` (for downstream defaulting) but rejects explicit `store: true` and `stream: false`.
- Enforce payload constraints: 1 MiB body size limit, duplicate JSON key rejection, and malformed JSON fail-closed rejection.
- Reject unsupported features before credential lookup or HTTP transport: unsupported tool types, background/resources, unsupported output controls, and stateful session references (`previous_response_id`, `conversation`).
- Admit valid text, function, and reasoning fixtures without mutating payload bytes or initiating network calls.

## Acceptance

- [x] Explicit `store:true`, non-streaming (`stream:false`), background/resources, unsupported output caps, and unsupported tool types fail with sanitized `GatewayError` (`CategoryUnsupportedFeature` or `CategoryInvalidRequest`).
- [x] Mode rules are enforced: native requires explicit `stream:true` and `store:false`; translation rejects `store:true` and non-streaming while permitting omitted `store`.
- [x] Payload bounds and integrity are enforced: bodies > 1 MiB, malformed JSON, and duplicate keys are rejected fail-closed without leaking sensitive details.
- [x] Stateful continuation controls (`previous_response_id`, `conversation`) fail closed before network send.
- [x] Valid text, function call/output, and reasoning fixtures (including existing `request-positive.json`, `request-tools-history.json`, `request-reasoning-item.json`) are admitted with immutable payload bytes and zero upstream sends.
