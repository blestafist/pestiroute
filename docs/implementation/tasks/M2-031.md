# M2-031 — Verify concurrent attempt and scope isolation

## Outcome

Concurrent request execution, terminal completion, cancellation, and component shutdown cannot mix scopes, leak credentials/tokens, or duplicate attempt observations across routes and accounts. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Internal execution contract](../CONTRACT.md#component-descriptor-and-lifecycle) (concurrency, lifecycle, component close).
- [Usage and scoped runtime services](../CONTRACT.md#usage-and-scoped-runtime-services) (attempt isolation, credentials, once-only accounting).
- Existing concurrency and observation coverage: `internal/core/dispatch_test.go` (`TestDispatchConcurrentIsolationAndCancellation`, `TestDispatchConcurrentTerminalSignals`, `TestAttemptObservation`), `internal/core/services_test.go`, and `cmd/gateway/main_test.go` (`TestGatewayShutdownDrainsAndCancels`).

## Scope

- In `internal/core/dispatch_test.go` (and `cmd/gateway/main_test.go` if multi-route gateway concurrency is exercised):
  - Add synchronized multi-attempt concurrent execution across distinct routes, accounts, and credentials (`AttemptScope{AccountID, Mode, ID}` and `InvocationServices.Credentials()`).
  - Verify competing simultaneous terminal signals (success vs client cancellation vs stream Close vs shutdown) settle deterministically without cross-attempt corruption.
  - Verify trailing malformed or duplicate frames (e.g. repeated Complete or trailing Body after Complete) emitted on one attempt cannot corrupt concurrent or subsequent independent attempts.
  - Verify `InMemoryAttemptObservations` and `AttemptResult` recording under concurrent multi-attempt execution: each attempt produces exactly one immutable terminal observation with distinct attempt IDs, preserved scoped usage, and correct outcome without clobbering.
- Explicit limits:
  - Deterministic synthetic fixtures only; no live provider networks or credentials.
  - No persistent database, distributed locking, or admission rate limiters (strictly M3 scope).
  - No multi-target fallback or automatic retry loops (strictly M3 scope).

## Acceptance

- [x] Distinct concurrent requests across different routes and accounts maintain strictly isolated `AttemptScope`, credential tokens, request/attempt IDs, and opaque payloads with zero data races.
- [x] Each executed attempt yields exactly one terminal `AttemptResult` and observation record; failed, timed out, or cancelled attempts never overwrite or corrupt concurrent or subsequent successful attempts.
- [x] Competing terminal signals (simultaneous Close, EOF, context cancel, and registry shutdown) release all held gates and resources cleanly without goroutine leaks.
- [x] `GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go test -race -count=5 -run 'Test.*Concurrent.*|Test.*Isolation.*' ./internal/core/... ./cmd/gateway/...` and `./scripts/check.sh` pass cleanly.
