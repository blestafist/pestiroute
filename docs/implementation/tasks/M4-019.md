# M4-019 — Translate function call and result history

## Outcome

Translate function call and result history. One bounded deliverable in the [M4 registry](../TASKS.md#m4--first-translation-connector)
toward the original [M4](../ROADMAP.md#m4--first-translation-connector).

## Read First

- [Request policy decisions](../M4-TRANSLATION.md#request-policy-decisions).
- [M4 binding](../M4-BINDING.md).
- Anthropic official [Messages create](https://platform.claude.com/docs/en/api/messages/create) and [Tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use).
- Existing translation parser in `internal/connector/anthropic/translate.go` and tests in `internal/connector/anthropic/translate_test.go`.

## Scope

- Map Responses input history items `function_call` and `function_call_output` in `internal/connector/anthropic/translate.go` to Anthropic Messages `assistant` (`tool_use`) and `user` (`tool_result`) content blocks.
- Distinguish output item IDs (`id`), call IDs (`call_id`), function names (`name`), and JSON argument strings (`arguments`). Parse argument strings into structured JSON objects for Messages `tool_use.input`.
- Group consecutive or mixed function calls and outputs into valid Messages message structures (`assistant` with `tool_use`, `user` with `tool_result`) without altering semantic history order.
- Enforce fail-closed validation before dispatch:
  - Reject orphan `function_call_output` referencing unknown or non-preceding `call_id`.
  - Reject duplicate `call_id` definitions.
  - Reject invalid or malformed argument JSON strings.
  - Reject output item IDs used in place of call IDs.
  - Fail with client-safe `*core.GatewayError` (Category `invalid_request`) and zero upstream calls.
- Preserve admitted request payload bytes unmodified; keep full history client-supplied without stored response IDs or synthetic continuation.

## Acceptance

- [x] Responses input history containing `function_call` and `function_call_output` items maps to Anthropic Messages `tool_use` and `tool_result` content blocks with intact `call_id` linkage, preserving order across single and multiple call/result pairs and mixed text/tool turns.
- [x] Orphan results, duplicate call IDs, malformed argument JSON, and ambiguous chronology reject before dispatch with `invalid_request` GatewayError; admitted request bytes remain unmodified.
