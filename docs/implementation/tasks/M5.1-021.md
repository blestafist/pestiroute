# M5.1-021 — Build trusted selected-account HTTP headers

## Outcome

Build trusted selected-account HTTP request headers for the Codex Responses profile. Upstream requests authenticate using only runtime-managed OAuth credentials and bound account identity, stripping client-injected auth/account headers and untrusted metadata. One bounded deliverable in the [M5.1 Codex registry](../TASKS.md#m51--codex-subscription-connector), under [ROADMAP M5.1](../ROADMAP.md#m51--agent-protocol-connectors).

## Scope

- Implement Connector-private HTTP request header builder in `internal/connector/codex` (e.g., `transport.go` or `headers.go`).
- Retrieve credentials from `core.InvocationServices.Credentials.Get(ctx, "oauth")`, decode via `decodeOAuthBundle`, and extract the `AccessToken` and `AccountID`. Fail closed if unavailable or bundle is invalid.
- Construct upstream headers for the candidate profile:
  - `Authorization: Bearer <AccessToken>`
  - `ChatGPT-Account-Id: <AccountID>`
  - `Content-Type: application/json`
  - `Accept: text/event-stream`
  - Safe client passthrough: allow propagation of standard trace headers (`Traceparent`, `Tracestate`) and a documented/safe `User-Agent`.
- Header filtering / blocking:
  - Block inbound `Authorization`, `ChatGPT-Account-Id` (and any case-variants, folded keys, or duplicates).
  - Block inbound hop-by-hop headers (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `Proxy-Connection`, `TE`, `Trailer`, `Trailers`, `Transfer-Encoding`, `Upgrade`) and any headers listed in an inbound `Connection` header.
  - Block client auth/session/account headers (`Session-Id`, `Cookie`, `Cookie2`, `OpenAI-Organization`, `OpenAI-Project`, `X-Api-Key`, `X-Codex-*`, `OpenAI-Beta`).
  - Block inbound `Content-Length`, `Content-Type`, `Accept`, `Accept-Encoding`, `Host`.
- Reject/ignore cache-affinity steering: do not derive or synthesize `session-id` from inbound client headers; `prompt_cache_key` in request JSON body remains opaque payload metadata, not routing/account selection authority.
- Retain no references to `core.InvocationServices` or plaintext access tokens/secrets in memory beyond header construction/invocation; diagnostics/errors must never log or format tokens or account secrets.

## Acceptance

- [x] Upstream request headers contain `Authorization: Bearer <token>` and `ChatGPT-Account-Id: <account_id>` strictly from the decoded runtime `oauth` credential bundle; inbound client auth/account headers are stripped.
- [x] Case-folded, duplicate, and spoofed inbound auth/account/session headers (`authorization`, `CHATGPT-ACCOUNT-ID`, `session-id`, `x-codex-*`, `cookie`, `openai-organization`, etc.) and hop-by-hop headers are blocked and cannot steer upstream target or credentials.
- [x] Missing, expired, unparseable, or mismatched credential bundles fail closed with an opaque error without performing network requests.
- [x] Safe trace/agent headers (`traceparent`, `tracestate`, `user-agent`) are preserved while protocol-critical headers (`Content-Type: application/json`, `Accept: text/event-stream`) are enforced.
- [x] No `core.InvocationServices` handles or token secrets are retained beyond invocation, and errors/diagnostics omit bearer tokens and secret materials.

## Completion Evidence

Implemented the Connector-private `buildRequestHeaders` helper. It reads the
runtime-scoped `oauth` credential, decodes and checks expiry/account binding,
generates auth/account/protocol headers, and forwards only bounded safe trace
and user-agent values. Client selectors, auth/session/account fields, protocol
overrides, hop-by-hop fields and `Connection`-nominated headers are omitted.

fixtures and additionally prove that `Connection: traceparent` suppresses
otherwise safe trace passthrough and that control characters in tokens/account
IDs fail closed. No provider/network request is made and no live compatibility
is claimed. The helper does not retain invocation services; transport wiring
is the subsequent M5.1-022 scope, and its returned bearer header exists only
for the caller's upstream invocation.
