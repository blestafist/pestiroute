## Scope

- Implement Authenticate(continue) polling step in `internal/connector/codex`:
  - When `request.Action == "continue"`, verify connector readiness and account scope (`request.AccountID == c.accountID`).
  - Unmarshal opaque `request.State` as connector-private `deviceAuthContinuation`. Reject empty or malformed state with sanitized `*core.GatewayError`.
  - Enrich `deviceAuthContinuation` in `auth_start.go` to retain `UserCode`, `VerificationURI`, and `Interval` so they are available across poll attempts.
  - Enforce session expiry: if current time is at or beyond `ExpiresAt`, fail closed with sanitized error (`auth_expired`); polling never moves or extends the initial runtime expiry.
  - Enforce poll interval: if called before the minimum poll interval has elapsed since the last poll attempt, wait for the remaining interval respecting caller context cancellation, or fail promptly if context expires.
  - Send POST request to `/api/accounts/deviceauth/token` using invocation-scoped `services.Transport` (default base `https://auth.openai.com`, with loopback test URL support), capped at the binding's 30s response-header deadline.
  - Send JSON body `{"device_auth_id":"...","user_code":"..."}` with `Content-Type: application/json`.
  - Refuse redirects fail-closed via `doAuthNoRedirect`; direct RoundTrip execution ensures no redirect is followed.
  - Read provider response with bounded limit (64 KiB).
  - Handle provider responses:
    - HTTP 200 with `authorization_pending`: return `core.AuthResult{Supported: true, NextAction: "continue", State: <continuation with updated LastPolledAt>, UserAction: &core.AuthUserAction{VerificationURI: ..., UserCode: ..., PollInterval: ...}}` without extending `ExpiresAt`.
    - HTTP 200 with `slow_down`: parse increased interval (clamp to minimum 1s), return `NextAction: "continue"` with updated interval in `UserAction` and continuation state, retaining original `ExpiresAt`.
    - HTTP 403 or 404: treated as pending during polling per research/fixtures; return `NextAction: "continue"` with existing `UserAction` projection and unchanged `ExpiresAt`.
    - HTTP 200 with `authorization_code` and `code_verifier` (`poll-authorized.json`): authorized transition! Return `core.AuthResult{Supported: true, NextAction: "continue", State: <marshaled authorized continuation containing code and verifier>, UserAction: nil}`. Candidate credentials remain nil.
    - Terminal errors (non-200 except 403/404, unexpected error responses, malformed JSON, oversized response, or caller context cancellation): fail closed with sanitized `*core.GatewayError` and discard continuation state; never leak codes or secrets into errors or logs.
- Implement comprehensive unit tests in `internal/connector/codex/auth_test.go`:
  - Primary check `TestDeviceAuthPollExchange`: verify continue polling against mock HTTP server returning `poll-pending.json`, `poll-pending-403.json`, `poll-pending-404.json`, `poll-slow-down.json`, and `poll-authorized.json`.
  - Expiry enforcement: expired session state returns error and does not invoke transport.
  - Interval / timing: early poll waits until interval elapses; cancellation during wait returns prompt error.
  - Scope/lifecycle: unready connector state or mismatched `AccountID` rejects before transport.
  - Fail-closed error handling: terminal HTTP status, redirect refusal, malformed payload, and context cancellation return sanitized errors.
- Explicit limits:
  - Do NOT implement token exchange `/oauth/token` (belongs to M5.1-011).
  - Do NOT implement background infinite polling loops (each invocation executes at most one poll step).
  - Do NOT classify inference 403/404 as pending (strictly isolated to device-auth polling).
  - Do NOT persist credentials or session state to database (belongs to M5.1-013).
  - Local mock server only; no live provider calls.

## Acceptance

- [x] Provider pending responses (HTTP 200 `authorization_pending`, HTTP 403, HTTP 404) return `Supported: true`, `NextAction: "continue"`, safe `UserAction` projection, and retain the original session expiry without extending it.
- [x] Provider `slow_down` response updates the poll interval in `UserAction` without extending the fixed session expiry.
- [x] Early polling before the interval elapses waits until the required interval passes or aborts promptly on context cancellation.
- [x] Success response (`authorization_code` and `code_verifier`) transitions continuation state for the code exchange (`NextAction: "continue"`) with nil `UserAction` and no candidate credentials yet.
- [x] Expired session, transport failure, unexpected non-200 HTTP status, malformed response, or caller cancellation return sanitized `*core.GatewayError` and discard invalid continuation state; redirect targets are not contacted.
