# M10-042 — Implement Antigravity reasoning carrier emission and replay translation

## Outcome

Implement actual connector carrier emission and input replay for Antigravity thought/reasoning signatures using the purpose-separated reasoning codec from M10-041 and the design in DEC-031. Emits encrypted reasoning continuation carriers when clients explicitly supply `include: ["reasoning.encrypted_content"]`, while preserving fail-closed rejection on signed parts without that opt-in. Replays and authenticates inbound reasoning items in multiturn history, reconstructing original Gemini signed parts before provider dispatch with strict scope verification (account, project, model) and zero route fallback on mismatch. Links row in [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [M10 brief](../M10-ANTIGRAVITY.md).

## Scope

- `internal/connector/antigravity/execute.go`:
  - Update `admit` to accept top-level `include: []string` in JSON request body; enforce exact `include: ["reasoning.encrypted_content"]` for reasoning carrier emission; pass include opt-in flag to streaming.
  - Update `translateInput` to accept input `type: "reasoning"` items carrying `encrypted_content`:
    - Open and authenticate carrier using `c.reasoning.open(carrierBytes, scope)`.
    - Validate attempt scope (`AttemptScope.AccountID`, `creds.ProjectID`, `Model`); if mismatch, return fixed safe pre-dispatch `invalid_request` with subtype `continuation_scope_mismatch`, with 0 provider HTTP calls and no alternate route/account fallback.
    - Reconstruct authentic Gemini parts (direct signed thought/text/function-call or adjacent signature-only association) in content turns.
    - Compare visible items (message text, function call arguments/name/id) against sealed content to reject spoofed/tampered client modifications.
    - Enforce 1 MiB aggregate carrier limit per turn.
    - Support resubmission of valid history without single-use cache restrictions.
- `internal/connector/antigravity/stream.go`:
  - Wire `ReasoningCodec` and `includeEncryptedReasoning bool` into `stream`.
  - If `includeEncryptedReasoning` is enabled and `c.reasoning != nil`:
    - Support direct signed parts (`thoughtSignature` on part) and adjacent signature-only parts in the same source-ordered parts array.
    - Seal one bounded carrier per signed source part using `c.reasoning.seal(...)`.
    - Incremental thought summary text and ordinary text deltas arrive before carrier completion.
    - Emit `encrypted_content` strictly on completed reasoning `response.output_item.done` and `response.completed`.
    - Terminate stream as `incomplete` on ambiguous, non-adjacent, or duplicate signatures without fabricating provider inputs.
  - If `includeEncryptedReasoning` is not enabled or `c.reasoning == nil`:
    - Preserve existing fail-closed rejection on signed parts (`errUnsupportedReasoning`).
- Tests:
  - Synthetic offline tests in `internal/connector/antigravity/...` and `cmd/gateway/...` covering emission, replay, opt-in/omission, tampering, scope mismatch, ordering, and zero secret/canary leaks.
- Explicit limits:
  - Zero live provider calls or budget deduction (M10-028 remains blocked).
  - No changes to Core runtime contracts or InvocationServices.

## Acceptance

- [x] Top-level `admit` accepts `include: ["reasoning.encrypted_content"]`; invalid or unknown include values fail closed as `invalid_request`.
- [x] When `include: ["reasoning.encrypted_content"]` is present and codec is configured, stream emits `encrypted_content` on `response.output_item.done` and `response.completed` for signed parts.
- [x] Text and reasoning summary deltas continue to be delivered incrementally before output item completion.
- [x] When `include` does not contain `"reasoning.encrypted_content"`, signed provider parts fail closed with `unsupported_reasoning` and no carrier is emitted.
- [x] Both direct signed parts and adjacent signature-only parts within one ordered candidate parts array are handled correctly; non-adjacent, duplicate, or ambiguous signatures terminate stream as incomplete without fabricating signatures.
- [x] Inbound history containing reasoning items with `encrypted_content` is authenticated and unpacked using the attempt scope (AccountID, ProjectID, Model).
- [x] Scope mismatch (account, project, or model drift) returns fixed pre-dispatch `invalid_request` with subtype `continuation_scope_mismatch`, making zero provider calls and triggering no route fallback.
- [x] Tampered ciphertext, bad nonce, mutated AAD, corrupted plaintext, or visible item mismatch is rejected pre-dispatch without disclosing secrets or canaries.
- [x] Valid history can be resubmitted across multiple turns without single-use rejection.
- [x] Carrier size and aggregate per-turn carrier bytes adhere to the 1 MiB limit.
- [x] Zero live provider calls and zero budget deductions; all tests pass offline under Go race detector.
