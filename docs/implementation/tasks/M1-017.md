# M1-017 — Bounded slow-consumer backpressure

## Outcome

A stalled client cannot make application queues or response buffers grow with total stream size. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-014 cleanup, actual stream/observer buffers, [backpressure](../CONTRACT.md#execution-response-and-streamframe), [test distinction](../TESTING.md#testing-levels).

## Scope

- Verify and enforce bounded read-ahead across Connector, Core and adapter with a large synthetic stream and stalled consumer.
- Add only the fixture controls/instrumentation needed to observe buffer bounds and resume/cancel behavior.
- Stop before general load testing or numerical production budgets; stalled reading is not itself disconnect evidence.

## Acceptance

- [ ] Application buffer/queue capacities are documented and independent of total response length; no unbounded observer/event accumulation.
- [ ] Controlled producer progress eventually stalls under backpressure, allowing for finite OS/HTTP buffers; resumed consumption preserves all bytes.
- [ ] Explicit cancellation while blocked releases all work within the test bound.

## Verification

From root run a deterministic blocked-consumer test and real-socket slow-reader scenario, then `./scripts/check.sh`. Prefer bounded queue/read counters over flaky absolute RSS assertions; record buffer sizes and observation method. Name commands at READY.
