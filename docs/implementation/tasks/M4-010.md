## Scope

- Map profile-specific Messages HTTP rejection/error bodies into generic GatewayError before Head. Limit read bytes and sanitize messages/diagnostics; format admitted Responses client errors rather than leak Messages JSON.
- Separate invalid/auth/permission/throttle/unavailable errors and bounded retry-after data. Safe replay needs positive evidence; HTTP status alone does not supply it.
- Keep the classified Head/Complete policy consistent and make no hidden inference retry or auth refresh.

in `http_error_test.go`. HTTP rejection bodies are drained up to 64 KiB and closed,

boundaries. Read errors are sanitized and bodies closed; cancellation releases a blocked
context-bound body with one observed transport call. Actual `responses.Encode` output is
checked for status, JSON, Retry-After, and absence of provider details. No auth refresh,
automatic replay, or end-to-end Execute/Head lifecycle is claimed; M4-013 owns the
upstream-response-to-stream integration using this classifier.
