# M12-007 — Establish operator design foundation, theme tokens, and shell layout

## Outcome

Establish a restrained, polished operator console visual design foundation and design token system (palette, typography, elevation, spacing, focus indicators, light/dark themes) and update the shared application shell (topbar, navigation, footer, session banner, and login view) without modifying backend API bindings or breaking accessibility attributes. ## Scope

- Refactor `web/src/style.css` to introduce structured CSS variables for light and dark themes:
  - Surface elevation hierarchy: canvas background, card/panel surface, elevated modal surface, subtle nested container backgrounds.
  - Border and divider tokens: subtle hairline dividers, active border accents.
  - Typography scale: system font stack, tabular numeric figures (`font-variant-numeric: tabular-nums`) for metrics/counters, monospace font stack for IDs/hashes/tokens.
  - State and status tokens: distinct tokens for ready/supported (emerald), unsupported/error (rose/crimson), unknown/warning/demo (amber), and active/info (sky/slate).
  - Focus rings: high-contrast 2px focus outlines with offset visible against both light and dark backgrounds.
- Refactor the shared application shell in `web/src/App.tsx`:
  - Persistent header: brand mark, control plane badge, gateway connectivity indicator, theme toggle, and session actions.
  - Sidebar navigation: numbered index / icon accents, clean active state indicators, accessible focus styling.
  - Login view: centered operator console access panel with security notice (in-memory bearer token, no persistence) and demo data toggle.
  - Demo banner: restrained technical warning indicator.
- Explicit limits:
  - Do not modify API routes, DTO structures, or `web/src/api.ts`.
  - Preserve all existing ARIA roles, accessible names, form labels, and test IDs relied upon by `App.test.tsx` and `operator.pw.ts`.
  - Do not redesign the internal content of individual screens (deferred to M12-008 and M12-009).
