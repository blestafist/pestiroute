## Scope

- Exercise the actual translation Connector under configured fallback and multi-candidate topologies:
  - Local non-retryable rejection (e.g. validation error during request translation in `translateRequest`).
  - Conclusively unsent failure if provable vs. ambiguous send (transport failure without proof of not-sent stays `RetryUnknown` / non-retryable; no fallback).
  - HTTP throttle / server rejection (e.g. HTTP 429 and HTTP 500: `classifyHTTPRejection` sets `Retryable: true` with `RetryDisposition: RetryUnknown`, causing `DecideRetry` to deny fallback with `retry_disposition_denied`; exactly one upstream call occurs).
  - Committed SSE stream failure (e.g. provider error event during stream after `FrameHead`: `RetryCommitted` denies fallback; exactly one candidate attempt).
  - Candidate scope isolation (wrong account ID or mismatched model rejected non-retryably).
  - Stateful / unknown affinity boundaries: verify that a translated request with `session_bound: true`, `affinity_known: false`, or `previous_response_id` fails closed before dispatch against multi-candidate routes and executes only on configured singleton routes without candidate cycling.
- Require evidence for any safe classification; if the transport cannot prove not-sent, keep unknown and verify no fallback occurs. Do not manufacture a production safe claim from a scripted error.
- Explicit limits: No speculative client retry, no heuristic replay for HTTP 429/5xx, no session directories, and no cross-account state migration.

## Acceptance

- [x] Provider status/code remains Connector-local; no hidden resend or account switch occurs, discarded attempt resources close once, and stateful/unknown-affinity requests enforce singleton target restrictions.
