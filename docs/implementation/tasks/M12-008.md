## Outcome

Apply the restrained operator console visual system to the primary management surfaces (Overview, Connections, and Keys & Policies) in both live and fixture/demo modes, establishing clear information hierarchy, high-density metric cards, structured data tables, and distinct write-only credential sections while preserving all existing interaction, accessibility, and security behaviors. ## Scope

- Polish `Overview` screen in `web/src/App.tsx` and `web/src/style.css`:
  - Structured KPI metric cards for gateway readiness, enabled accounts, and recent ledger volume, clearly displaying null/unknown distinctly from zero.
  - Component readiness grid with status badges.
  - Recent activity list with status-coded indicator pills linking to Usage; live activity links navigate plainly to View Usage without query parameters because live filter query handling is deferred to M12-011.
- Polish `Connections` screen in `web/src/App.tsx` and `web/src/style.css`:
  - Dense tabular presentation of accounts, connectors, credential expiry, and tri-state capability badges (supported, unsupported, unknown).
  - Distinct "Create account" section with clean input groupings.
  - Write-only credential replacement card with explicit non-echoing password fields and security callouts.
  - Clean presentation of advertised OAuth and manual authentication actions with feedback text.
- Polish `Keys & Policies` screen in `web/src/App.tsx` and `web/src/style.css`:
  - Plain-language policy card with revision badge and rate limit indicators.
  - Virtual keys table with creation/revocation timestamps and danger-styled revocation action triggers.
  - Creation form for restricted keys with revision tracking.
  - Accessible one-time secret reveal dialog with monospace key display, copy button, copy status feedback, and immediate dismissal.
  - Destructive revocation confirmation dialog naming target key.
  - Revision conflict (CAS 409) banner with preserved form inputs and explicit refresh action.
- Explicit limits:
  - Do not alter API request/response handling or field mappings.
  - Maintain strict write-only input hygiene: never cache, echo, or log raw credentials.
  - In live mode, show credential expiry only when returned by the accepted API; otherwise show Unknown. Do not manufacture account metadata.
  - In live mode, recent activity links navigate plainly to View Usage without query parameters; live ledger query filtering and server pagination are deferred to M12-011.
  - Preserve all element accessible labels and roles expected by tests. Updating browser selectors for the new named revoke confirmation is allowed; retain the original revocation/rejected-inference assertions.
  - No confirmation is needed to dismiss a one-time secret.
  - Usage, Routing, and Settings screens are scoped to M12-009; live ledger pagination and filtering are scoped to M12-011.
