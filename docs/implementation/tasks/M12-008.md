# M12-008 — Redesign core operator screens: Overview, Connections, Keys & Policies

## Outcome

Apply the restrained operator console visual system to the primary management surfaces (Overview, Connections, and Keys & Policies) in both live and fixture/demo modes, establishing clear information hierarchy, high-density metric cards, structured data tables, and distinct write-only credential sections while preserving all existing interaction, accessibility, and security behaviors. Tracked in [TASKS](../TASKS.md#m12--webui) under [M12](../ROADMAP.md#m12--webui).

- [M12-007](M12-007.md) (Design tokens and layout shell)

- `web/src/App.test.tsx` (screen assertions, write-only credential fields, one-time secret dialog)

## Scope

- Polish `Overview` screen in `web/src/App.tsx`:
  - Structured KPI metric cards for gateway readiness, enabled accounts, and recent ledger volume, clearly displaying null/unknown distinctly from zero.
  - Component readiness grid with status badges.
  - Recent activity list with status-coded indicator pills linking directly into Usage filters.
- Polish `Connections` screen in `web/src/App.tsx`:
  - Dense tabular presentation of accounts, connectors, credential expiry, and tri-state capability badges (supported, unsupported, unknown).
  - Distinct "Create account" section with clean input groupings.
  - Write-only credential replacement card with explicit non-echoing password fields and security callouts.
  - Clean presentation of advertised OAuth and manual authentication actions with feedback text.
- Polish `Keys & Policies` screen in `web/src/App.tsx`:
  - Plain-language policy card with revision badge and rate limit indicators.
  - Virtual keys table with creation/revocation timestamps and danger-styled revocation action triggers.
  - Creation form for restricted keys with revision tracking.
  - Accessible one-time secret reveal dialog with monospace key display, copy button, copy status feedback, and immediate dismissal.
  - Destructive revocation confirmation dialog naming target key.
  - Revision conflict (CAS 409) banner with preserved form inputs and explicit refresh action.
- Explicit limits:
  - Do not alter API request/response handling or field mappings.
  - Maintain strict write-only input hygiene: never cache, echo, or log raw credentials.
  - Preserve all element accessible labels and roles expected by tests.
  - Usage, Routing, and Settings screens are scoped to M12-009.

## Acceptance

- [ ] Overview renders polished metric cards, component health badges, and recent activity links, strictly distinguishing zero from null/unknown.
- [ ] Connections renders an aligned accounts table, tri-state capability chips, write-only credential form, and advertised OAuth flow triggers.
- [ ] Keys & Policies renders policy details, virtual keys table, CAS conflict banner preserving inputs, and one-time secret modal with focus trapping and copy feedback.
- [ ] Named revocation confirmation modal displays target key identifier and requires explicit confirmation.
- [ ] Existing automated unit and integration tests in `web/src/App.test.tsx` pass without regressions.
