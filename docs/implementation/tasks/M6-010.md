# M6-010 — Implement lifecycle operation bridging

## Outcome

Bridge `core.Component` lifecycle methods (`Descriptor`, `Init`, `Health`, `Capabilities`, and `Close`) on the external Connector proxy over the verified gRPC IPC connection with partial-init failure cleanup. See [registry](../TASKS.md#m6--external-plugin-runtime), [milestone](../ROADMAP.md#m6--external-plugin-runtime) and [binding](../M6-BINDING.md#ownership-topology-versions).

## Scope

- Define `Init`, `Health`, `Capabilities`, and `Close` RPCs on `Connector` service in `internal/ipc/proto/connector.proto` adhering to [M6-BINDING](../M6-BINDING.md#ownership-topology-versions) wire shapes:
  - `Init`: client-streaming `RecordFragment` carrying `ComponentConfig`; gRPC status only (no typed response).
  - `Health`: server-streaming `RecordFragment`, returning one complete fragmented `Health` record.
  - `Capabilities`: bidirectional `RecordFragment`, one fragmented `CapabilityScope` in and one `CapabilityResult` out.
  - `Close`: unary placeholder envelope; fixed gRPC status only, with no typed request/result record.
- Regenerate protobuf code via `protoc` in `internal/ipc/gen/`.
- Implement `core.Component` proxy wrapper in `internal/connector/external/`:
  - `Descriptor() core.Descriptor`: returns cached valid descriptor obtained during handshake.
  - `Init(ctx context.Context, config core.ComponentConfig) error`: streams fragmented config; enforces 30 s default timeout bounded by caller context; on failure marks unavailable and immediately executes partial-init teardown/close on child supervisor.
  - `Health(ctx context.Context) core.Health`: queries child health record; enforces 2 s default timeout bounded by caller context; `HealthUnknown` / `HealthUnavailable` never implies readiness.
  - `Capabilities(ctx context.Context, scope core.CapabilityScope) core.CapabilityResult`: queries capabilities for scope; enforces 2 s default timeout bounded by caller context.
  - `Close(ctx context.Context) error`: stops admission, sends unary Close with 30 s default timeout bounded by caller context, is idempotent, reaps child process group via supervisor, unlinks owned socket, and reports bounded sanitized errors.
- Limits: Component lifecycle bridging only. No `Execute` bridging (M6-017/018), no reverse host services (credentials M6-012, HTTP transport M6-013, logging M6-014), no model enumeration or usage estimation (M6-015), no auth state bridging (M6-016).

## Acceptance

- [x] Implement `core.Component` on the external Connector proxy; `Descriptor()` is accessible pre-Init and matches the validated descriptor.
- [x] `Init` streams complete `ComponentConfig` record under `ipc.MaxGRPCMessageBytes` fragmentation; failure leaves the instance unavailable and triggers supervisor teardown and resource cleanup.
- [x] `Health` returns truthful health states (`ready`, `unavailable`, `unknown`) and sanitized diagnostics; non-ready states never indicate readiness; calls obey 2 s deadline.
- [x] `Capabilities` validates input scope, exchanges fragmented request/response, and accurately returns typed capability states (`supported`, `unsupported`, `unknown`).

- [x] Lifecycle operations enforce bounded timeouts (30 s for Init/Close, 2 s for Health/Capabilities) bounded by caller context.
