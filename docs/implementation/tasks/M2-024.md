## Scope

- Expand `internal/conformance/conformance_test.go` with shared opacity and incremental delivery scenarios executed against both native-loopback and scripted connector factories:
  - Exact payload opacity: arbitrary byte preservation on request and response bodies. Request payloads containing custom whitespace, unknown/unexpected JSON fields, and multi-byte UTF-8 sequences are transmitted verbatim without Gateway/Core normalization or parsing.
  - Opaque response body assembly: chunked streaming frames (across arbitrary frame boundaries, split multi-byte UTF-8 sequences, split JSON/SSE delimiters, and synthetic tool call identifiers) reconstruct exact raw bytes identical to the upstream/scripted source without Gateway/Core decoding or re-encoding.
  - Incremental delivery without buffering: gated multi-step streams deliver the initial body frame(s) to the caller while later steps remain gated/blocked; verify the stream does not buffer the entire response before emitting the first chunk.
  - Observable channel synchronization: synchronization is coordinated via deterministic channel gates and signals (`Gate`, `Waiting`/`Sent`), with zero timing-only thresholds or flaky sleeps.
- Explicit limits:
  - Do not implement stream-contract violation conformance (M2-025), error/usage/no-replay conformance (M2-026), cancellation/partial-close (M2-027), or backpressure (M2-028).
  - Test-only additions under `internal/conformance/`; no changes to `internal/core/` or `internal/connector/` unless fixing conformance assertion coverage.
  - Synthetic and local loopback fixtures only; no live provider credentials or network access.

## Acceptance

- [x] Conformance scenarios execute against both `native-loopback` and `scripted` factories verifying exact byte-level request and response preservation for unknown fields, custom whitespace, and multi-byte UTF-8 sequences.
- [x] Incremental delivery is proven: initial response body frame is received and verified by the caller while subsequent completion/terminal frames remain gated and unreleased.
- [x] Gated streaming and chunk assembly preserve ordering, synthetic tool call IDs, and split multi-byte/delimiter boundaries across frames without drop, mutation, or duplication.
- [x] Conformance runner synchronization uses channel-based gating (`Gate`/`Waiting`/`Sent`) rather than arbitrary sleeps or timing thresholds.
- [x] Deliberate anti-conformance mutations (e.g. byte corruption, whole-response buffering prior to first frame delivery) are rejected by assertion-bearing conformance checks.
