# M10-023 — Implement durable pre-dispatch request budget accounting and provider-neutral HTTP transport wrapper

## Outcome

Implement durable pre-dispatch request budget accounting across all provider HTTP operations (token exchange, project discovery, onboarding, polls, inference, refresh, retries) under [DEC-025](../../project/DECISIONS.md#dec-025--bound-experimental-antigravity-managed-project-onboarding). Persistently enforce a hard ceiling of at most 1000 total new provider HTTP requests for the authorized test account using an atomic, restart-safe SQLite budget store and provider-neutral `core.HTTPDoer` wrapper. Fail closed on exhaustion, missing store, or unconfigured budget for accounts requiring budget; never refund consumed dispatches on timeout, cancellation, restart, or unknown provider outcomes. Keep unbudgeted connectors unaffected. See [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [M10 brief](../M10-ANTIGRAVITY.md).

## Scope

- Persistent SQLite schema & storage:
  - Add schema migration v7 in `internal/storage/sqlite/migrate.go` defining table `operator_request_budgets` (`account_id TEXT PRIMARY KEY`, `ceiling INTEGER NOT NULL CHECK (ceiling >= 0)`, `consumed INTEGER NOT NULL DEFAULT 0 CHECK (consumed >= 0)`, `created_at INTEGER NOT NULL`, `updated_at INTEGER NOT NULL`, `CHECK (consumed <= ceiling)`).
  - Implement atomic reservation (`Reserve(ctx, accountID) error`) using `BEGIN IMMEDIATE` / atomic UPDATE in `internal/storage/sqlite/`.
- Provider-neutral transport wrapper:
  - Implement `BudgetedHTTPDoer` wrapping `core.HTTPDoer` before dispatch across all operations.
  - Fail closed on budget exhaustion or store error with sanitized `request_budget_exceeded` error before any network handoff.
  - Strict zero-refund invariant: errors, cancellations, timeouts, and unknown outcomes remain permanently consumed.
- Transport composition & gateway wiring:
  - Wire budgeted doer in `cmd/gateway/admin_auth.go` and `cmd/gateway/main.go` for budgeted accounts. Unbudgeted accounts/connectors operate unaffected.
  - Antigravity connector compatibility: ensure `Execute` and `Authenticate` accept the budgeted transport when real transport is enabled.
- Synthetic-only test suite:
  - Migration idempotency, concurrent multi-goroutine and restart-simulated reservation race tests.
  - Non-refund verification on errored/cancelled calls and fail-closed exhaustion tests.
  - Existing DB protection invariant: tests use synthetic in-memory or synthetic temp databases only; zero reading of actual credential contents.
  - Define budget baseline: prior new live count is 0; public source fetches and test fakes do not count towards the 1000 ceiling.
- Explicit limits:
  - No live network requests or external provider calls.
  - Does NOT implement the onboarding POST/polling state machine (reserved for M10-024).
  - Does NOT expand the ceiling above 1000.

## Acceptance

- [x] Schema migration v7 creates persistent `operator_request_budgets` with non-negative constraints and check constraint `consumed <= ceiling`.
- [x] Atomic reservation operates under cross-process serialization (`BEGIN IMMEDIATE` / atomic UPDATE); concurrent workers cannot exceed the configured ceiling.
- [x] Provider-neutral `core.HTTPDoer` wrapper atomically reserves 1 request before each `Do` call across all operations (auth exchange, project discovery, onboarding, polling, inference, refresh, retries).
- [x] Exhaustion or reservation failure fails closed with safe diagnostic code `request_budget_exceeded`; no provider request is dispatched.
- [x] Non-refund invariant verified: errored, cancelled, timed-out, or ambiguous HTTP dispatches remain permanently consumed in persistent storage.
