# M3-010 — Persist encrypted credentials with revision checks

## Scope

- Implement a pure Go SQLite encrypted credential repository in `internal/storage/sqlite` (e.g. `credentials.go` and `credentials_test.go`), keeping SQL persistence outside of Core.
- Model `Credential` record matching schema v2 columns: `ID`, `AccountID`, `FormatVersion`, `KeyVersion`, `Nonce`, `Ciphertext`, `ExpiresAt *time.Time`, `Revision int64`, `CreatedAt time.Time`, `UpdatedAt time.Time`. Slice fields must be defensively copied to guarantee immutable read results.
- Implement credential repository operations:
  - Create: insert new credential envelope into `credentials` table with initial `revision = 1` and timestamps as integer UTC Unix milliseconds (`INTEGER NOT NULL`). Enforces foreign key constraint to `accounts(id)`.
  - Get / GetDecrypted: query credential by `(account_id, id)`. Authenticate and decrypt secret payload using `crypto.MasterKey` and bound AAD (purpose `"credentials"`, recordID `id`, accountID `account_id`, formatVersion `1`).
  - Update with optimistic revision check: compare-and-swap update on `(id, account_id, expected_revision)`. Atomically increments `revision = revision + 1` and updates `updated_at` (UTC Unix ms). Returns typed `ErrRevisionMismatch` (or `ErrNotFound`) if the expected revision does not match the persisted revision, leaving data untouched.
  - Multi-credential atomic updates: support transactional multi-value credential replacement that rolls back completely if any revision check or constraint fails, preserving the prior complete set.
- Use short transactions via `*sql.DB` opened with `sqlite.Open` (WAL, `synchronous=FULL`, foreign keys ON, 500 ms busy timeout). No network calls inside transactions.
- Explicit limits: Account lifecycle management belongs to M3-011; CLI commands belong to M3-014/M3-015; supplying credentials to invocations belongs to M3-017; auth sessions belong to M3-034; Core imports remain standard-library only.

## Acceptance

- [x] Creating and reading/decrypting a credential with the valid external master key recovers original plaintext bytes; credentials survive `db.Close()` and reopen with `sqlite.Open`.
- [x] Optimistic revision check succeeds on matching `expected_revision`, incrementing `revision` by 1 and updating `updated_at`; stale or mismatched revision fails with typed `ErrRevisionMismatch` without modifying stored data.
- [x] Competing updates or multi-value credential replacement inside a transaction roll back atomically on any failure, leaving the complete pre-existing credential set.
- [x] Referential integrity is enforced: inserting a credential for a nonexistent `account_id` fails foreign key constraints (`ON DELETE RESTRICT`).
- [x] Wrong master key, corrupted ciphertext, altered nonce, or mismatched AAD (format version, purpose, credential ID, account ID) fails safely returning crypto errors without plaintext leakage.
- [x] Zero plaintext leakage: raw SQLite database file and WAL inspection confirms absence of synthetic secret tokens; errors and string representations do not disclose plaintext or master key material.
- [x] Defensive immutability: read results return immutable copies of slice fields (`Nonce`, `Ciphertext`, decrypted plaintext) so caller mutations cannot alter repository state.
