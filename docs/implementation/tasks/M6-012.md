# M6-012 — Bridge selected credential access

## Outcome

Bridge `core.CredentialAccess` over IPC so external child connectors can request named credentials scoped strictly to the host-recorded invocation and account, rejecting cross-account, expired, or post-close access. See [registry](../TASKS.md#m6--external-plugin-runtime), [milestone](../ROADMAP.md#m6--external-plugin-runtime) and [binding](../M6-BINDING.md#reverse-services-and-authority).

## Scope

- Host-services proto definition and code generation for reverse `CredentialGet` RPC under [M6-BINDING](../M6-BINDING.md#wire-value-mapping).
- Host-side reverse service handler on `hostServices` Unix socket:
  - Validates `RecordFragment` headers (epoch, invocation ID, monotonic call ID).
  - Uses `invocationRegistry.admitCallback` to correlate authority; child data cannot select account.
  - Reassembles `CredentialLookup`, delegates to invocation's `CredentialAccess.Get(ctx, name)`.
  - Enforces 2 s lookup timeout bounded by invocation context.
  - Fragments and returns `CredentialValue` or sanitized denial.
  - Releases callback lease on finish; drops late results on cancellation or revocation.
- Child-side `core.CredentialAccess` client adapter wrapping `CredentialGet`.
- Limits: Credential reverse service only. No HTTP reverse service (M6-013), logging (M6-014), models/usage (M6-015), auth state (M6-016), or Execute bridging (M6-017).

## Acceptance

- [x] Named credential lookup over IPC returns exact credential bytes for host-selected account associated with live invocation.
- [x] Child cannot access credentials across accounts; authority derives strictly from host invocation record.
- [x] Enforces 2 s lookup timeout bounded by parent context and obeys 8/32 callback limits.
- [x] Fails closed and denies access on stale epoch, unknown/revoked invocation ID, duplicate/stale call ID, cancelled context, or post-close child state.

## Completion Evidence

`CredentialGet` is served on the verified host-services Unix socket. The host derives the scoped `CredentialAccess` from its invocation record; the request carries only a name, epoch, host-issued invocation ID and process-unique monotonic call ID. Both typed records use the common fragment codec, preserving credential bytes. Each request is capped at 2 s and parent cancellation; leases release on completion and revocation drops late results. Connector close stops the host service and revokes all active invocations. Child access is an invocation-bound `core.CredentialAccess` adapter.

Race tests cover exact opaque bytes across accounts and fragment boundaries, parent-context expiry/cancellation, stale epoch/unknown/revoked/post-close and duplicate-call denial, out-of-order unique IDs `2,1` followed by rejection of both duplicates, the 2 s lookup timeout, and full 8/32 callback admission. The fixed 32-ID sliding replay window's high-water mark is advanced only by `rememberCallID`, supports reordered RPC arrival with constant memory, and rejects older unseen IDs as stale. The handler returns a fixed sanitized denial and never accepts an account selector. A transport test proves an oversized gRPC message is rejected with `ResourceExhausted`; host-services server receive/send message limits both match the binding's 84 KiB wire-frame ceiling (including gRPC prefix accounting).
