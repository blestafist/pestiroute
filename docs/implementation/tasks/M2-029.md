# M2-029 — Verify routed runtime failures with scripted Connectors

## Outcome

Routing behavior is proven by predictable successes and failures rather than only HTTP passthrough. Core dispatch, route matching, eligibility gating, and failure commit accounting are verified across distinct instances without fallbacks. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Add targeted integration tests (e.g. in `internal/core/routed_failures_test.go` or `internal/core/dispatch_routed_test.go`) configuring a `Registry`, `RouteTable`, `Services`, `Observations`, and `Dispatcher` with at least two scripted Connector instances/accounts and distinct model routes.
- Exercise explicit scenarios:
  - Route selection: exact opaque payload, model, and runtime-generated trusted IDs (`ExecutionRequest.ID`, `AttemptScope.ID`, `AccountID`, `Mode`) reach the designated connector instance without alteration.
  - No matching route: unknown model / unconfigured lookup fails with typed code `unsupported_target` and category `unsupported_feature` `GatewayError`, invoking zero connector executions.
  - Unavailable instance: missing or unregistered connector component fails route resolution prior to `Execute()`.
  - Capability gating: client request requiring an unsupported or unknown capability fails admission prior to connector execution with typed code `unsupported_capability` and category `unsupported_feature` `GatewayError` (zero connector calls).
  - Scope / policy mismatch: incompatible protocol or mode is rejected before any connector `Execute()`.
  - Pre-Head failure: scripted connector returns an `ExecuteError` before stream creation; Dispatcher finalizes the attempt as failed, uncommitted (`Committed == false`), retry-eligible per error definition; proves zero alternate fallback calls.
  - Post-Head failure: scripted connector yields a `Head` frame followed by a stream error; Dispatcher finalizes the attempt as incomplete, committed (`Committed == true`), non-retryable; proves zero alternate fallback calls.
  - Route isolation: failure on one route leaves independent healthy routes functional; an immediate subsequent request to another route succeeds cleanly with isolated attempt observations.
- Explicit limits:
  - Do not implement multi-target fallback or retry loops (strictly M3 scope).
  - Do not implement session portability or stateful migration across accounts/models.
  - Deterministic synthetic fixtures only (using `internal/testutil/scripted`); no live provider credentials or external networks.

## Acceptance

- [x] Opaque request payload, model, and runtime-generated trusted IDs (`ExecutionRequest.ID`, `AttemptScope.ID`, `AccountID`, `Mode`) reach the selected scripted instance/account verbatim.
- [x] Requests with unroutable model, missing registered component, or unknown/unsupported mandatory capabilities fail before any connector `Execute()` is invoked (recorded calls count = 0).
- [x] Pre-Head failure records an uncommitted attempt failure (`Outcome: failed`, `Committed: false`), and post-Head stream interruption records a committed incomplete attempt (`Outcome: incomplete`, `Committed: true`) per CONTRACT.md §Execution Response; neither scenario attempts fallback to another route or connector instance.
- [x] A healthy independent route executed immediately after a failed attempt completes successfully with isolated attempt observation records and unmodified state.
- [x] All failure GatewayErrors preserve typed codes, categories, and retry flags without panics or goroutine leaks.
