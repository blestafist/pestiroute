# M1-013 — Client-visible incremental flush

## Outcome

A real client receives the first SSE event while the upstream remains blocked on its next step. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

## Scope

- Wire streaming preference (`stream: true` / `llm.streaming`) into the gateway execution target to invoke `ExecuteSSE`.
- Flush HTTP output incrementally via `http.Flusher` on `core.FrameBody` in the adapter encoder.
- Add real-socket two-gated-event regression test in `cmd/gateway/main_test.go` verifying first event reaches client before upstream second gate opens.
- Stop before cancellation/disconnect handling ([M1-014](M1-014.md)), slow-client backpressure ([M1-017](M1-017.md)), or split-boundary fixtures ([M1-002](M1-002.md)).
