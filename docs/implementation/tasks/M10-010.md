## Scope

- In `docs/implementation/M10-BINDING.md`:
  - Update binding under explicit user authority: establish that the earlier fake-only restriction was a boundary for the initial minimal vertical slice (M10-004), not a permanent contract limitation.
  - Define pinned community-source candidate endpoint shape (`https://cloudcode-pa.googleapis.com`, streaming action path `/v1internal:streamGenerateContent?alt=sse`, with uncertainty noted vs synthetic `/v1internal/projects/{project}:generateContent?alt=sse`) and explicit opt-in standard HTTP transport alongside deterministic test transport. Do not present it as official Google evidence.
  - Preserve remote/provider capability Unknown ceilings and zero-live-provider-testing guarantees; `llm.streaming` is supported only as the exact locally implemented/deterministically tested translation scope. No core CONTRACT change or ADR is needed.
- In `internal/connector/antigravity`:
  - Extend connector configuration to support optional `endpoint` (default production `https://cloudcode-pa.googleapis.com`; supports `PESTIROUTE_ANTIGRAVITY_ENDPOINT` override). When using standard endpoints, target `/v1internal:streamGenerateContent?alt=sse`; preserve `/v1internal/projects/{project}:generateContent?alt=sse` when targeting `antigravity.synthetic.invalid` for fixture backwards compatibility.
  - In `Execute`: permit only the connector-owned redirect-disabled HTTP client when explicitly enabled (e.g. `PESTIROUTE_ANTIGRAVITY_REAL_TRANSPORT=1`), alongside existing deterministic `offlineTestTransport`. An arbitrary injected `HTTPDoer` is never an opt-in seam. Reject ambient network egress with `unavailable`.
  - In `Execute`: admit candidate function tool declarations from `openai.responses.v1` (`tools` array with `type: function`, mapping `parameters` to candidate Gemini `tools: [{functionDeclarations: [...]}]`) with an explicit recursively validated JSON Schema keyword subset; reject unchecked/malformed nested constraints.
  - Fail closed on unsupported tool features per `M10-TOOL-BINDING.md`: reject unsupported `tool_choice` modes and signature-dependent multi-turn continuations before dispatch with `unsupported_feature` or `invalid_request`.
  - In `Capabilities`: report `llm.streaming: Supported` specifically for the implemented and deterministically verified scope (`scope.Protocol == "openai.responses.v1"` and `scope.Mode == core.ModeTranslation`). This is a local implementation-scope statement, not remote entitlement/provider support. Provider authentication (`auth.oauth`), exact usage (`usage.exact`), and other unverified capabilities remain `Unknown`.
  - In `stream.go`: accept synthetic `response.done: true`, or candidate `finishReason: STOP`, optionally followed by one usage-only frame, then clean EOF. After STOP reject candidate content and conflicting finishes; after usage reject further events. Usage alone is not terminal evidence. Detect truncation/mid-frame EOF; reject `thoughtSignature` or `thought: true` parts before emitting any content from that frame. Generate distinct per-execution Responses/message IDs.
  - Add unit tests for configurable endpoints, real transport opt-in rejection/acceptance, tool declaration mapping, capability reporting, stream terminal policy with truncation detection, and reasoning exclusion.
- In `cmd/gateway` (under user-granted serialized gateway edit window):
  - In `yaml_config.go`: allow connector implementation `"pestiroute.antigravity.v1internal"`, validate required settings (`project`, `model`, `account_id`, optional `endpoint`), and allow route target matching in translation mode.
  - In `protected_startup.go`: map `"pestiroute.antigravity.v1internal"` connector and configure component limits/timeouts.
  - In `main.go`: instantiate `antigravity.NewConnector()` when registering connectors for protected runtime.
  - In `cmd/gateway`: add end-to-end test verifying YAML loading, protected route startup, and `/v1/responses` execution through the unwrapped real connector and its connector-owned HTTP client against a controlled local TLS upstream. Prove first content reaches the client before terminal release, then prove downstream cancellation cancels upstream. Do not mask connector capabilities.
- Explicit limits:
  - Zero live provider/external-network calls in automated checks; a controlled loopback TLS upstream is permitted for end-to-end transport/stream lifecycle verification.
  - No signature-dependent multi-turn replay (remains BLOCKED per M10-006).
