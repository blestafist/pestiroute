## Scope

- Wire `POST /v1/chat/completions`, the new adapter and compatible Connector at
  the composition root. Add explicit route/config validation and protected admin
  provisioning as required by the binding, reusing existing generic policies.
- Prefer Chat-specific files; agree ownership of shared gateway/config edits with
  M8 before writing. Keep the Claude connector's gate unchanged.
- Add protected client-to-loopback JSON/SSE tests with a synthetic key/account,
  denial-before-dispatch, protocol mismatch, limits, cancellation and accounting.
- Do not alter Core to parse Chat bodies, create a parallel usage path, promote
  live capabilities, or implement additional provider translation.

## Acceptance

- [ ] Explicitly configured native Chat routes work; wrong-protocol routes and
  unknown implementations fail startup/eligibility without upstream dispatch.
- [ ] Revoked/disallowed keys and exhausted limits never reach the backend.
- [ ] Early SSE, disconnect cancellation, complete/incomplete usage, reservations,
  and once-only finalization follow existing protected runtime guarantees.
- [ ] Existing Responses routes and Claude default rejection retain regression coverage.
