## Scope

- Wire `POST /v1/chat/completions`, `internal/adapter/chatcompletions` (descriptor
  `pestiroute.chat-completions.native`), and `internal/connector/chatcompletions`
  (descriptor `pestiroute.chat-completions.native`) at the composition root.
- Add YAML configuration parsing and startup validation for Chat connectors and
  routes per [M9-BINDING.md#protected-yaml-and-admin-behavior](../M9-BINDING.md#protected-yaml-and-admin-behavior):
  - Connector implementation `pestiroute.chat-completions.native`, protocol `openai.chat-completions.v1`.
  - Base URL validation: absolute URL, scheme `https` (or `http` on loopback host), escaped path ending in `/v1/chat/completions`.
  - Native settings only (disallow `process`, `model`, `account_id`, `credential_id`, or Responses-specific settings).
  - Route validation: protocol `openai.chat-completions.v1`, mode `native`, adapter `pestiroute.chat-completions.native`.
  - Startup fails on protocol mismatch, missing adapter/connector, or cross-protocol target mixing.
- Register `POST /v1/chat/completions` HTTP handler alongside `POST /v1/responses`
  in `cmd/gateway`, dispatching requests via the existing Core Dispatcher keyed by
  protocol and model, reusing virtual-key authentication, policy authorization,
  reservations, limits, and SQLite accounting without parallel code paths.
- Add protected client-to-fake-backend tests in `cmd/gateway/chat_protected_test.go`
  exercising JSON, SSE, authentication, pre-dispatch denial, route isolation,
  cancellation, and token accounting settlement.
- Named exclusive sequencing ownership: this task owns edits to `cmd/gateway/main.go`,
  `cmd/gateway/yaml_config.go`, and `cmd/gateway/protected_startup.go`. Keep Claude
  connector default rejection and Responses routes unchanged.
- Boundaries: Do not alter Core to parse Chat bodies, add universal message types,
  promote live capabilities, add CLI/UI features, or implement cross-protocol
  translation.

## Acceptance

- [x] Startup topology and YAML validation admit `pestiroute.chat-completions.native`
  connectors and `openai.chat-completions.v1` routes; reject invalid base URLs (not
  ending in `/v1/chat/completions`), process configurations, wrong protocols, or
  cross-protocol route targets.
- [x] Protected `POST /v1/chat/completions` serves valid JSON and incremental SSE
  responses from a fake backend using synthetic SQLite keys/accounts, preserving
  raw request/response bytes and headers verbatim.
- [x] Denials before dispatch: requests with missing API key, invalid key, revoked key,
  unauthorized model, or exhausted limits (RPM/TPM) fail with standard error responses
  and never reach the backend connector.
- [x] Route isolation: configured paths dispatch only to their configured
  protocol-specific connector; unconfigured models return `unsupported_target`.
  Isolation is path/protocol selection, not payload-shape inspection: the Responses
  Adapter does not reject Chat-shaped opaque JSON merely because its schema resembles
  Chat, and neither Adapter validates a foreign protocol schema.
- [x] Accounting and lifecycle: valid token usage is settled exactly once in SQLite
  accounting; missing usage is left unknown; client disconnect cancels fake-upstream
  IO and records cancelled attempt.
- [x] Regressions remain clean: existing Responses native, translation, Codex, and local
  runtime test suites in `cmd/gateway` pass unchanged.
