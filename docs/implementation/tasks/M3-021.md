# M3-021 — Persist request and attempt lifecycle records

## Outcome

Durable SQLite persistence for requests, attempts, and usage records matching schema v4 from [M3-008](M3-008.md), providing authoritative lifecycle state and terminal usage recording without payload or secret leakage. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Read First

- [Request and Attempt Schema](M3-008.md) and schema v4 in `internal/storage/sqlite/migrate.go`.
- [Ledger lifecycle and recovery](../M3-STORAGE.md#lifecycle-and-recovery).
- [Attempt lifecycle](../M3-RUNTIME.md#request-admission-and-limits) and [Execution Contract](../CONTRACT.md#execution-response-and-streamframe).
- Existing repository conventions in `internal/storage/sqlite/{accounts,keys,policies}.go`.

## Scope

- In `internal/storage/sqlite`, define request, attempt, and usage repository structures and methods for `requests`, `attempts`, and `usage_records` tables.
- Support creating admitted requests, creating attempts with route/budget metadata, transitioning attempt state (e.g. `intent`, terminal status), and recording terminal sanitized usage records.
- Preserve nullable token counts (`input_tokens`, `output_tokens`, `reasoning_tokens`, `cached_tokens`), ensuring unmeasured fields remain `NULL`.
- Ensure idempotency: repeated identical terminal operations succeed cleanly; conflicting terminal writes return explicit conflict errors.
- Enforce foreign keys and check constraints with typed sentinel errors (e.g., not found, conflict).
- Explicit limits: admission window arithmetic belongs to [M3-022](M3-022.md); token estimation belongs to [M3-023](M3-023.md); atomic admission with reservation holding belongs to [M3-024](M3-024.md); reservation settlement belongs to [M3-026](M3-026.md); dispatch wiring belongs to [M3-027](M3-027.md). Do not persist request/response payload bodies, provider headers, or secrets.

## Acceptance

- [x] Inserting requests and attempts persists required metadata, foreign keys (`virtual_key_id`, `policy_id`/`policy_revision`, `account_id`), and integer timestamps.
- [x] Duplicate begin or identical finalize operations cannot create duplicate requests, attempts, or usage records.
- [x] Conflicting repeated terminal transitions return an explicit conflict error rather than silently overwriting the committed record.
- [x] Usage records preserve nullable token counts (`NULL` in SQL, nil in Go) and recorded timestamps without data loss.
- [x] Terminal attempt writes persist the commit flag and sanitized `error_category` / `error_reason` metadata defined by schema v4.
- [x] SQL failures and constraint violations return clear wrapped errors; no payload, secret, or provider error body is persisted.
- [x] Persisted request, attempt, and usage records round-trip accurately across file-backed connection close and reopen.
