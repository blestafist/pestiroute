## Scope

- Implement a Connector-private Responses SSE event emitter / lifecycle state machine in `internal/connector/anthropic` formatting standard SSE frames (`event: <type>\ndata: <json>\n\n`).
- Implement the exact plain-text event sequence for Anthropic translation:
  - Initial lifecycle: generate distinct client `response_id` (prefixed `resp_`) and text output item `id` (prefixed `msg_`); emit `response.created` and `response.in_progress` (carrying `response_id` and `status: "in_progress"`), followed by `response.output_item.added` (output_index 0, item type `message`, item `id`), and `response.content_part.added` (output_index 0, `item_id`).
  - Streaming deltas: emit `response.output_text.delta` (output_index 0, `item_id`, delta `text`) promptly in order without holding deltas for the final body.
  - Text block completion: emit `response.output_text.done` (output_index 0, `item_id`, text snapshot), `response.content_part.done` (output_index 0, `item_id`, part snapshot), `response.output_item.done` (output_index 0, item snapshot with role `"assistant"`, status `"completed"`, content array with empty annotations/logprobs).
  - Terminal completion: emit exactly one terminal event: `response.completed` (status `"completed"`, `output_items` snapshot, usage) on normal stop (`end_turn` or `stop_sequence`), or `response.incomplete` (status `"incomplete"`, `incomplete_details: {"reason":"max_output_tokens"}`, `output_items` snapshot, usage) on `max_tokens` truncation stop.
- Enforce the 1 MiB cumulative retained text ceiling from the binding for final snapshots; abort with an explicit error if exceeded.
- Enforce strict lifecycle ordering: prevent duplicate terminal/output closure, out-of-order event emission, or post-closure event generation. Emitted byte slices must be immutable on handoff.
- Do not connect to HTTP Execute or SSE reader (deferred to M4-013), do not introduce tool or reasoning event types, and do not modify Core or Adapter.

## Acceptance

- [x] Emitted byte frames format as valid SSE (`event: <type>\ndata: <json>\n\n`) and decode to the expected Responses JSON schema: distinct non-empty `resp_` and `msg_` IDs, consistent output_index (0) and item_id references.
- [x] Normal lifecycle emits the full ordered sequence: `response.created` -> `response.in_progress` -> `response.output_item.added` -> `response.content_part.added` -> `response.output_text.delta`* -> `response.output_text.done` -> `response.content_part.done` -> `response.output_item.done` -> `response.completed`.
- [x] Truncation lifecycle (`max_tokens`) emits snapshots with `response.incomplete` and `incomplete_details.reason: "max_output_tokens"`.
- [x] Cumulative retained text up to 1 MiB is accumulated for done/completed snapshots while deltas stream immediately; exceeding 1 MiB returns an error and suppresses further events.
- [x] State machine rejects duplicate terminal calls, out-of-order calls, or calls after termination; no duplicate terminal events or ID reuse across executions.
- [x] Handed-off byte slices are independent and immutable.
