# M10-020 — Implement bounded Google OAuth callback metadata parsing and safe callback diagnostics

## Outcome

Delivers connector-private bounded parsing of standard Google OAuth callback URL parameters (`scope`, `authuser`, `prompt`, `hd`) in the Antigravity connector, introduces fine-grained secret-safe callback diagnostic reason codes, and provides safe input classification feedback during operator paste. This resolves pre-exchange `invalid_auth_callback` rejections caused by DEC-019's two-key limit when users paste valid Google OAuth redirect URLs, while preserving byte-exact redirect URI checks, single-use state matching, and zero secret leakage. See [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [M10 brief](../M10-ANTIGRAVITY.md).

## Owning ADR: DEC-023

- **Status:** Accepted by planner resolution for M10-020 on 2026-10-21; offline candidate authorization and specification synchronization.
- **Context:** Operator error was reported with cause UNKNOWN; independently, synthetic query probes confirmed the two-key rule rejects known Google metadata. RFC 6749 §4.1.2 directs clients to ignore unrecognized response parameters; it does not establish these four keys as universally present or their Antigravity-specific semantics.
- **Decision:** Amend CONTRACT.md callback-URL rules: allow Connectors to explicitly declare an allowlist of bounded, non-sensitive provider query keys (for Antigravity: `scope`, `authuser`, `prompt`, `hd`) while rejecting undeclared keys. The generic runtime remains provider-agnostic and forwards `CallbackInput` unparsed; Claude Code remains strict `code`/`state`. The Connector must still enforce:
  1. Byte-exact scheme, authority, and escaped path matching against the stored session `RedirectURI`.
  2. Rejection of fragments (`#`), userinfo, control chars, and malformed encoding.
  3. Exactly one non-empty `code` and one `state`, rejecting duplicate keys.
  4. Byte-for-byte `state` equality before exchange.
  5. Immediate rejection on OAuth `error` parameters.
  6. Zero reading, logging, or storage of token/credential values from the URL.
  Connector callback validation reports distinct safe diagnostic error codes (`callback_malformed`, `callback_redirect_mismatch`, `callback_query_keys`, `callback_state_mismatch`, `callback_error_param`). Terminal feedback may safely display input classification (`callback_url` vs `raw_code`) and length only, never content.
- **Alternatives rejected:** Blindly ignoring all query parameters (violates defense against parameter injection and token leakage in URL); universal URL rewriting/normalization in Core (violates Core neutrality); forcing raw-code manual paste only (fails when users paste redirect URLs).
- **Compatibility / impact:** Connector-private Antigravity compatibility extension only; Core diagnostic allowlist updated with provider-neutral codes; runtime execution, IPC, and Claude Code unchanged. No general URL normalization or claim about Google callback guarantees.
- **Verification:** Unit and gateway race tests verify allowed Google query keys, duplicate parameter rejection, undeclared parameter rejection, error response rejection, state mismatch rejection, safe diagnostic reason mapping, and input classification without secret leakage. Zero live provider calls.

## Scope

- Documentation:
  - Record DEC-023 in `docs/project/DECISIONS.md` and synchronize `docs/implementation/CONTRACT.md`, `M10-AUTH-BINDING.md`, and `LOCAL-M10.md` to reflect bounded provider callback query keys.
- Connector (`internal/connector/antigravity/auth.go`):
  - In URL callback parser, replace the strict `len(values) != 2` check with bounded validation permitting declared Google metadata keys (`scope`, `authuser`, `prompt`, `hd`) alongside mandatory single `code` and `state`.
  - Reject duplicate occurrences of any allowed parameter (`len(values[k]) != 1`).
  - Reject any undeclared query parameter fail-closed.
  - Return actionable provider-agnostic error codes distinguishing failure categories: `callback_malformed`, `callback_redirect_mismatch`, `callback_query_keys`, `callback_state_mismatch`, `callback_error_param`.
  - Retain byte-exact scheme, host/port, and escaped path matching against continuation `RedirectURI`; reject userinfo, fragments, and control characters.
  - Never read, store, or log query parameter values or tokens.
- CLI / Admin UX (`cmd/gateway/admin_auth.go`):
  - When reading hidden stdin paste, report non-sensitive input classification (`kind` such as `callback_url` vs `raw_code`, and byte `length`) under `--debug` without echoing or logging input characters.
  - Format new granular callback error codes clearly.
- Tests:
  - `internal/connector/antigravity/auth_test.go`: test URL callbacks with combinations of `scope`, `authuser`, `prompt`, `hd`; test rejection of duplicate keys, undeclared keys, malformed escaping, fragments, redirect mismatch, state mismatch, and OAuth error params (`error=access_denied`).
  - `cmd/gateway/admin_auth_test.go`: test `--debug` output formatting and input classification without leaking tokens, codes, state, or URL query contents.
- Explicit limits:
  - No live network requests or external provider calls.
  - No relaxation of byte-exact redirect URI matching or state equality.
  - Core provider-neutral diagnostic allowlist extended; no Core payload parsing, provider branching, schema, IPC, or Claude Code behavior change.
  - No token/credential/ID reading from URL parameters.
