# M10-018 — Implement secret-safe auth diagnostics and align token/discovery parsers with Google OAuth specifications

## Outcome

Delivers secret-safe stage/reason/status diagnostics for administrative auth failure reporting (`admin auth --debug`) and aligns offline Antigravity token exchange and discovery response parsing with documented OAuth 2.0 (RFC 6749 §5.1) and Google OAuth token endpoint norms. This fixes the generic `admin: authentication unsupported or unavailable` collapse, allows normative Google response fields (`scope`, `id_token`) while strictly validating required credentials without speculative relaxation, and enables deterministic reproduction without live provider calls or sensitive operator inputs. See row in [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and milestone in [ROADMAP.md](../ROADMAP.md#m10--google-antigravity-connector).

## Scope

- In `internal/connector/antigravity/auth.go`:
  - Update `exchangeAuthCode` and `authenticateRefresh` token JSON parsers to permit documented normative OAuth 2.0 / Google token endpoint fields (`scope`, `id_token`) alongside `access_token`, `expires_in`, `token_type`, and `refresh_token`.
  - Maintain strict validation for required fields: non-empty `access_token`, valid `token_type`, positive bounded `expires_in`, unique JSON keys, control-character rejection, and fail-closed parsing. Do not store `scope` or `id_token` in the persisted credential bundle.
  - Return provider-agnostic `GatewayError` codes recognized by Core's `safeAuthDiagnosticCode` (`auth_invalid_response`, `auth_rejected`, `auth_transport_unavailable`, `auth_request_failed`, `auth_rate_limited`, `auth_invalid_state`).
  - Attach sanitized `HTTP status %03d` to `OriginalError` on non-200 HTTP responses in both token exchange and `discoverProject`.
  - In `discoverProject`, handle candidate project representations from pinned sources, reporting distinct sanitized error codes and HTTP statuses on failure.
- In `internal/core/auth_coordinator.go` and `cmd/gateway/admin_auth.go`:
  - Ensure provider-agnostic safe diagnostic codes and sanitized HTTP status strings are preserved and formatted clearly under `--debug` without collapsing to `auth_unavailable`.
  - Document the durable claim boundary: claiming occurs before connector invocation; continuation failure consumes the session, preventing replay.
- Tests:
  - `internal/connector/antigravity/auth_test.go`: deterministic offline tests for token responses with normative Google fields (`scope`, `id_token`), rejection of unknown/malformed fields, discovery response formats, and sanitized diagnostic codes/status.
  - `cmd/gateway/admin_auth_test.go`: verify `--debug` emits sanitized diagnostic reason and status without leaking provider body strings, URLs, tokens, codes, or state.
- Explicit limits:
  - No live network requests or provider authentication calls. Live re-tests remain blocked pending reviewed code.
  - Do NOT read, edit, or inspect existing operator databases, keys, or credential fixtures.
  - No speculative relaxation accepting malformed, empty, or duplicate credentials; changes are source- and spec-based only.
  - No sensitive provider error strings, URLs, tokens, codes, state, or log redactions required from the operator.
  - No shared contract ADR needed: changes preserve CONTRACT.md provider-neutral boundaries, existing credential schemas, and admin diagnostic conventions.

## Acceptance

- [x] Token exchange and refresh parsers accept legitimate Google OAuth responses containing normative fields (`scope`, `id_token`) while strictly verifying required fields (`access_token`, `token_type`, positive bounded `expires_in`, and optional `refresh_token`).
- [x] Duplicate keys, control characters, negative/zero/overflow `expires_in`, empty `access_token`, and non-normative unknown fields fail closed as `auth_invalid_response`.
- [x] Credential bundle schema remains unchanged: only `access_token`, `refresh_token`, and `project_id` are stored; `id_token` and `scope` are ignored and not persisted.
- [x] Discovery (`loadCodeAssist`) parser handles candidate project shapes from pinned sources, failing closed with distinct diagnostic codes on malformed/missing project data or non-200 HTTP status.
- [x] Antigravity connector emits provider-agnostic error codes and attaches sanitized `HTTP status %03d` to `OriginalError` on HTTP failures.
- [x] Admin auth under `--debug` outputs secret-safe diagnostic reason and HTTP status instead of collapsing all errors to generic `auth_unavailable`. No secrets, codes, state, or provider response bodies are leaked.
- [x] Operator-reported failure is documented accurately with the consumed single-use continuation boundary (cannot replay callback; no retry).
- [x] All unit and gateway tests pass with race detector under lane TMPDIR (`GOFLAGS=-p=1`).
