## Scope

- Write `docs/implementation/SMOKE-M4.md` specifying:
  - Exact direct leg: Anthropic Messages API (`https://api.anthropic.com/v1/messages`, `anthropic-version: 2023-06-01`, model `claude-opus-5-5` or pinned Anthropic model snapshot).
  - Exact gateway leg: OpenAI Responses client calling PestiRoute `POST /v1/responses` on protected translation route mapping to Anthropic backend.
  - Pinned clients, versions, and configurations: OpenCode CLI 2.0.6 (or reproducible curl harness) sending Responses requests vs direct Messages requests with matched prompts and parameters.
  - 5 matched comparative scenarios:
    1. Plain text streaming response.
    2. Single tool call and tool result return continuation.
    3. Two tool calls in a single turn (parallel tool execution / sequential observation).
    4. Two complete multi-turn tool interaction rounds.
    5. Unsupported reasoning rejection (verifying client error and zero upstream dispatch for `reasoning` controls per M4-029..M4-031).
  - Explicit bounds and safety rules:
    - Request timeout <= 30s per attempt.
    - Output token cap <= 4096.
    - Request attempts capped at 2 client attempts per leg.
    - Credential sanitation: `x-api-key` and `Authorization: Bearer` replaced with sanitized labels (`<ANTHROPIC_KEY_REDACTED>`, `<CLIENT_KEY_REDACTED>`); zero live secrets in artifacts or logs.
  - Offline dry-run procedure and harness:
    - Verifies script/helper against local mock/fake upstreams without network or real credentials.
    - Confirms request capping, credential redaction, and comparison output formatting before any live run.
- Explicit non-goals:
  - No live network requests or paid upstream API calls (live execution is strictly deferred to M4-036).
  - No modification of historical M1 evidence or existing production contracts.
