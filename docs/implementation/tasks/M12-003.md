# M12-003 — Implement account and key management workflows on fixtures

## Outcome

Deliver interactive account (connection) and virtual key / policy management workflows on the frontend fixture adapter, including credential replacement, advertised auth actions, one-time raw key display, named revocation confirmation, revision conflict handling, and rendered tri-state capability badges (`supported`, `unsupported`, `unknown`). Delivers the core operator administration workflows for [M12-WEBUI](../M12-WEBUI.md) tracked in [TASKS](../TASKS.md#m12--webui).

## Read First

- [M12 brief](../M12-WEBUI.md) and [M12-UX](../M12-UX.md) (Connections/Accounts and Keys/Policies layouts, walkthroughs, state matrix rows 2-3).
- [Architecture](../project/ARCHITECTURE.md) (opaque payloads, write-only credentials, transient one-time keys, no browser secret persistence).
- [Parallel ownership](../PARALLEL.md) and [registry](../TASKS.md).
- Existing UI shell in `web/src/App.tsx`, `web/src/fixtures.ts`, and `web/src/App.test.tsx`.

## Scope

- `web/src/fixtures.ts`: Extend fixture models and in-memory mock store with account records (id, connector, enabled, models, tri-state capabilities, expiry metadata, revision), virtual keys (id, label, status, policy reference/revision, limits, created/revoked timestamps), and policy definitions. Add synthetic mutation handlers for creating/toggling accounts, write-only credential replacement, advertised auth triggers, creating keys with transient one-time secret generation, revoking keys, and simulating CAS revision conflicts.
- `web/src/App.tsx` (or dedicated subcomponents in `web/src/`):
  - Connections screen (`/connections`): Account listing with connector, enabled status, credential expiry, revision, and declared capabilities explicitly rendered as tri-state badges (`supported`, `unsupported`, `unknown`). Account creation form (id, connector type, enabled, write-only credential). Account detail view with enable/disable toggle, write-only credential replacement, and advertised auth action trigger (without exposing tokens or persisting callbacks).
  - Keys & Policies screen (`/keys`): Virtual-key list with label/id, active/revoked status, policy details, limits, and created/revoked timestamps. Key creation form with policy restrictions (models, targets, rate limits). One-time raw secret modal/callout shown strictly once upon creation with copy-to-clipboard action and dismissal acknowledgment. Destructive key revocation requiring explicit confirmation modal naming the key. CAS revision conflict UI preserving entered form inputs and offering refresh.
- `web/src/App.test.tsx` (and/or additional test files in `web/src/`): Unit/component tests testing all account and key workflows, one-time secret display and zero persistence in `localStorage`/`sessionStorage`, named revocation confirmation, CAS conflict preservation, and explicit rendering of tri-state capability badges.
- Out of scope: Overview, Usage, Routing, and Settings screens (M12-004); live M11 admin API integration (M12-005); Go embed packaging (M12-006); browser persistence of raw keys or credentials.

## Acceptance

- [x] Connections view displays account records with connector, status, expiry, and explicitly renders tri-state capability badges (`supported`, `unsupported`, `unknown`), addressing the residual risk from M12-002.
- [x] Account creation and credential replacement forms accept write-only credentials; submitted credentials are never echoed back in DOM, stored in `localStorage`/`sessionStorage`, or retained in non-transient state.
- [x] Advertised auth actions (simulated OAuth/manual) trigger observable status transitions without exposing callback tokens or URL secrets.
- [x] Key creation generates and displays the raw virtual key secret exactly once with copy control and acknowledgment; closing the dialog permanently hides the secret; neither `localStorage` nor `sessionStorage` contains raw key secrets.
- [x] Key revocation requires explicit confirmation naming the target key before updating status to revoked; ordinary reads and list navigation require no confirmation.
- [x] Revision/CAS conflicts preserve operator inputs, display a clear conflict message with reload action, and never silently overwrite.
- [x] `cd web && npm ci`, `npm run typecheck`, `npm run build`, and `npm test` all pass with zero errors.
- [x] Workspace Go baseline checks (`git diff --check`, `test -z "$(gofmt -l cmd internal)"`, `go vet ./...`, `go build ./cmd/...`) pass cleanly without Go modifications.
