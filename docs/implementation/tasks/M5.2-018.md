## Scope

- Exercise protected policy denial, reservations/usage and selected-account auth with two compatible targets (e.g., unauthenticated `ollama-v0.40.3` and bearer-authenticated `vllm-v0.31.0`).
- Verify out-of-policy (disabled key, unpermitted model/connector) requests reject before dispatch without reaching upstream.
- Verify credential and header isolation between distinct targets: no bearer headers leak to unauthenticated endpoints, and scoped accounts route strictly to their configured upstreams.
- Verify accounting lifecycle: exactly-once attempt finalization for success, terminal error, mid-stream interruption, and cancellation, capturing known, partial, and unknown usage in SQLite storage.
- Confirm absent upstream usage maps to unknown usage rather than free/zero inference; invalid conservative reservation budgets fail closed before dispatch.
- Verify storage failure handling: database unavailability withdraws service readiness without triggering post-commit replay or ambiguous delivery fallback.
- Reuse existing durable settlement/recovery and accounting helpers; do not add local-runtime-specific storage engines or Core provider branches.

- [x] Absent usage is not zero/free inference; invalid conservative budget fails before dispatch.
- [x] Storage failure withdraws readiness; no ambiguous delivery fallback or post-commit replay.
