# M6-007 — Implement bounded wire values and codecs

## Outcome

Encode/decode the M6 gRPC messages losslessly within documented bounds. See [registry](../TASKS.md#m6--external-plugin-runtime) and [binding](../M6-BINDING.md#wire-value-mapping).

## Read First

- [M6-BINDING](../M6-BINDING.md#wire-value-mapping)
- [CONTRACT](../CONTRACT.md)
- `internal/core/{component,connector,execution}.go`

## Scope

- Generated protobuf messages and process-boundary conversion/validation only; Core types and semantics unchanged.
- Encode every complete typed protobuf request/result/control record with M6-BINDING's common bounded `RecordFragment` envelope; no per-field allowlist. Keep opaque Execute/EstimateUsage request bodies and HTTP/Execute response bodies on their separate incremental <=64 KiB body streams. Execute and EstimateUsage request bodies reassemble under the parameterized effective admitted route bound; 1 MiB is an example fixture, not a universal ceiling.
- Implement `RequestMetadata.Extensions` only as opaque `map<string, bytes>` slots; v1 has no declared codecs, so reject any non-empty map. Do not serialize arbitrary Go `any` values or coerce them to JSON/string.

## Acceptance

- [x] Round-trip every supported Go field through complete typed records, preserving nil vs zero/false, opaque bytes, repeated header value order, unknown vs explicit capability values, optional auth fields, and empty Extensions.
- [x] Accept opaque Execute and EstimateUsage bodies larger than 64 KiB and exactly at a parameterized effective route bound; preserve bytes/order through chunks/reassembly. A 1 MiB fixture is illustrative only. Reject aggregate bytes only above that route bound; reject an individual chunk over 64 KiB as malformed.
- [x] EstimateUsage invokes the logical method exactly once with the reconstructed query and returns one parity-matching EstimateResult; the common record envelope streams a >84 KiB Method field and exposes no partial result. A lower route limit rejects before invocation.
- [x] For every reviewer-named control type, exercise both an individual text field larger than 84 KiB and a multi-field/collection record larger than 84 KiB: ExecutionRequest ID/model/capability set and RequestMetadata header keys/values; CapabilityScope protocol/mode/model/account; ModelQuery fields; HeadFrame protocol/content type/headers; and each GatewayError text field. Also cover large Descriptor declarations and capability/model result collections. Verify exact field/map/slice/presence semantics, one method call, and whole-record atomicity. Do not add aggregate logical-value limits.
- [x] Exercise >84 KiB ComponentConfig.Data, every AuthRequest/AuthResult variable field and credential values through the same generic envelope; each logical method runs/returns once with exact bytes. HTTP bodies and Execute Body output remain incremental and never aggregate a complete user response.
- [x] Accept an encoded wire frame exactly at 84 KiB including gRPC's five-byte prefix; reject 84 KiB + 1 and typed-record fragments/body chunks larger than 64 KiB. Keep gRPC serialized-message cap at 84 KiB - 5.
- [x] Reject duplicate/skipped/reordered sequence, wrong call/type/length/offset, truncation, trailing fragments, and claimed-length overflow without preallocating from declared length. Do not invoke on malformed requests or expose partial results. Execute also rejects duplicate/out-of-order controls and a partial body ending before `InputComplete`.
- [x] Reject non-empty v1 Extensions until a namespaced extension and codec are separately declared/negotiated; no arbitrary `any` serialization.
- [x] Reject invalid enums/malformed presence and malformed fragments before conversion; honor existing body/HTTP/header/config limits but impose no new aggregate cap on typed logical records.
- [x] No serialized Go interfaces/errors/contexts; no imports added to `internal/core`.
