# M10-021 — Implement bounded Google OAuth callback issuer (iss) verification and absence compatibility

## Outcome

Delivers connector-private bounded parsing and verification of the RFC 9207 OAuth callback issuer parameter (`iss`) in the Antigravity connector, permitting valid Google OAuth redirect callbacks containing `iss=https://accounts.google.com`, rejecting untrusted/duplicate/malformed issuers fail-closed before network dispatch, while preserving strict redirect/state checks and absence compatibility. See [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [M10 brief](../M10-ANTIGRAVITY.md).

## Owning ADR: DEC-024

- **Status:** Accepted for M10-021 offline implementation on 2026-10-23.
- **Context:** A sanitized callback shape established presence of `iss` alongside existing fields; the DEC-023 six-key bound rejects it. RFC 9207 defines the authorization-response issuer identifier for mix-up protection, but does not require every authorization server to return it. Google's published OpenID Connect discovery metadata identifies `https://accounts.google.com` as issuer ([Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect#discovery)). Structural incompatibility is confirmed; cause of the latest live operator attempt remains UNKNOWN.
- **Decision:** Amend CONTRACT.md callback-URL rules: allow Antigravity connector-local bounded optional `iss` query parameter alongside the existing parameters (`code`, `state`, `scope`, `authuser`, `prompt`, `hd`), updating the maximum distinct query parameter count bound to 7. When `iss` is present:
  1. It must occur exactly once and match the trusted Google accounts HTTPS issuer (`https://accounts.google.com`) byte-for-byte.
  2. Any untrusted, malformed, non-HTTPS, or duplicate issuer value is rejected fail-closed before network dispatch.
  3. When `iss` is absent, absence compatibility is preserved per RFC 9207 and existing specification.
  4. Never persist, log, or echo `iss` or any callback metadata; safe diagnostic reason codes distinguish validation failures (`callback_iss_mismatch` or `callback_query_keys`) without exposing payload values.
  5. Core remains provider-neutral: Core safe diagnostic allowlist admits `callback_iss_mismatch`; Core does not parse callback URLs, branch on providers, or modify stored schema.
- **Alternatives rejected:** Blindly ignoring `iss` (violates RFC 9207 mix-up protection and safe input validation); permitting arbitrary query parameters (violates defense-in-depth); requiring `iss` universally (breaks absence compatibility for providers or historical flows without RFC 9207 support).
- **Compatibility / impact:** Connector-private Antigravity compatibility extension only; Core diagnostic allowlist updated with provider-neutral code `callback_iss_mismatch`; runtime execution, IPC, schema, and other connectors unchanged. No live network calls or unreviewed promotion.
- **Verification:** Synthetic deterministic positive (trusted issuer and absence) and negative (wrong scheme/authority/path/query/fragment/case, duplicate encoded key, excess keys) tests; single-decode query semantics; canary suppression through coordinator/CLI diagnostic path; connector/core/gateway race tests.

## Scope

- Documentation / Specification handoff:
  - Document DEC-024 in `docs/project/DECISIONS.md` and synchronize `docs/implementation/CONTRACT.md`, `M10-AUTH-BINDING.md`, and `LOCAL-M10.md` to reflect bounded RFC 9207 `iss` verification, trusted Google accounts issuer, 7-key maximum bound, and absence compatibility.
- Connector (`internal/connector/antigravity/auth.go`):
  - In URL callback parser, extend the allowed query keys map to include `"iss": true` and update the key bound from 6 to 7.
  - When `iss` is present in query parameters:
    - Verify it occurs exactly once (`len(values["iss"]) == 1`).
    - Verify the value matches `https://accounts.google.com` byte-for-byte.
    - If `iss` is malformed, not HTTPS, or does not match `https://accounts.google.com`, reject fail-closed with `callback_iss_mismatch` before any network dispatch.
  - When `iss` is absent, proceed normally with existing code/state and optional metadata validation (preserving absence compatibility).
  - Retain byte-exact scheme, authority, and escaped path matching against continuation `RedirectURI`; reject userinfo, fragments, and control characters.
  - Never read, store, or log `iss` value or query contents into tokens, credentials, or diagnostics.
- Core Runtime (`internal/core/auth_coordinator.go`):
  - Extend provider-neutral `safeAuthDiagnosticCode` allowlist to include `callback_iss_mismatch`.
  - Preserve single-use claim semantics, zero provider branching, and zero payload parsing.
- CLI / Admin UX (`cmd/gateway/admin_auth.go`):
  - Ensure `callback_iss_mismatch` is formatted cleanly as a safe diagnostic code without echoing callback content.
- Tests:
  - `internal/connector/antigravity/auth_test.go`:
    - Test valid callback URL containing `iss=https://accounts.google.com` alongside `code`, `state`, and combinations of `scope`, `authuser`, `prompt`, `hd`.
    - Test valid callback URL omitting `iss` (absence compatibility).
    - Test rejection of callback with untrusted `iss` (e.g. `iss=https://evil.example.com` or `iss=http://accounts.google.com`) returning `callback_iss_mismatch`.
    - Test rejection of duplicate `iss` parameters returning `callback_query_keys`.
    - Test rejection when query keys exceed 7 or contain undeclared keys.
    - Test unchanged rejection of redirect mismatch, state mismatch, fragments, OAuth error param, and malformed encoding.
  - `cmd/gateway/admin_auth_test.go`:
    - End-to-end admin auth test with synthetic callback containing `iss`, verifying clean diagnostics and canary suppression.
- Explicit limits:
  - No live network requests or external provider calls.
  - No operator fixture, db, key, secret, or callback reads.
  - No relaxation of byte-exact redirect URI matching or state equality.
  - Core remains provider-neutral; no Core payload parsing, provider branching, or schema changes.

## Acceptance

- [x] URL callback parser accepts bounded optional `iss` alongside metadata, `code`, and `state` up to 7 distinct keys.
- [x] Present `iss` must exactly equal `https://accounts.google.com`; untrusted values fail with `callback_iss_mismatch` before dispatch. Query values decode once; no later normalization.
- [x] Absent `iss` remains compatible; valid callbacks succeed.
- [x] Duplicate `iss` (including encoded duplicate spelling) and undeclared/excess keys fail before exchange.
- [x] Raw scheme, authority, escaped path, and exact state checks remain strict; exchange retains original redirect and no replay.
- [x] Core safe diagnostic allowlist admits `callback_iss_mismatch` without provider branching.
- [x] Terminal feedback and diagnostics do not echo callback values; synthetic issuer/code canaries are suppressed.
- [x] DEC-024 recorded and CONTRACT, M10 auth binding, and LOCAL-M10 synchronized.
- [x] Focused race suites, `go vet ./...`, `go build ./...`, and `git diff --check` pass.
