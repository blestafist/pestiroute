# M2-018 — Validate terminal EOF before finalizing stream success

## Outcome

Malformed trailing frames cannot be hidden by finalizing and closing immediately at Complete. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Apply the binding's terminal validation path: retain pending completion/usage until orderly EOF is verified, keeping cancellation/deadline effective and reads bounded.
- Classify duplicate completion, post-Complete data/error and premature EOF as contract/infrastructure failures; preserve available usage and finalize once.
- Do not buffer body, fabricate Complete/provider events or replace the response after commit.

## Acceptance

- [ ] Complete(succeeded) followed by Body/Complete/unknown frame is recorded as a runtime error rather than success.
- [ ] Valid Complete-to-EOF, failed Head-to-Complete and missing completion each produce the correct single record and cleanup.
- [ ] A producer stalled after Complete is cancellable; Close/EOF/cancellation races cannot publish duplicate records.
