# M2-018 — Validate terminal EOF before finalizing stream success

## Outcome

Malformed trailing frames cannot be hidden by finalizing and closing immediately at Complete. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Execution Response and StreamFrame](../CONTRACT.md#execution-response-and-streamframe) (lifecycle: `Head → Body* → Complete → EOF`; `Complete` is control metadata followed by EOF; no following frames).
- [Error model and interrupted attempts](../CONTRACT.md#error-model) (contract failures, incomplete attempts, preserving partial/unknown usage).
- `internal/core/dispatch.go` (`attemptStream.Next`, `finalize`, `fail`, `Close`), `internal/core/execution.go` (`checkedStream`), `internal/adapter/responses/encode.go` (terminal EOF read).
- `internal/testutil/scripted/scripted.go` (scripted streams with step gates and errors).

## Scope

- In `internal/core/dispatch.go`, update `attemptStream` so encountering `FrameComplete` from the source does not immediately finalize success or close the underlying stream.
- Retain the pending completion outcome, usage report, and error until the subsequent `Next()` confirms orderly `io.EOF` from the source stream (`checkedStream`).
- Deliver `FrameComplete` to downstream consumers (such as `adapter/responses.Encode`), allowing downstream to inspect completion metadata and execute its terminal EOF check.
- When `Next()` is called after `FrameComplete`:
  - If the underlying stream returns `io.EOF`, finalize the attempt with the pending completion outcome (`OutcomeSucceeded` or reported outcome), usage, and error, and return `io.EOF`.
  - If the underlying stream returns an additional frame (`FrameBody`, `FrameComplete`, unknown) or non-EOF stream error, classify as a contract/infrastructure error (`OutcomeFailed`, `execution_failed` / `ErrStreamContract`), retain any supplied usage, and finalize once.
- Stalled producers: ensure context cancellation and deadlines remain effective while awaiting post-Complete EOF; cancelled reads abort the wait, close the stream, and finalize as `OutcomeCancelled`.
- Preserve concurrency invariants: `Close()`, `Next()`, context cancellation, and loser finalizer synchronization publish exactly one terminal `AttemptObservation` without races.
- Explicit limits: No response body buffering; no synthetic/fabricated Complete frames or client response rewriting after commit; no changes to adapter schemas or persistent databases.

## Acceptance

- [x] Complete(succeeded) followed by Body/Complete/unknown frame or unexpected stream error is recorded as a runtime contract error rather than success, while preserving any supplied usage.
- [x] Valid Complete-to-EOF, failed Head-to-Complete, and missing completion (premature EOF / non-Complete termination) each produce exactly one terminal record and clean stream closure.
- [x] A producer stalled after Complete is cancellable and deadline-bounded; concurrent Close/EOF/cancellation races publish exactly one terminal attempt record without data races or leaks.
