# M10-016 — Translate Responses multi-turn tool history to candidate Antigravity contents and verify tool cycle

## Outcome

Translates `openai.responses.v1` multi-turn conversation and tool history (string or array `input` with `message`, `function_call`, and `function_call_output` items) into candidate Gemini-style `contents` turns (`role: "user" | "model"`) within `internal/connector/antigravity`. Verifies client-to-fake-backend tool cycle and incremental response correctness under the offline fake transport. Preserves opaque Core contract and adapter boundaries (no repeat translation in adapter). Fails closed on thought signatures / reasoning items pre-dispatch; assesses signature incompatibility with fullworking multi-turn goal. ## Scope

- In `internal/connector/antigravity/execute.go`:
  - Extend `admit` to accept `input` as either a JSON string or a JSON array of input items.
  - Map accepted item shapes to Gemini candidate `contents` turns:
    - User `message` (`role: "user"`) -> `role: "user"`, `parts: [{"text": ...}]`.
    - Assistant `message` (`role: "assistant"`) -> `role: "model"`, `parts: [{"text": ...}]`.
    - Assistant `function_call` (`call_id`, `name`, `arguments`) -> `role: "model"`, `parts: [{"functionCall": {"name": ..., "args": ..., "id": ...}}]`. Consecutive parallel calls coalesce into one model turn preserving part order and IDs.
    - User `function_call_output` (`call_id`, `output`) -> `role: "user"`, `parts: [{"functionResponse": {"name": ..., "id": ..., "response": {"output": ...}}}]`. Consecutive tool responses coalesce into one user turn matching call IDs.
  - Enforce chronology and causal pairing:
    - Every `function_call_output` must match a prior unfulfilled `function_call` by `call_id`.
    - Reject orphan outputs, duplicate outputs for the same `call_id`, interleaved user text before pending calls resolve, and dangling calls when subsequent non-tool items appear.
  - Fail closed pre-dispatch (`unsupported_feature` / `invalid_request`):
    - Any reasoning item (`type: "reasoning"`), thought part, or thought signature metadata fails closed pre-dispatch before any transport invocation.
    - Reject unrecognized item types, invalid JSON arguments, and unsupported top-level fields.
- In `internal/connector/antigravity/execute_test.go` and `cmd/gateway/antigravity_composition_test.go`:
  - Unit tests for single-round and multi-round tool history translation, parallel function calls, text + tool history.
  - Fail-closed tests for orphan outputs, duplicate outputs, interleaved messages, dangling calls, and thought-signature rejection.
  - Gateway composition test verifying an end-to-end client-to-fake-backend tool cycle (prompt -> tool call SSE stream -> tool result resubmission in history -> final text SSE stream) with incremental SSE delivery and cancellation.
- In `docs/implementation/M10-TOOL-BINDING.md` / `docs/implementation/M10-COMPATIBILITY.md`:
  - Record the multi-turn history translation ceiling and explicit offline/live boundary.
  - Explicitly assess that end-to-end fullworking live tool loops against signature-enforcing Gemini Thinking models are constrained by the absence of a standard Responses thought-signature carrier; record offline follow-up for carrier or validator bypass (`skip_thought_signature_validator`) research.
- Explicit limits:
  - No live network requests, provider endpoints, or account discovery (`loadCodeAssist`).
  - No modification or reading of persistent operator/user credentials.
  - Core runtime and Protocol Adapter remain untouched (opaque bytes, no repeated translation).
  - Connector descriptor capabilities remain `Unknown`.
