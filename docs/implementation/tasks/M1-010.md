# M1-010 — Single-target Core execution

## Outcome

Core owns one attempt and its lifecycle without interpreting provider bytes. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-005 binding, M1-004 scoped eligibility decisions, [request](../CONTRACT.md#execution-request), [frames](../CONTRACT.md#execution-response-and-streamframe), [Connector](../CONTRACT.md#connector-contract).

## Scope

- Inject one eligible target via an interface; assign trusted request/attempt IDs, runtime context and scoped services.
- Enforce frame ordering, commit-at-Head-handoff, cancellation/Close and exactly-once in-memory attempt finalization with partial/unknown usage.
- Stop before concrete Connector wiring, persistent accounting, generic registry, alternative targets or fallback.

## Acceptance

- [ ] One admitted request invokes one Execute; client metadata cannot select an account or replace runtime IDs.
- [ ] Scripted valid, pre-head-error and malformed-frame streams finalize once; EOF without Complete is not success.
- [ ] Required capabilities use the decided exact scoped support check; Core imports no concrete adapter/Connector and parses no JSON/SSE.

## Verification

From root run focused Core tests with a scripted Connector, including invalid ordering and cancellation, then `./scripts/check.sh`. Inspect imports and assert call/finalization counts. Record the concrete command at READY.
