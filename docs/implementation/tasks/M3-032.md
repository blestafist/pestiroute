## Scope

- In `cmd/gateway`:
  - Add end-to-end abrupt-restart accounting tests (e.g. `cmd/gateway/restart_recovery_test.go` or `cmd/gateway/...`) testing gateway process lifecycle across crashes with a real SQLite database file, master key, and loopback upstream.
  - Test crash and restart across boundaries:
    1. Abrupt termination after durable admission and reservation commit, before dispatch intent.
    2. Abrupt termination after dispatch intent commit, during upstream dispatch or streaming.
    3. Abrupt termination after upstream stream completion, before terminal settlement write.
  - Verify on restart:
    - Startup recovery runs automatically before readyz/listener open.
    - Undispatched reservations are released and attempts marked `failed` with `not_dispatched` reason.
    - Dispatched/in-flight attempts marked `interrupted`, reservation settled conservatively, usage counts recorded as NULL/unknown.
    - Zero replay requests sent to upstream.
    - Repeated restart and recovery passes are idempotent: no double charges, no refunds.
    - Encrypted credentials and virtual key policies survive intact; subsequent valid requests succeed and limits are correctly enforced across restarts.
    - CLI usage inspection (`pestiroute admin usage ...`) accurately reflects recovered attempt states and conservative/unknown tokens.
- Explicit limits:
  - Permitted test-only seam: in `cmd/gateway/main.go`, `composeHandler` preserves an injected `c.accounting` when present (`if accounting == nil { accounting = sqliteAccountingStore{...} }`), matching `policyStore` and `accountAuthorizer`.
  - In `cmd/gateway/restart_recovery_test.go`, run a test subprocess helper via `os.Args[0]` that wraps `sqliteAccountingStore` to halt/pause or trigger `SIGKILL` immediately after `Admit` commits and before `RecordDispatchIntent`, providing true process kill evidence at the pre-intent boundary.
  - No production environment hooks, debug flags, or backlog scope changes.
  - Does not implement provider-neutral auth runtime or OAuth sessions (reserved for [M3-033](M3-033.md)–[M3-036](M3-036.md)).
  - Does not implement fallback routing or retry decisions (reserved for [M3-037](M3-037.md)–[M3-041](M3-041.md)).
  - Uses synthetic fixtures and local loopback; no paid inference or live provider network calls.

## Acceptance

- [x] Abrupt gateway termination after admission (before intent) recovers on restart: reservation is released, attempt terminalized as `failed` (`not_dispatched`), request terminalized as `failed`, zero upstream replays occur, and CLI usage reports zero tokens charged.
- [x] Abrupt termination during active dispatch or streaming recovers on restart: attempt is marked `interrupted`, reservation is settled conservatively, usage counts remain NULL (unknown), zero upstream replays occur, and CLI usage reflects conservative token retention.
- [x] Repeated restart cycles are idempotent: no additional attempts or charges are created, existing settlements are preserved, and subsequent valid requests are admitted and accounted correctly under limits.
- [x] Encrypted credentials and virtual key policies survive across restarts, and the gateway serves subsequent valid requests without secret leakage.

## Completion Evidence

`cmd/gateway/main.go` preserves an injected accounting store and defaults to SQLite only when nil. In `cmd/gateway/restart_recovery_test.go`, an `os.Args[0]` child-test helper wraps `sqliteAccountingStore`, commits real `Admit`, prints the exact request/attempt IDs, then blocks before returning to Core, so intent cannot be recorded; the parent SIGKILLs that process. On restart those exact IDs are verified as request/attempt `failed`, `not_dispatched`, reservation `released`, charge zero, and no usage. This uses the same fixture key as all later admissions.

Separate real-process kills cover dispatch active at the upstream and after upstream response completion. In the latter case an independent `BEGIN IMMEDIATE` writer holds settlement; immediately before kill the exact request/attempt remain `admitted`/`intent`, reservation `held`, charge zero, no usage row. Restart recovers those exact IDs as `interrupted`/`conservative`, charge 10, with NULL token counts. Parsed CLI request JSON verifies all three unique request/attempt IDs, per-row states/reservation states/charges, and totals of 3 requests, 3 attempts, 30 estimated tokens and 20 charged. Full CLI JSON snapshots remain byte-identical over repeated recovery restarts. The original key is rejected `rate_limit_exceeded` at TPM 20 without another upstream call; a new key under the surviving policy completes a post-restart request. Only the configured synthetic credential reaches the loopback upstream; generated virtual-key plaintext is absent from CLI usage and DB/WAL/SHM files.
