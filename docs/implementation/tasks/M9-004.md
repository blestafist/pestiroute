## Scope

- Add comprehensive protected client-to-fake-backend tests in `cmd/gateway/chat_agent_test.go` (and/or `internal/conformance/chatcompletions_test.go`):
  - Multi-round tool workflow: Round 1 (user message, tool definitions) returns assistant tool call with unique ID, function name, and JSON arguments; Round 2 (conversation history including assistant tool call and tool message with matching `tool_call_id`) returns final assistant completion.
  - Streaming tool deltas: multi-chunk SSE stream delivering tool call fragments across chunks (index, id, name, argument deltas) terminated by `[DONE]`.
  - Parallel tool calls: single assistant response or client history containing multiple concurrent tool calls (`index: 0`, `index: 1`, ...). Verify `parallel_tool_calls: true` enforces `llm.tools.parallel` requirement before dispatch.
  - Tool choice options: `auto`, `required`, and named function selector `{"type":"function","function":{"name":"..."}}` with opaque argument preservation and `llm.tools` capability gating.
  - Response format options: `{"type":"text"}`, `{"type":"json_object"}`, and `{"type":"json_schema",...}` with strict schema validation and `llm.structured_output` capability gating.
  - Native byte and ID preservation: tool call IDs, nested argument strings, and unrecognized message properties remain verbatim across all turns.
  - Pre-dispatch capability denials: requests requiring `llm.tools`, `llm.tools.parallel`, or `llm.structured_output` fail closed before backend dispatch when the connector target does not declare them as `supported`.
- Exclusive sequencing ownership for this lane: `cmd/gateway/chat_agent_test.go`, `internal/conformance/chatcompletions_test.go`, and Chat-specific test fixtures. Keep Claude connector and Responses paths unchanged.
- Boundaries: Do not implement cross-protocol translation (e.g. Chat to Responses), universal message representations, UI/CLI changes, or live provider calls.

## Acceptance

- [x] Multi-round tool interaction succeeds through the protected gateway (`POST /v1/chat/completions`) using synthetic SQLite keys/accounts: round 1 returns assistant tool calls with generated IDs; round 2 passes tool execution results (`role: "tool"`, matching `tool_call_id`) and receives assistant completion, with body bytes and IDs preserved verbatim.
- [x] Streaming tool call delivery: incremental SSE delivery transmits tool call deltas (split IDs, function names, argument chunks) across multiple chunks terminated by `[DONE]`, preserving raw chunk bytes and stream ordering.
- [x] Parallel tool calls: requests with multiple tool calls in a single turn and `parallel_tool_calls: true` correctly require `llm.tools.parallel` and dispatch when supported; fail before dispatch when candidate lacks `llm.tools.parallel`.
- [x] Tool choice variants: `tool_choice` forms `none`, `auto`, `required`, and named function selector are validated per binding; non-`none` forms require `llm.tools`; invalid forms fail closed before dispatch.
- [x] Response format options: `json_object` and `json_schema` require `llm.structured_output` and preserve format options verbatim; malformed schemas fail closed; requests dispatch when capability is supported and fail before dispatch when unsupported.
- [x] Existing Chat and Responses gateway regressions pass unchanged.
