# M1-009 — Fixed-response native Connector

## Outcome

Fixed JSON responses use the same cancellable frame lifecycle as streaming responses. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- [M1-008](M1-008.md) (transport), [M1-004](M1-004.md) and [M1-BINDING](../M1-BINDING.md#connector-observation-without-response-buffering) (observation rules), [frames](../CONTRACT.md#execution-response-and-streamframe), [errors](../CONTRACT.md#error-model), [usage](../CONTRACT.md#usage-and-scoped-runtime-services), `internal/connector/responses/transport.go`, `internal/core/execution.go`.

## Scope

- Implement fixed JSON execution in `internal/connector/responses/` using the scoped transport: yield `FrameHead`, incremental opaque `FrameBody` chunks as read, and one classified `FrameComplete`.
- Apply bounded inline observation (up to 1 MiB scratch per `M1-BINDING.md`) for `error`, `status` (`completed`, `failed`, `incomplete`) and terminal usage without buffering the whole response.
- Classify HTTP rejections (preserving native status and body frames) and pre-Head failures (such as unsupported `Content-Encoding`), and ensure partial-read or cancelled stream `Close()` aborts and releases upstream transport resources immediately.
- Stop before SSE event observation (owned by M1-012), adapter HTTP handler integration, or full capability registries. Unknown usage remains `UsageUnknown`.

## Acceptance

- [x] Success and rejection bodies match upstream bytes exactly with incremental chunking and no whole-response buffering; frames obey v1 `Head -> Body* -> Complete` ordering.
- [x] HTTP 200 alone is not assumed success: provider failure/incomplete objects and transport truncation before JSON completion are classified as `OutcomeFailed` / `OutcomeIncomplete`.
- [x] Rejection metadata and pre-Head errors are classified into `GatewayError`; non-identity `Content-Encoding` fails pre-Head without forwarding encoded bodies.
- [x] Stream `Close()` is idempotent, interrupts blocked reads, and terminates upstream HTTP response/body without leaking resources.
