# M1-009 — Fixed-response native Connector

## Outcome

Fixed JSON responses use the same cancellable frame lifecycle as streaming responses. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-008 transport, M1-004 outcome-observation decisions, [frames](../CONTRACT.md#execution-response-and-streamframe), [errors](../CONTRACT.md#error-model), [usage](../CONTRACT.md#usage-and-scoped-runtime-services).

## Scope

- Implement Execute for fixed JSON with Head, incremental opaque Body frames and one classified Complete; use bounded Connector-side observation per the binding note.
- Preserve native rejection body/status, classify pre-head errors and make partial-read Close cancel/release the upstream.
- Stop before SSE observation, HTTP adapter integration, exact token extraction or complete-response buffering. Unknown usage is valid and must remain unknown.

## Acceptance

- [ ] Success and rejection bodies match exactly with no whole-response accumulation; frames obey v1 ordering.
- [ ] HTTP 200 alone is not success: failed/incomplete provider outcome and truncated transport are classified correctly under the selected native scope.
- [ ] Error metadata is available at the correct boundary; close is idempotent and no work continues after cancellation.

## Verification

From root run fake-upstream Connector tests for success, provider failure, rejection, truncation and partial-read close, then `./scripts/check.sh`. Use observable bytes, outcome and cancellation evidence; name the tests at READY.

## Open Questions / Blocker
