# M6-027 — Verify crash accounting and delivery-safe fallback

## Outcome

Verify crash accounting and delivery-safe fallback for external child connectors under fault injection in protected gateway execution. Prove that child crashes or transport severance before send (proven safe) allow delivery-safe fallback across candidates, while ambiguous crashes/drops (after send, pre-Head) or post-commit crashes (post-Head) settle SQLite reservations exactly once with unknown/zero usage, never trigger ambiguous replay or fallback across candidate targets, and preserve ledger integrity across supervisor child recovery. See [registry](../TASKS.md#m6--external-plugin-runtime) and [milestone](../ROADMAP.md#m6--external-plugin-runtime).

## Scope

- Deterministic integration tests in `cmd/gateway/`:
  - Multi-target route configuration with external connector instances and SQLite ledger backing.
  - Safe pre-send failure injection: verify explicit `RetrySafe` allows delivery-safe fallback to the next candidate target, recording both attempts in SQLite with sequential attempt numbers and exactly-once settlement.
  - Ambiguous pre-Head crash injection (child SIGKILL or transport severance while awaiting response): verify `CategoryUnavailable` with `RetryUnknown` fails closed, prevents fallback to subsequent targets, and settles the attempt reservation exactly once in SQLite.
  - Post-Head crash injection (child SIGKILL or transport drop mid-stream): verify caller receives stream termination, no fallback is attempted after commit, and SQLite accounting settles without duplicate tokens or dangling reservations.
  - Child supervisor recovery: verify supervisor restarts the crashed child within budget for subsequent new requests while guaranteeing zero replay of the interrupted request.
- Limits:
  - Multi-account credential/stream isolation across concurrent tenants belongs to M6-028.
  - Unified cross-connector conformance suite belongs to M6-029.
  - Core runtime retry/fallback logic is preserved unchanged; test verifies integration with external connector child process.

## Acceptance

- [x] Explicit pre-send safe failure allows fallback to a second configured target, settling both attempts in SQLite ledger with sequential attempt numbers and exactly-once finalization.
- [x] Ambiguous child crash before Head (`RetryUnknown` / `RetryUnsafe`) fails closed: gateway returns error to client, refuses fallback to secondary targets, and settles the reservation in SQLite ledger exactly once.
- [x] Post-Head child crash during streaming commits the attempt, delivers error to caller without fallback, and finalizes accounting in SQLite ledger without duplicate tokens or hanging reservations.
- [x] Child restart by supervisor after crash restores service for subsequent new requests while guaranteeing zero replay of the crashed request.
- [x] Tests pass under `go test -race` with zero leaked goroutines, child processes, or orphaned sockets.
