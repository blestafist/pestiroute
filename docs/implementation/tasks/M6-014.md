# M6-014 — Bridge bounded sanitized logging

## Outcome

Bridge runtime invocation logging and child diagnostics over IPC so external child connectors can emit structured log events to the host runtime logger without leaking credentials or raw payloads, while enforcing record size (<=8 KiB) and process-wide queue capacity (<=256 records) bounds. See [registry](../TASKS.md#m6--external-plugin-runtime), [milestone](../ROADMAP.md#m6--external-plugin-runtime), and [binding](../M6-BINDING.md#reverse-services-and-authority).

## Scope

- HostServices proto definition and code generation for client-streaming `Log` RPC under [M6-BINDING](../M6-BINDING.md#reverse-services-and-authority).
- Log framing and codec: `LogRecordTo` and `LogRecordFrom` converting `*gen.LogRecord` and validating:
  - 8 KiB maximum record length.
  - Valid log levels (`DEBUG`, `INFO`, `WARN`, `ERROR` mapped to `slog.Level`).
  - Prohibited attribute keys/fields (`payload`, `body`, `credential`, `secret`, `token`, `authorization`).
- Host-side reverse service handler on `HostServices`:
  - Receives client-streaming `RecordFragment` stream carrying fragmented `LogRecord`.
  - Correlates with host invocation via `invocation_id` when present, or host process logger when absent.
  - When bound to an invocation, routes log through invocation's scoped `*slog.Logger` (which redacts registered secrets via `redactingHandler`).
  - Enforces process-wide log record queue bound (max 256 records) and drops excess records without blocking child execution or failing RPC (best-effort delivery per binding).
  - Completes with the binding's empty response and standard gRPC status (no custom acknowledgement record).
- Child-side logging adapter wrapping `Log` RPC:
  - One process-owned `LogDispatcher` shares the fixed 256-record queue and worker across that process's invocation loggers; it is not a global shared across process epochs.
  - Exposes `*slog.Logger` / `slog.Handler` that serializes log records into `LogRecord` protobuf messages.
  - Enforces 8 KiB record limit before sending.
  - Streams fragmented `RecordFragment` messages to host.
- Child diagnostic stream sanitization and bounding:
  - Ensure `Process.Diagnostics()` retains at most 64 KiB stdout/stderr.
  - Verify secret-marker redaction and absence in diagnostics and log outputs.
- Limits: Logging reverse service and diagnostic bounding only. Models/usage (M6-015), auth state (M6-016), and Execute stream bridging (M6-017) are separate tasks. No raw prompt or response payload logging.

## Acceptance

- [x] Child emits structured log events over IPC with level, message, and attributes; host receives and logs them through the invocation's runtime logger.
- [x] Log records exceeding 8 KiB are rejected with structured failure without corrupting IPC stream state.
- [x] Registered credential secrets are redacted from log messages and attributes before writing to output.
- [x] Prohibited payload/body/credential attribute keys are stripped or rejected; raw request/response bodies are never logged.
- [x] Process-wide log queue is bounded at 256 records; bursts exceeding queue capacity drop excess records without blocking child execution or deadlocking IPC.
- [x] Child process stdout/stderr diagnostics are bounded at 64 KiB total retention and do not leak secret markers into gateway diagnostics.
