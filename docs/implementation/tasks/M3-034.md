# M3-034 — Persist protected authentication sessions

## Outcome

Persist protected authentication sessions and refresh markers in SQLite. This provides the durable foundation for provider-neutral interactive auth continuation, crash-safe token refresh tracking, quarantine of ambiguous operations, and atomic credential replacement. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Schema migration version 5 in `internal/storage/sqlite/migrate.go`:
  - Create table `auth_sessions`:
    - Columns: `id` (TEXT PRIMARY KEY), `account_id` (TEXT NOT NULL REFERENCES accounts(id) ON DELETE RESTRICT), `connector` (TEXT NOT NULL), `kind` (TEXT NOT NULL CHECK in `'interactive'`, `'refresh'`), `expected_credential_revision` (INTEGER NOT NULL CHECK >= 1), `lifecycle` (TEXT NOT NULL CHECK in `'active'`, `'refresh_in_progress'`, `'uncertain'`, `'consumed'`), `expires_at` (INTEGER, nullable), `created_at` (INTEGER NOT NULL), `updated_at` (INTEGER NOT NULL), `format_version` (INTEGER, nullable), `key_version` (TEXT, nullable), `nonce` (BLOB, nullable), `ciphertext` (BLOB, nullable), `quarantine_reason` (TEXT, nullable CHECK in `'ambiguous_result'`, `'cancelled_after_call'`, `'persistence_failed'`, `'restart_in_progress'`), `current_credential_revision` (INTEGER, nullable CHECK >= 1).
    - Table-level CHECK constraint enforcing:
      - Active interactive rows require `format_version`, `key_version`, `nonce`, `ciphertext`, and `expires_at`; consumed interactive rows retain expiry metadata but clear the envelope columns.
      - Refresh rows (`kind = 'refresh'`): `format_version`, `key_version`, `nonce`, `ciphertext`, and `expires_at` are all NULL.
    - Partial unique index: `CREATE UNIQUE INDEX idx_auth_sessions_account_refresh_active ON auth_sessions(account_id) WHERE lifecycle IN ('refresh_in_progress', 'uncertain');` ensuring at most one active or quarantined refresh marker per account.
    - Indices: `idx_auth_sessions_account_id ON auth_sessions(account_id)` and `idx_auth_sessions_lifecycle_expires ON auth_sessions(lifecycle, expires_at)`.
- Storage repository in `internal/storage/sqlite/auth_sessions.go`:
  - Interactive session lifecycle:
    - `CreateInteractiveSession`: creates row with `kind='interactive'`, `lifecycle='active'`, `expires_at`, and encrypted state envelope via `crypto.Seal` using master key and AAD `("auth_sessions", id, account_id)`.
    - `GetInteractiveSessionDecrypted`: retrieves row, validates `lifecycle == 'active'` and `expires_at > now`, and decrypts opaque connector state via `crypto.Open` verifying AAD. Expired or non-active sessions return sentinel error.
    - `ConsumeInteractiveSession`: marks row `consumed` and zeroes/clears ciphertext and nonce.
  - Refresh marker lifecycle:
    - `CreateRefreshMarker`: inserts pre-exchange marker with `kind='refresh'`, `lifecycle='refresh_in_progress'`, expected revision, and NULL envelope/expiry (enforcing at most one in-progress/uncertain marker per account).
    - `QuarantineRefreshMarker`: transitions `refresh_in_progress` to `uncertain` with non-secret quarantine reason (`ambiguous_result`, `cancelled_after_call`, `persistence_failed`, `restart_in_progress`) and current credential revision; never stores provider diagnostics or tokens.
    - `ClearRefreshMarker`: deletes or clears marker only when invocation was provably never initiated.
    - `ResolveRefreshAndReplaceCredentials`: atomic transaction under `BEGIN IMMEDIATE` checking expected credential revision, replacing account credentials via CAS, and clearing the account's refresh marker. Stale revision fails without mutating credentials or clearing quarantine.
  - Expiry and recovery:
    - `CleanupExpired`: updates expired interactive sessions (`expires_at <= now` and `lifecycle = 'active'`) to `consumed` and clears ciphertext/nonce. Quarantined (`uncertain`) rows are strictly exempt from TTL cleanup.
    - `RecoverAuthSessions`: startup recovery pass transitioning any unfinalized `refresh_in_progress` rows to `uncertain` with `quarantine_reason = 'restart_in_progress'`.
- Explicit limits:
  - Connector invocation, HTTP networking, and OAuth token protocol handling are outside scope (M3-035/M3-036).
  - Cross-process concurrency mutexes and auth coordinator logic are outside scope (M3-035).
  - CLI commands are outside scope (M3-036).
  - No plaintext secrets, tokens, or master keys in database, WAL, errors, or logs.

## Acceptance

- [x] Schema migration 5 creates `auth_sessions` and indices atomically, enforcing kind/envelope/expiry constraints and the partial unique index on `(account_id)` for `lifecycle IN ('refresh_in_progress', 'uncertain')`.
- [x] Interactive session encrypted state survives database reopen only while valid and decryptable with external master key; expired or consumed sessions cannot be decrypted or continued.
- [x] Opaque interactive state envelopes use authenticated encryption with AAD bound to table, session ID, and account ID; cross-account or tampered reads fail closed.
- [x] Refresh markers enforce at most one in-progress or uncertain refresh per account via the partial unique index; concurrent second refresh marker creation fails.
- [x] Refresh resolution with credential replacement updates credentials and clears the marker atomically in one transaction; stale credential revision fails atomically and leaves marker quarantined.
- [x] TTL cleanup consumes expired interactive sessions and removes encrypted state; `uncertain` quarantined rows are strictly exempt from TTL cleanup.
- [x] Startup recovery converts unfinalized `refresh_in_progress` rows to `uncertain` with reason `restart_in_progress` without replaying or clearing them.
- [x] Plaintext session states or secrets never appear in unencrypted database columns, WAL files, error strings, or logs.
