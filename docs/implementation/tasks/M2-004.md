# M2-004 — Implement invocation-scoped runtime services

## Outcome

An attempt receives only its selected instance/account services, with credentials owned by runtime. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Request context](../CONTRACT.md#execution-request), [scoped services](../CONTRACT.md#usage-and-scoped-runtime-services), [M2 binding](../M2-BINDING.md#component-lifecycle-and-connector-api).
- `internal/core/connector.go` InvocationServices, CredentialAccess, HTTPDoer; `internal/core/dispatch.go` AttemptScope; `cmd/gateway/main.go` secret loading; `internal/connector/responses/transport.go` credential/transport construction.

## Scope

- Implement the agreed service boundary and an in-memory environment-backed provider for selected credentials, transport and safe logging.
- Keep invocation context immutable and distinct from client Metadata; no arbitrary account lookup, global service locator, database handle or authentication persistence.

## Acceptance

- [x] An invocation cannot retrieve another instance/account credential or override selection using headers/extensions.
- [x] Cancellation reaches service calls; missing credentials fail explicitly; diagnostic formatting/logging does not disclose synthetic secrets.
- [x] Concurrent service scopes remain isolated and require no hidden global state.

## Completion Evidence

- Implemented `EnvironmentServices` in `internal/core/services.go` (`NewEnvironmentServices`, `ForAttempt`): creates attempt-scoped `InvocationServices` with isolated credentials, configured `HTTPDoer` transport (returning `ErrServiceUnavailable` when unconfigured), and redacting `slog.Logger`.
- Direct proofs in `internal/core/services_test.go`: `TestEnvironmentServicesAreAccountScopedCancellableAndRedacted`, `TestEnvironmentServicesMissingCredentialIsExplicit`, `TestInvocationTransportReceivesRequestCancellation`, `TestInvocationCredentialAndLoggerShareSnapshot`, and `TestCredentialBytesRedactedByTextAndJSONHandlers` verify concurrent account isolation, env mutation snapshot preservation, cancelled context propagation, explicit missing credential errors, and logger redaction across text/json handlers.
- Redaction boundary: exact substring match on configured account secret values in messages, attribute keys, group names, string values, and `KindAny` stringified/byte-slice representations. No guarantees for secrets encoded/transformed (e.g., base64/hex/URL-encoded) or nested inside structured byte fields/fixed arrays (`[N]byte`); does not provide general secret-proof logging.
- `go test -race -count=1 ./internal/core/...`, `./scripts/check.sh`, and `git diff --check` pass cleanly. No external credentials or live calls.
