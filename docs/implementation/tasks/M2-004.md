# M2-004 — Implement invocation-scoped runtime services

## Outcome

An attempt receives only its selected instance/account services, with credentials owned by runtime. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Implement the agreed service boundary and an in-memory environment-backed provider for selected credentials, transport and safe logging.
- Keep invocation context immutable and distinct from client Metadata; no arbitrary account lookup, global service locator, database handle or authentication persistence.

## Acceptance

- [ ] An invocation cannot retrieve another instance/account credential or override selection using headers/extensions.
- [ ] Cancellation reaches service calls; missing credentials fail explicitly; diagnostic formatting/logging does not disclose synthetic secrets.
- [ ] Concurrent service scopes remain isolated and require no hidden global state.
