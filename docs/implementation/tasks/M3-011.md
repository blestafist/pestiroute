# M3-011 — Implement persistent account lifecycle

## Outcome

Implement persistent account lifecycle in SQLite storage, providing create, get, list, and enable/disable operations for connector-owned accounts while preserving historical identity, safe metadata, and referential retention for credentials, requests, and attempts. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Implement a pure Go SQLite account repository in `internal/storage/sqlite` (`accounts.go` and `accounts_test.go`), keeping SQL persistence outside of Core.
- Model `Account` domain entity matching schema v2 columns: `ID string`, `Connector string`, `Enabled bool`, `CreatedAt time.Time`, `UpdatedAt time.Time`.
- Implement account repository operations on `*sql.DB` opened with `sqlite.Open`:
  - `Create(ctx context.Context, account Account) (Account, error)`: inserts new account row with UTC Unix-millisecond timestamps (`INTEGER NOT NULL`). Requires non-empty `ID` and `Connector`. Rejects duplicate IDs via primary key constraint.
  - `Get(ctx context.Context, id string) (Account, error)`: queries account by ID; returns typed `ErrAccountNotFound` when row does not exist.
  - `List(ctx context.Context, filter AccountFilter) ([]Account, error)`: queries accounts matching optional filter (`Connector string`, `Enabled *bool`) sorted deterministically (e.g. `created_at ASC, id ASC`); returns safe metadata only.
  - `SetEnabled(ctx context.Context, id string, enabled bool) (Account, error)`: standard operational lifecycle path for retirement/activation. Atomically updates `enabled` flag and `updated_at` (UTC Unix ms) via `UPDATE ... RETURNING`. Preserves account identity, credentials, and historical `attempts.account_id` references. Returns updated record or typed `ErrAccountNotFound`.
  - `Delete(ctx context.Context, id string) error`: operator purge operation. Enforces referential integrity via SQLite foreign keys: blocked if credentials exist (`ON DELETE RESTRICT`); if no credentials reference it, deletion nullifies `attempts.account_id` via `ON DELETE SET NULL` per schema v4 while retaining attempt and usage rows.
- Keep repository boundary clean:
  - Repository exposes safe metadata; never accesses, exposes, or decrypts credentials.
  - Core remains standard-library only and does not import database packages or concrete Connectors.
- Explicit limits:
  - Credential persistence/CAS belongs to [M3-010](M3-010.md).
  - CLI management commands belong to [M3-014](M3-014.md) and [M3-015](M3-015.md).
  - Supplying persistent credentials to runtime invocations belongs to [M3-017](M3-017.md).
  - Model/route admission authorization belongs to [M3-019](M3-019.md).
  - Dynamic discovery, load balancing, and health circuit breakers remain outside this card.

## Acceptance

- [x] Account creation succeeds with valid ID, connector, and initial enabled state, persisting integer UTC Unix-millisecond timestamps that survive `db.Close()` and reopen with `sqlite.Open`.
- [x] Duplicate account IDs are rejected by SQLite primary key constraint; empty ID or empty connector returns validation error before query execution.
- [x] `Get` retrieves existing account with exact fields; querying nonexistent ID returns typed `ErrAccountNotFound`.
- [x] `List` returns accounts matching filter (all, by connector, or by enabled flag) in deterministic order; returns an empty non-nil slice when no matches exist.
- [x] `SetEnabled` atomically toggles enabled state (enable/disable), updates `updated_at` timestamp, and preserves historical `created_at` and `id`; nonexistent ID returns typed `ErrAccountNotFound`.
- [x] Disabling an account (`enabled = false`) retains historical rows, does not invalidate credentials, and preserves `attempts.account_id` references across restarts.
- [x] Referential retention and purge constraints: deleting an account referenced by existing credentials fails under SQLite foreign key constraint (`ON DELETE RESTRICT`); deleting an account without credentials sets `attempts.account_id` to NULL (`ON DELETE SET NULL`) while leaving attempt and usage rows intact.
- [x] Concurrency: concurrent `SetEnabled` calls preserve monotonic `updated_at` ordering and immutable `created_at`/`id`; concurrent `Delete` and `SetEnabled` resolve deterministically without corrupting repository state.
- [x] Account records, lists, errors, and string formats contain only safe metadata and never expose decrypted credential secrets or master key material.
- [x] Core package dependencies remain untouched; repository has no dependencies on concrete Protocol Adapters or Connectors.
