## Scope

- In `internal/connector/antigravity/stream.go`:
  - Extend candidate part parsing in `stream.consume` to recognize `functionCall` (`name` string, `args` JSON object/raw message, optional `id` string).
  - Reject if `part.Thought != nil && *part.Thought` or `len(part.ThoughtSignature) != 0` (thought/reasoning signature constraints remain fail-closed per M10-006).
  - Emit Responses streaming events for each tool call:
    - Allocate distinct item ID (`fc_...`) and call ID (`call_...` or preserving candidate `id` if present).
    - Emit `response.output_item.added` with `output_index`, `item.type = "function_call"`, `name`, `call_id`, `arguments = ""`, `status = "in_progress"`.
    - Emit `response.function_call_arguments.delta` with serialized arguments.
    - Emit `response.function_call_arguments.done` with complete serialized arguments.
    - Emit `response.output_item.done` with `item.status = "completed"`.
  - Support interleaved text and single or multiple/parallel `functionCall` items across candidates with distinct sequential `output_index` values.
  - Include completed function call items alongside messages in the terminal `response.completed` output list.
  - Enforce bounded memory retention (max 1 MiB across text and tool arguments) and valid UTF-8; reject oversized or malformed arguments.
- In `internal/connector/antigravity/execute_test.go` and `internal/connector/antigravity/testdata/`:
  - Replace the former stub test that rejected `functionCall` with tests verifying valid streaming translation:
    - Single tool call with arguments emitting full lifecycle events and final completion item.
    - Parallel / multiple tool calls in stream preserving distinct IDs, argument values, and sequential output indices.
    - Interleaved text and tool call items in single response.
    - Rejection of malformed JSON arguments, empty name, oversized argument payloads (>1 MiB), and presence of thought signatures.
    - Cancellation mid-stream releases reader without buffering whole response.
  - Add/update synthetic test fixture(s) in `testdata/` with manifest SHA-256 integrity update (`manifest.json`) per M10 synthetic fixture provenance rules.
- In `docs/implementation/M10-BINDING.md` / `docs/implementation/M10-TOOL-BINDING.md`:
  - Synchronize binding docs to record the implemented candidate streaming functionCall translation scope and its offline synthetic evidence ceiling.
- Explicit limits:
  - No live network requests or provider credentials.
  - Signature-dependent continuation and multi-turn session state remain BLOCKED per M10-006.
  - Core contract and non-Antigravity packages remain unchanged.
