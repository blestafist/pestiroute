## Outcome

Build an evidence-scoped compatibility and execution safety matrix for the candidate Claude Code subscription backend, including tool execution models, reasoning, statefulness/affinity, cancellation, and retry safety. The matrix provides planning evidence for feasibility assessment without claiming runtime support or altering architecture. ## Scope

- Add a capability and execution safety matrix to `docs/references/CLAUDE_CODE_CONNECTOR_RESEARCH.md` evaluating the pinned Claude Code target.
- Assess capabilities against CONTRACT identifiers: `llm.streaming`, `llm.tools`, `llm.tools.parallel`, `llm.reasoning`, `llm.structured_output`, `llm.vision`, `usage.exact`, and `auth.oauth`.
- For each capability, record evidence, version/account scope, and status (`supported`, `unsupported`, or `unknown`); missing or unproven runtime behavior must remain `unknown`.
- Distinguish client-owned orchestration (CLI tool execution, prompt history, multi-turn loops) from upstream backend inference capabilities.
- Assess statefulness, session affinity, prompt caching, cancellation propagation, and error classifications with retry dispositions (`Retryable`, `RetryDisposition`, `RetryAfter`).
- Confirm that ambiguous delivery (post-dispatch disconnect/timeout) is not classified as safely retryable and that post-commit fallback remains prohibited under CONTRACT.
- Identify any structural gaps that would require an ADR; do not modify contracts, code, or runtime behavior.
- Strictly offline documentation research: zero live provider calls, zero credential acquisition/login, zero binary reverse engineering/decompilation, and zero legal determinations.
