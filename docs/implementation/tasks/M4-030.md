## Scope

- Enforce the accepted M4-029 unsupported reasoning policy across all incoming translation input variants:
  - Top-level `reasoning` controls (`effort`, `summary`, or unrecognized reasoning properties) reject locally with `invalid_request`.
  - Input items of `type: "reasoning"` (including summary, encrypted content, or provider state) reject locally with `invalid_request`.
  - Assistant/user/developer message content parts of `type: "reasoning_text"`, `type: "thinking"`, `type: "redacted_thinking"`, or other reasoning types reject locally with `invalid_request`.
  - Attempts to replay Anthropic thinking/signature blocks or synthetic provider state across multi-turn history reject locally before provider dispatch.
  - Maintain accepted `include: ["reasoning.encrypted_content"]` as a harmless request hint that yields no reasoning output state or synthetic ciphertext.
- All unsupported reasoning inputs fail closed locally before any upstream network dispatch.
- Preserve admitted payload immutability; Core and Adapter boundaries remain untouched with zero reasoning parsing or provider branching.
- Explicit limits: Do not implement reasoning streaming or provider thinking block synthesis (ruled out by M4-029). Stream tool rounds and multi-turn execution belong to M4-031.

## Acceptance

- [x] Every request containing top-level `reasoning` controls, history items (`type: "reasoning"`), or content parts (`reasoning_text`, `thinking`, etc.) fails closed locally with `invalid_request` before upstream dispatch.
- [x] Attempts to replay Anthropic thinking/signature/redacted blocks or synthetic provider state in conversation history reject locally.
- [x] Admitted payloads remain immutable; valid non-reasoning requests (including `include: ["reasoning.encrypted_content"]`) continue to translate unmodified.
- [x] Core routing and contract remain untouched; no reasoning structures or provider branches exist in Core.
