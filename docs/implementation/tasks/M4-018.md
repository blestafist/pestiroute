## Outcome

- Existing translation request parser in `internal/connector/anthropic/translate.go` and tests in `internal/connector/anthropic/translate_test.go`.

## Scope

- Map fixture-verified Responses `tool_choice` and `parallel_tool_calls` in `internal/connector/anthropic/translate.go` to Anthropic Messages `tool_choice` structures (`{"type": "auto"}`, `{"type": "any"}`, `{"type": "tool", "name": "..."}`, with optional `"disable_parallel_tool_use": true`).
- Support valid Responses API choices:
  - String `"auto"` maps to Messages `{"type": "auto"}`.
  - String `"required"` maps to Messages `{"type": "any"}`.
  - String `"none"` omits `tools` and `tool_choice` from the backend Messages request to prevent tool use while preserving text completion.
  - Flat function object `{"type": "function", "name": "fn_name"}` maps to Messages `{"type": "tool", "name": "fn_name"}`.
- Map `parallel_tool_calls`:
  - When `parallel_tool_calls: false`, set `"disable_parallel_tool_use": true` in Messages `tool_choice` (generating implicit `{"type": "auto", "disable_parallel_tool_use": true}` if `tool_choice` was omitted by client).
  - When `parallel_tool_calls: true` or omitted, leave `"disable_parallel_tool_use"` omitted or false on wire; explicit false and omission are not conflated.
- Enforce fail-closed validation before dispatch:
  - Reject `tool_choice` when `tools` is absent or empty.
  - Reject named `tool_choice` referencing a function name not defined in `tools`.
  - Reject Chat Completions nested `{"type": "function", "function": {"name": "..."}}` shape.
  - Reject non-boolean or null `parallel_tool_calls`, unknown `tool_choice` string/object shapes, and extra unrecognized fields.
  - Preserve admitted request payload bytes unmodified.
- Keep tool result/call history (M4-019), streamed tool calls (M4-020), and tool execution strictly out of scope.

## Acceptance

- [x] Unavailable named tools, `tool_choice` without tools, Chat Completions nested function choice, invalid parallel types, and unrepresentable forms fail before dispatch with client-safe `*core.GatewayError` (Category `invalid_request`) and zero upstream calls.
