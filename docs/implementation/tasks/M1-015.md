# M1-015 — Pre-commit failure behavior

## Outcome

Rejected or failed upstream attempts produce one correct client response without hidden replay. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-001 integration, [errors](../CONTRACT.md#error-model), [Connector](../CONTRACT.md#connector-contract), [early error/replay tests](../TESTING.md#testing-levels).

## Scope

- Cover native auth rejection, 429, unavailable status, connection failure and ambiguous pre-head drop through the assembled gateway.
- Fix classification/status preservation at the owning boundary; retain native upstream error bytes and sanitized gateway errors.
- Stop before fallback implementation or late-stream failure handling.

## Acceptance

- [x] Upstream rejection status/body survive unchanged with failure metadata available before Head handoff.
- [x] Pre-head transport failure emits one client-safe gateway error; ambiguous delivery is not marked safe.
- [x] Every case has at most one upstream inference attempt, including Retry-After/transient responses; missing credentials never reach upstream.

## Verification

From root run `go test -race -v -run 'TestResponses.*(Reject|TransportError|PreCommit)' ./cmd/gateway/...`, `go test -race ./internal/connector/responses/...`, and `./scripts/check.sh`. Use `fakeupstream.Server.RequestCount()`, status and body comparisons, and classified GatewayError assertions; do not infer absence of retry solely from the final HTTP status.

## Open Questions / Blocker

None. Controllable via existing `fakeupstream.Response{Status, Body, Drop}` and `Server.RequestCount()`, plus connector and adapter error classification tests.

## Completion Evidence

Implemented native rejection classification for 401/403/429/503 at Connector Head, including parsed delta-seconds/HTTP-date Retry-After for transient statuses; retry disposition remains unknown. Rejection response status/body and Retry-After pass through the Adapter unchanged. Gateway integration verifies 401/403/429/503 classification and one upstream request per case. Both an upstream drop before response headers and a refused connection produce one sanitized 503 gateway error with unknown retry disposition, without replay. Startup configuration checks in the existing suite verify an unset credential prevents configured inference startup.
