# M12-010 — Visual polish, responsive ergonomics, accessibility audit, and E2E regression

## Outcome

Validate and refine responsive viewport adaptations, keyboard navigation paths, ARIA announcements, dark/light contrast ratios, and end-to-end browser workflows in headless Chromium against the packaged gateway release binary to ensure zero visual regressions or workflow breakage across the redesigned WebUI. Tracked in [TASKS](../TASKS.md#m12--webui) under [M12](../ROADMAP.md#m12--webui).

## Scope

- Refine responsive ergonomics in `web/src/style.css` and `web/src/App.tsx`:
  - Narrow/mobile viewport (<768px): navigation adapts cleanly (compact bar or labeled scroll menu), data tables provide responsive scroll regions or card layouts without horizontal page blowout, modal dialogs fit within viewport bounds.
  - Desktop viewport (>=1024px): layout max-width constraint, balanced multi-column forms and cards.
- Accessibility audit:
  - Contrast ratios: verify text and UI controls meet WCAG 2.1 AA (4.5:1 for normal text, 3:1 for large text/badges/controls) in both light and dark themes.
  - Keyboard navigation: visible focus rings on all interactive elements, modal focus trap and Escape restoration.
  - Screen reader attributes: verify semantic landmarks (`header`, `nav`, `main`, `footer`), headings hierarchy, live regions (`role="status"`, `role="alert"`), and accessible form labels.
- Packaged E2E browser regression:
  - Run the complete packaged Chromium E2E test suite against a live compiled gateway binary with embedded redesigned UI assets.
  - Verify complete operator lifecycle: authentication, account/credential creation, restricted key issuance, one-time secret copy, inference, usage ledger, revocation, and logout.
- Explicit limits:
  - Do not modify gateway backend code, database schema, or admin API endpoints.
  - Preserve behavioral assertions in `operator.pw.ts`; update selectors and add the named revoke confirmation step when the accepted UX changes.

## Acceptance

- [ ] All six operator screens render responsively at 375px, 768px, and 1440px viewports without horizontal page overflow.
- [ ] Keyboard navigation (Tab, Shift+Tab, Escape, Enter) operates all interactive components, dialogs, and forms with high-contrast visible focus rings.
- [ ] Both light and dark themes satisfy WCAG 2.1 AA contrast requirements across all text, status badges, and controls.
- [ ] Unit and component test suite passes: `npm --prefix web test`.
- [ ] Frontend asset build succeeds: `npm --prefix web run build`.
- [ ] Complete packaged Chromium E2E passes against the release binary: `./scripts/release-build.sh --with-ui bin/gateway && M12_E2E_GATEWAY="$PWD/bin/gateway" npm --prefix web run e2e`.
