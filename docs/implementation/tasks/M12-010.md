## Scope

- Responsive ergonomics across all six screens (`Overview`, `Connections`, `Keys & Policies`, `Usage`, `Routing`, `Settings & Diagnostics`) in `web/src/style.css` and `web/src/App.tsx`:
  - Narrow/mobile viewports (420px, 375px): navigation collapses or wraps cleanly without overlapping controls, form controls and actions stack cleanly, data tables provide bounded horizontal scroll regions without page blowout, modal dialogs fit within viewport margins.
  - Tablet/intermediate viewport (760px): responsive grid wrapping for route topology cards, credential forms, and usage ledger filters.
  - Desktop viewports (1024px, 1440px): content max-width constraints, balanced multi-column layout, aligned tabular ledger and badges.
- Accessibility and theme audit:
  - WCAG 2.1 AA contrast audit (>= 4.5:1 for normal text, >= 3:1 for large text/controls/badges) across both light and dark themes for all six screens.
  - Interactive states: visible high-contrast focus rings on all focusable elements (links, buttons, inputs, selects).
  - Dialog accessibility: focus trapping, initial focus placement, and Escape key restoration on modals (`issuedSecret` modal, named revoke confirmation).
  - ARIA and semantic markup: landmarks, live status regions, form label associations.
- Explicit real packaged-browser E2E gate:
  - Build release gateway with embedded UI (`./scripts/release-build.sh --with-ui bin/gateway`). Bounded provisioning of pinned Node 24 (under `/tmp/pestiroute-lane.hGmeZS/antigravity` or local environment) and Playwright Chromium is permitted if host toolchain requires it.
  - Execute complete packaged Chromium E2E (`M12_E2E_GATEWAY="$PWD/bin/gateway" npm --prefix web run e2e`) exercising live operator lifecycle: authentication, account/credential creation, restricted key issuance, one-time secret capture, live inference, usage ledger reflection, revocation confirmation, and unauthenticated logout.
  - Run offline Python test harness (`python3 scripts/e2e-m12-webui.py`).
- Explicit limits:
  - Do not modify gateway Core routing, SQLite schema, or Admin API contracts.
  - Real browser verification must record actual check evidence; completion cannot rely on deferred host assumptions.
