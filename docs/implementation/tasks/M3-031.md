# M3-031 — Expose durable usage through the local CLI

## Outcome

Expose durable usage and attempt records through the local CLI (`gateway admin usage`). This provides operational visibility into admitted requests, individual upstream attempts, token reservations, nullable observed usage, and aggregate charges across keys, accounts, and time windows without starting a network listener or exposing secret values. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Storage queries in `internal/storage/sqlite`:
  - Filtered request queries: filter by virtual key ID, model, route ID, state, and `since`/`until` accepted timestamps, with bounded `limit` (max 500, default 50) and `offset` pagination, ordered deterministically (`accepted_at ASC, id ASC`).
  - Filtered attempt queries: filter by request ID, account ID, connector, state, and inclusive `since`/`until` timestamps. Effective attempt time is `dispatched_at`, else `finished_at`, else the parent request's `accepted_at` for pending attempts without either timestamp; this same effective time drives filtering and ascending ordering, with attempt ID as the deterministic tie-breaker. Pagination is bounded by `limit` and `offset`.
  - Filtered usage aggregate query: compute totals for input, output, reasoning, and cached tokens, as well as token reservations (estimated vs actual vs effective charge) within an optional key, account, or time window.
- CLI subcommands in `cmd/gateway`:
  - Add `gateway admin usage` subcommands dispatched under the existing admin CLI boundary (`admin.go`):
    - `gateway admin usage requests [--key ID] [--account ID] [--since RFC3339] [--until RFC3339] [--limit N] [--offset N] [--json]`
    - `gateway admin usage attempts [--request ID] [--account ID] [--since RFC3339] [--until RFC3339] [--limit N] [--offset N] [--json]`
    - `gateway admin usage summary [--key ID] [--account ID] [--since RFC3339] [--until RFC3339] [--json]`
  - Standard admin `--db` and `--master-key` flags and validation (fail-closed master key verification via `crypto.LoadMasterKey`, `sqlite.Open` connection pragmas, and schema version checking).
  - Nullable token counter presentation: format unobserved or unknown token counters as `-` / `unknown` in tabular/text output and `null` in JSON output; never coerce unknown counters to `0`.
  - Distinguish observed token counters from estimated tokens and effective charges; display multi-attempt breakdowns so individual fallback/retry attempts remain distinct.
  - Timestamps rendered in UTC RFC-3339 format.
  - Fail-closed error handling: exit non-zero on invalid arguments, unmigrated schemas, missing database/key, or malformed time filters without printing raw keys or secrets.
- Explicit limits:
  - No prompt, completion, tool call, or reasoning text is persisted or exposed.
  - Virtual keys are queried and displayed only by virtual key ID (`id`), never by raw secret or key hash.
  - Account deletion or disabling does not cascade-delete or hide historical usage rows.
  - No remote HTTP API, web UI, or pricing computation is introduced.
  - Core runtime (`internal/core`) remains untouched.

## Acceptance

- [x] `gateway admin usage requests`, `attempts`, and `summary` run against real file-backed SQLite databases via `runAdmin` with stream injection (`stdout`, `stderr`), returning deterministic results that remain identical after closing and reopening the database.
- [x] Nullable token counters (`input_tokens`, `output_tokens`, `reasoning_tokens`, `cached_tokens`) display distinctly as unknown/null when unrecorded; detail tokens (reasoning, cached) are not double-counted into input/output totals.
- [x] Multi-attempt requests list individual attempts with distinct ordinals, accounts, and error reasons without double-counting settled charges.
- [x] Filtering by key, account, and RFC-3339 time ranges (`--since`, `--until`) and pagination (`--limit`, `--offset`) are bounded, stable, and deterministic; disabled or deleted accounts/keys do not omit historical records.
- [x] `--json` produces valid JSON output with strict UTC timestamps and nulls for absent/unknown counters; text mode outputs structured columns without exposing secrets or master keys.
- [x] Usage help (`gateway admin usage --help`) and invalid flag/argument checks exit cleanly with non-zero status without opening database or master-key files.
