# M12-005 — Integrate the accepted admin API and authentication

## Outcome

Connect the WebUI shell and screens to the accepted administrative HTTP API (`/admin/v1/*`) using an isolated client and memory-only token authentication. Replaces fixtures as the default runtime mode while preserving an explicit opt-in mock mode. Delivers the API integration milestone for [M12-WEBUI](../M12-WEBUI.md) tracked in [TASKS](../TASKS.md#m12--webui).

## Scope

- `web/src/api.ts` (or isolated client module in `web/src/`):
  - Typed HTTP client consuming `/admin/v1` routes:
    - Status & routing snapshot: `GET /admin/v1/status`
    - Accounts: `GET /admin/v1/accounts`, `POST /admin/v1/accounts`, `GET /admin/v1/accounts/{account_id}`, `PUT /admin/v1/accounts/{account_id}/enabled`
    - Credentials: `POST /admin/v1/accounts/{account_id}/credentials`, `PUT /admin/v1/accounts/{account_id}/credentials/{credential_id}`
    - Policies: `GET /admin/v1/policies`, `POST /admin/v1/policies`, `GET /admin/v1/policies/{policy_id}`, `PUT /admin/v1/policies/{policy_id}`
    - Keys: `GET /admin/v1/keys`, `POST /admin/v1/keys`, `GET /admin/v1/keys/{key_id}`, `DELETE /admin/v1/keys/{key_id}`, `PUT /admin/v1/keys/{key_id}/policy`
    - Usage: `GET /admin/v1/usage/requests`, `GET /admin/v1/usage/attempts`, `GET /admin/v1/usage/summary`
    - Auth coordinator: `POST /admin/v1/auth/sessions`, `POST /admin/v1/auth/sessions/{session_id}/continue`, `POST /admin/v1/auth/accounts/{account_id}/refresh`
  - DTO types matching `docs/api/admin.openapi.yaml` and `docs/implementation/M11-BINDING.md`.
  - Standard error envelope parsing for `{ error: { code, message, request_id } }`.
- `web/src/App.tsx` (and screen components):
  - Switch default data source from fixtures to the real API client.
  - Memory-only operator session: bearer token held in memory only; unauthenticated view prompts for token; logout clears token and view cache; no tokens or secrets in `localStorage`, `sessionStorage`, cookies, or URL search parameters.
  - Error state handling: 401 transitions to unauthenticated/expired state; 409 CAS revision conflicts preserve operator form inputs with a refresh action; 403/404/413/500/503 render actionable alerts with request/correlation IDs.
  - Retain explicit opt-in mock mode with visible "DEMO DATA — NOT LIVE" banner; default is live API client.
- `web/src/App.test.tsx` (and dedicated tests):
  - Unit/component tests verifying API client calls, bearer auth header injection, in-memory token lifecycle, logout cleanup, 401 unauthenticated handling, 409 CAS conflict handling with input preservation, and absence of token/secret storage in browser storage APIs.
- Out of scope: Go asset embedding and static mount wiring (M12-006); browser E2E with real gateway binary (M12-006); modifications to Go packages (`internal/admin`, `cmd/...`); provider-specific calls or external network requests.
