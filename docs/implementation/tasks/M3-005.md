## Scope

- Add the migration engine in `internal/storage/sqlite` applying ordered migrations atomically using short transactions on `*sql.DB`.
- Create and maintain the `schema_migrations` journal table (`version INTEGER PRIMARY KEY`, `applied_at TEXT NOT NULL`) recording each applied migration in the same transaction as its statements.
- Support fail-closed version checking: verify current database schema version against supported code migrations and refuse unsupported newer schemas before serving.
- Ensure rollback on error, context cancellation handling, and bounded lock/resource release without leaking database locks.
- Keep scope bounded to the migration engine, version validation, and baseline/test schema; entity tables for accounts/credentials (M3-006), virtual keys/policies (M3-007), and requests/attempts (M3-008) remain in their respective tasks.

## Acceptance

- [x] A fresh database initializes `schema_migrations` and applies ordered migrations atomically, recording version and UTC timestamp.
- [x] Re-running migrations on an up-to-date database is an idempotent no-op with no schema changes or duplicate journal entries.
- [x] A migration step containing an invalid SQL statement rolls back atomically, leaving the database and journal at the previous consistent version.
- [x] Opening or migrating a database with an unsupported future schema version fails closed with an explicit error without modifying data.
- [x] Context cancellation before or during migration aborts execution, rolls back in-flight transactions, and releases connection resources.
- [x] Migrations execute against connections opened via `sqlite.Open` preserving WAL, `synchronous=FULL`, foreign keys, and 500 ms busy timeout.
