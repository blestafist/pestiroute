## Scope

- Implement offline state machine in `internal/connector/claudecode`:
  - `start`: generate PKCE verifier/challenge (S256), state parameter, and authorization URL in `AuthUserAction.VerificationURI`.
  - `continue`: accept pasted callback URL via `AuthRequest.CallbackInput`; compare raw scheme, authority, and escaped path byte-for-byte (without normalization) against the absolute configured redirect URI (which has no query, fragment, or userinfo); strictly decode query and require exactly one non-empty `code` and `state`; reject duplicate, malformed, OAuth-error, or unexpected parameters; compare decoded state byte-for-byte with protected expected state before synthetic exchange.
  - `refresh`: atomic token refresh using stored refresh token without replaying ambiguous exchanges.
- Explicit limits: Offline synthetic implementation only in `internal/connector/claudecode`. Generic runtime plumbing is owned by M7-016. No live calls, no real credential storage, no browser automation.

## Acceptance

- [ ] Generates valid PKCE S256 challenge and verifier in initial start step with authorization URL in `UserAction.VerificationURI`.
- [ ] Opaque continuation state strictly protects verifier and session state without exposing secrets.
- [ ] Safely parses pasted callback URL from `AuthRequest.CallbackInput`, enforces exact raw redirect components and decoded state, requires exact-one code/state, and rejects duplicates, malformed encoding, errors, and unexpected parameters.
- [ ] Expiry and tokens parsed accurately from synthetic response fixtures.
- [ ] Safe non-replaying token refresh state transitions.
