# M1-012 — Incremental native SSE Connector

## Outcome

The Connector forwards SSE incrementally and reports terminal outcome separately from native bytes. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Read First

- M1-009 Connector, M1-004 observer limits, [frames](../CONTRACT.md#execution-response-and-streamframe), [HTTP streaming](../STACK.md#http-and-streaming), fake upstream Step controls.

## Scope

- Extend the native Connector with bounded incremental SSE outcome observation and opaque Body delivery.
- Observe only the terminal/error metadata needed for lifecycle; preserve bytes independently of parser boundaries and keep usage unknown unless actually extracted.
- Stop before HTTP flushing, general Responses translation, tool execution or exact accounting.

## Acceptance

- [ ] First Body is consumable while a later upstream step is gated; ordering and bytes are unchanged.
- [ ] Completed, failed, incomplete, malformed/truncated and missing-terminal streams receive truthful outcomes; transport EOF alone is not successful provider completion.
- [ ] Split UTF-8/delimiters, multiline events and events beyond Scanner's default limit work within documented bounds; over-limit observation has explicit bounded behavior.

## Verification

From root run gated Connector streaming/outcome tests with deterministic gates, then `./scripts/check.sh`. Record focused commands and buffer bounds when promoting. No sleeps as the sole first-chunk assertion.

## Open Questions / Blocker

Use M1-004's event/observation and compression choices; do not weaken native byte preservation.
