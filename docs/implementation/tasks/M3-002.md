# M3-002 — Validate and pin the SQLite driver

## Outcome

Validate and pin the SQLite driver (`modernc.org/sqlite`) with a temporary file-backed integration spike and reusable open/close seam in `internal/storage/sqlite`. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Implement driver validation and minimal reusable connection open/close seam in package `internal/storage/sqlite`.
- Pin `modernc.org/sqlite` (version `v1.60.1`) and transitive dependencies in `go.mod`/`go.sum` without CGO requirement (`CGO_ENABLED=0`).
- Configure required SQLite pragmas on every connection: WAL mode (`journal_mode=WAL`), full synchronous durability (`synchronous=FULL`), foreign keys (`foreign_keys=ON`), and a bounded busy timeout (`busy_timeout`).
- Establish temporary file-backed integration tests covering database reopen, WAL/foreign-key verification, concurrent write contention under bounded busy timeout, context cancellation during query/contention, and isolation (no transaction spanning simulated network wait).
- Update CI workflow `.github/workflows/ci.yml` to download dependencies before `./scripts/check.sh`; keep `GOPROXY=off GOSUMDB=off` enforcement inside `scripts/check.sh`.
- Limits: spike and minimal open/close seam only. Do not implement entity tables/migrations (deferred to M3-005–M3-010) or introduce SQLite imports into `internal/core`.

## Acceptance

- [x] Temporary file-backed integration tests in `internal/storage/sqlite` demonstrate reopen integrity, WAL mode, `foreign_keys=ON` on every pool connection, bounded busy handling, and cancellation without leaked locks.
- [x] Concurrent write contention obeys the configured busy timeout and fails deterministically; no transaction spans simulated network wait.
