# M11-003 — Expose redacted status topology and ledger views

## Outcome

Expose authenticated, redacted status/topology snapshot (`GET /admin/v1/status`) and filterable/paginated usage ledger views (`GET /admin/v1/usage/requests`, `GET /admin/v1/usage/attempts`, `GET /admin/v1/usage/summary`) conforming to the normative binding and OpenAPI specification. Delivers the read-only operational visibility step for [Administrative HTTP API](../M11-ADMIN-API.md) in [TASKS.md](../TASKS.md#m11--administrative-http-api) under [ROADMAP.md](../ROADMAP.md#m11--administrative-http-api).

## Scope

- Implement HTTP handlers and JSON serializers in `internal/admin` for:
  - `GET /admin/v1/status`: returns gateway version, readiness status (`ready`, `unavailable`, `unknown`), components (id, kind, implementation, health, protocols, capabilities map), and effective routes (protocol, mode, model, adapter_id, connector_id, account_id).
  - `GET /admin/v1/usage/requests`: paginated list of requests with nested bounded attempts; query filters `key_id`, `account_id`, `since`, `until`, `limit` (default 50, max 500), `offset` (>=0). Emits `{ items, limit, offset, total }`.
  - `GET /admin/v1/usage/attempts`: paginated list of attempts with nullable usage metrics and reservations; query filters `request_id`, `account_id`, `since`, `until`, `limit` (default 50, max 500), `offset` (>=0). Emits `{ items, limit, offset, total }`.
  - `GET /admin/v1/usage/summary`: aggregate summary of requests, attempts, estimated/actual tokens, effective charges, and nullable input/output/reasoning/cached tokens; query filters `key_id`, `account_id`, `since`, `until`. Rejects pagination parameters (`limit`, `offset`) with 400.
- Connect status/topology provider and ledger storage to `internal/admin.Config` and wire in `cmd/gateway/main.go`.
- Enforce strict redaction: omit credentials, secret references, file paths, endpoints, and environment variable names.
- Explicit boundaries:
  - Read-only operational views; no provider probes or live quota scraping.
  - No account, credential, key, policy mutations (deferred to M11-004 and M11-005).
  - No auth coordinator bridging (deferred to M11-006).
  - No Core runtime contracts or SQLite schema alterations.

## Acceptance

- [x] `GET /admin/v1/status` returns HTTP 200 with JSON matching OpenAPI `Status` schema: version, overall readiness (`ready`, `unavailable`, `unknown`), component descriptors (ID, kind, implementation, health, declared capabilities), and configured routes (protocol, mode, model, adapter_id, connector_id, account_id).
- [x] Secrets, credential references/values, upstream endpoints, private paths, and internal configuration details are redacted/omitted from `GET /admin/v1/status`.
- [x] Status reads and usage reads perform zero network provider requests or external probes.
- [x] `GET /admin/v1/usage/requests` supports `key_id`, `account_id`, `since`, `until`, `limit` (default 50, max 500), and `offset` (>=0), returning `{ items, limit, offset, total }` ordered by `accepted_at ASC, id ASC`.
- [x] `GET /admin/v1/usage/attempts` supports `request_id`, `account_id`, `since`, `until`, `limit` (default 50, max 500), and `offset` (>=0), returning `{ items, limit, offset, total }` ordered by event time ASC, id ASC.
- [x] `GET /admin/v1/usage/summary` supports `key_id`, `account_id`, `since`, `until`, returning aggregate counts and nullable token metrics; unknown/missing token counters serialize as explicit JSON `null`, never zero; passing `limit` or `offset` returns HTTP 400 `invalid_request`.
- [x] Invalid query parameters (malformed RFC3339 timestamps, `since > until`, limit > 500, limit < 1, offset < 0, unexpected parameters) return HTTP 400 with standard `{ "error": { "code": "invalid_request", ... } }`.
- [x] All status and usage endpoints enforce operator bearer authentication and Host/Origin validation established in M11-002 (401 for missing/invalid token, 403 for disallowed Host/Origin).
