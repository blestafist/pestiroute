# M2-019 — Load minimal M2 topology without breaking M1 startup

## Outcome

Startup produces explicit registry/route inputs while the existing single-target configuration remains usable. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- In `cmd/gateway/main.go` (and accompanying configuration types), implement configuration parsing and validation for the bounded M2 topology subset:
  - `components`: collection of component declarations with `id` (InstanceID), `implementation` (e.g. `pestiroute.responses.native`), `kind` (`adapter` or `connector`), and component-specific configuration (limits, transport/timeouts, endpoint).
  - `routes`: collection of explicit route declarations with `protocol` (`openai.responses.v1`), `mode` (`native`), `model`, `account`, `adapter` (InstanceID), `connector` (InstanceID), and optional capability map.
  - Credential resolution: map environment variable names to in-memory credential storage/lookups without exposing secret values in logs, errors, or String/GoString formatting.
- Normalize legacy single-target fields (`upstream_endpoint`, `upstream_credential_env`, timeouts, limits) into the equivalent singleton topology (one adapter instance, one connector instance, one native route).
- Enforce strict configuration validation rules:
  - Retain probe-only startup when no inference configuration (legacy or M2) is provided.
  - Disallow unknown fields, trailing JSON data, files > 1 MiB, or null field values.
  - Mutual exclusion: reject mixing legacy upstream fields with M2 `components` or `routes`.
  - Topology completeness: reject partial declarations, duplicate instance IDs, missing referenced adapter/connector instances, or mismatched component kinds.
  - Route validation: require `mode == "native"`, non-empty protocol/model/account, and reject duplicate `RouteIdentity`.
  - Environment credentials: env var names must be non-empty and present in the environment with non-empty values.
  - Network binding: require numeric loopback (`127.0.0.1` or `::1`) whenever inference routes exist.
- Explicit limits: Configuration loading, mapping, and validation only. Do not construct runtime registry instances, start HTTP handlers with the new topology, or replace the gateway dispatcher yet (that is scoped to M2-020). No M3 YAML/storage/policy schema.

## Acceptance

- [x] Legacy single-target configuration and probe-only configuration parse and validate identically to the M1 baseline, preserving strict unknown-field, 1 MiB size, and error formatting behavior.
- [x] M2 topology JSON with `components` and `routes` (including multi-route topologies, e.g. two distinct models or accounts) parses and normalizes successfully with valid credential references.
- [x] Malformed configurations fail safely with explicit diagnostics and zero secret leakage: mixed legacy/M2 fields, duplicate instance IDs, missing referenced components, mismatched component kinds, duplicate route identities, non-native modes, missing/empty env credentials, and non-loopback inference listeners.
