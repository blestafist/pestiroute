## Outcome

An attempt has a useful immutable diagnostic record without introducing M3 persistent accounting. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Extend the runtime record with selected route/instance/account, mode, trusted IDs, start/end timing, commitment, outcome, classified error/retry metadata and nullable final usage.
- Expose a bounded per-attempt observation/sink boundary and test collector; production need not retain all records in memory. Keep estimates distinct when present; no database, billing, reservations or prompt storage.

## Acceptance

- [ ] Records contain no raw payloads, secrets or unsanitized diagnostics; observer callbacks cannot mutate live execution state.
- [ ] Unknown/partial usage stays distinct from zero and cached/reasoning detail is not added to totals.
- [ ] Pre-Execute rejection and executed-attempt outcomes are distinguishable; at most one terminal record is published per attempt.
