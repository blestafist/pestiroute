# M2-017 — Record bounded in-memory attempt observations

## Outcome

An attempt has a useful immutable diagnostic record without introducing M3 persistent accounting. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Attempt/usage ownership](../CONTRACT.md#usage-and-scoped-runtime-services), [error metadata](../CONTRACT.md#error-model).
- `internal/core/dispatch.go`, `internal/core/execution.go`, and runtime selection/services from M2-016.

## Scope

- Extend `internal/core` attempt records with selected route/instance/account identity, mode, runtime-owned IDs (`RequestID`, `AttemptID`), start/end timing, commitment flag, outcome, classified error/retry metadata, and nullable final usage.
- Expose a bounded observation/sink interface and an in-memory test collector (e.g., fixed-capacity ring or slice); observer callbacks receive immutable copies and cannot mutate live execution state or block stream progression.
- Distinguish pre-execution rejections from executed-attempt outcomes: pre-Execute rejects produce no attempt record. Guarantee at most one terminal record per attempt.
- Explicit limits: in-memory diagnostics only; no SQLite, durable usage, billing, reservations, prompt storage, or background worker threads.

## Acceptance

- [x] Records contain no raw payloads, secrets or unsanitized diagnostics; observer callbacks cannot mutate live execution state.
- [x] Unknown/partial usage stays distinct from zero and cached/reasoning detail is not added to totals.
- [x] Pre-Execute rejection and executed-attempt outcomes are distinguishable; at most one terminal record is published per attempt.

Direct proof: `TestAttemptObservation` captures success, pre-Execute rejection (no record), pre-Head connector failure, incomplete stream error, Complete error, partial/reasoning/cached usage, and client cancellation; asserts metadata scope, monotonic timing, zero-versus-unknown usage, immutable snapshots, bounded/concurrent collection, and exactly one terminal record. A gated observer subtest verifies losing Close waits for winner publication without holding the handoff lock.
