## Scope

- In `internal/core/auth_coordinator.go`: project validated `*AuthUserAction` to transient `AuthSession.UserAction` during `Start` and `Continue`. Enforce DEC-009 validation rules: absolute HTTPS URI with host and no userinfo (1–2048 printable ASCII bytes), user code (1–256 printable ASCII bytes without controls), positive poll interval; valid only with `Supported=true` and `NextAction="continue"`. Discard session and fail closed on malformed action.
- In `cmd/gateway/admin_auth.go`: render approved user action fields (`verification_uri`, `user_code`, `interval_seconds`) alongside session ID and RFC3339 expiry when `session.UserAction` is present; never expose opaque state or credentials.
- Explicit limits: Presentation projection is transient and not persisted to SQLite. No browser launching or automation. No provider-specific branches in Core or CLI admin.

## Acceptance

- [x] `AuthCoordinator.Start` and `AuthCoordinator.Continue` project validated `UserAction` onto `AuthSession.UserAction`.
- [x] Malformed `UserAction` (non-HTTPS/userinfo/spaces/length-exceeded URI, control characters/length-exceeded code, non-positive interval, or action on completed/unsupported/refresh results) fails closed, discards session/claim, and leaks no state.
- [x] Admin auth CLI formats `verification_uri`, `user_code`, `interval_seconds`, `session`, and `expires_at` cleanly without leaking opaque state or credentials.
- [x] Existing flows with nil `UserAction` remain compatible and preserve standard continuation output.
- [x] Persistence or coordinator failure reports clean admin error without claiming success.
