## Scope

- Add targeted concurrent success/cancel/failure scenarios with unique request markers and controlled competing terminal signals.
- Fix exposed races or state sharing in the existing lifecycle only.
- Stop before persistent accounting, reservations, account pools or general stress infrastructure.

## Acceptance

- [ ] Request/attempt IDs are unique and bytes/control state never cross requests; cancelling one does not cancel another.
- [ ] Each attempt finalizes exactly once despite competing Complete, Close, timeout or shutdown signals.
- [ ] Interrupted usage remains partial/unknown; native failure is not overwritten by success; a subsequent request succeeds.
