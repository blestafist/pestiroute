# M6-022 — Supervise recovery for new work only

## Outcome

Supervise external child process recovery for new incoming work only: on unexpected child termination or process breach, immediately withdraw readiness, revoke active callbacks, cancel active invocations, clean up prior process resources, and restart with a monotonic process epoch under bounded restart backoff (100 ms–2 s exponential) and budget (at most 3 restarts in 60 s). Active work is never replayed or retried across epochs; new work is admitted only after fresh handshake and initialization. See [registry](../TASKS.md#m6--external-plugin-runtime) and [milestone](../ROADMAP.md#m6--external-plugin-runtime).

## Scope

- Supervised process manager and recovery loop in `internal/connector/external/`:
  - **Readiness withdrawal**: on child exit or fatal transport loss, mark connector not ready / unavailable immediately; reject new operations while restarting.
  - **Zero active replay**: active/in-flight invocations fail closed immediately with `CategoryUnavailable` / `RetryUnknown` (established in M6-021) and are revoked; never replayed or migrated to the new process epoch.
  - **Epoch increment**: each restart increments the host process epoch; old callbacks, frames, and tokens from previous epochs fail closed and are rejected.
  - **Bounded restart budget and backoff**: enforce at most 3 restarts within a sliding 60 s window; apply exponential backoff between 100 ms and 2 s; exceeding budget marks supervisor permanently failed/unhealthy (crash loop limit).
  - **Pre-restart cleanup**: ensure prior child process group and private socket directory are reaped and cleaned before spawning a new child generation.
  - **Re-handshake and re-init**: replacement child process must undergo full handshake, descriptor verification, and initialization before readiness is restored for new work.
- Test suite in `internal/connector/external/`:
  - Unit and race tests verifying:
    - Unexpected child exit triggers immediate readiness withdrawal and in-flight failure with zero replay.
    - Rapid crashes trigger up to 3 restarts with exponential backoff, then permanently fail.
    - Process epoch increments across restarts; callbacks from stale epochs are rejected.
    - New requests succeed after healthy restart, handshake, and initialization.
    - Old sockets and process groups are reaped before replacement start.
- Limits:
  - Process tree drain, SIGTERM/SIGKILL sequence and whole-connector shutdown belong to M6-023.
  - Native Responses child wrapping belongs to M6-024.
  - Gateway configuration / startup wiring belongs to M6-025.
  - End-to-end SQLite reservation rollback and attempt accounting belong to M6-027.

## Acceptance

- [x] Unexpected child exit or fatal transport failure immediately withdraws readiness; callers attempting new operations while restarting receive unavailable/not-ready errors.
- [x] In-flight operations active at crash time fail closed immediately with zero ambiguous replay; no active request is transferred, retried, or replayed onto the restarted child.
- [x] Each restart allocates a strictly greater host process epoch; frames or callbacks bearing prior epoch IDs are rejected.
- [x] Restart respects exponential backoff (100 ms base up to 2 s ceiling) and a strict budget of at most 3 restarts in 60 s; exceeding the budget halts restarts and marks the connector permanently unavailable.
- [x] Prior child process group, sockets, and temp directories are verified cleaned before spawning the replacement child.
- [x] New work resumes successfully once the new child completes startup, handshake, descriptor check, and Init.
- [x] All tests pass under `go test -race` with zero data races.
