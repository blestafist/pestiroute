## Threat Model & Design Resolution

1. **Confidentiality vs Redeemability**:
   While an unbound or intercepted loopback port risks exposing the authorization code string (loss of code confidentiality), PKCE S256 and one-time state match (DEC-019) guarantee that an interceptor CANNOT redeem the code for access/refresh tokens. The high-entropy `code_verifier` is never exposed to the browser or network and remains securely held in PestiRoute's encrypted SQLite session state.
2. **Coherent Remote-Browser / SSH Split**:
   Gateway `admin auth start` and `continue` are discrete commands. To avoid assuming a server listener can directly catch a remote client browser:
   - **Manual continuation (DEC-019 / DEC-022)**: Primary universal flow. The operator pastes the complete loopback callback URL or displayed authorization code into `admin auth continue --session ID --callback-stdin`. If loopback navigation fails locally on the browser host, the complete callback URL is preserved in the address bar.
   - **SSH Local-Forwarding**: For environments using a bound loopback listener, the operator establishes `ssh -L <port>:127.0.0.1:<port>` matching the redirect URI before opening the authorization URL.
3. **Connector State Decoupling & Normative Decision**:
   `authContinuation` explicitly carries `RedirectURI string json:"redirect_uri,omitempty"`. During `start`, the candidate redirect URI (from config, dynamic loopback port, or candidate default) is saved into continuation state. During `continue`, that exact recorded URI is retrieved for DEC-019 URL verification and token exchange `redirect_uri` form parameter.
   *Normative Decision*: CONTRACT lines 159-165 and DEC-022 specify using the "exact configured redirect URI". Storing the redirect URI in the Connector's opaque `authContinuation` at `start` purely clarifies effective session configuration integrity against runtime config drift across discrete CLI invocations (`start` then `continue`). Core treats continuation state as opaque bytes, with no schema or interface change; no new ADR is required.
4. **Live Gate Boundary**:
   Upstream Google registration of dynamic loopback ports is an external live gate deferred to live operator verification (M10-017); source-pinned 9Router evidence justifies candidate dynamic loopback offline.
