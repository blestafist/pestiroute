## Scope

- Implement Connector-private request adaptation helper for Codex in `internal/connector/codex` (e.g., `adapt.go`).
- Enforce native mode byte preservation: in `ModeNative`, if the request body already satisfies the profile, return the exact original request bytes without rewriting or re-serialization.
- Implement explicit translation mode (`ModeTranslation`):
  - Guarantee original `core.ExecutionRequest` and its payload bytes remain completely immutable.
  - Inject required defaults when omitted: `stream: true`, `store: false`.
  - Include profile default `reasoning.encrypted_content` in the `include` array if not already present.
  - Preserve chronological `input` items, item IDs, call IDs, order, and extensions.
  - Preserve function `tools`, schema parameters, `strict` flags, and `tool_choice`.
  - Preserve `prompt_cache_key` when present (printable ASCII <= 256 bytes) without synthesizing session IDs.
  - Preserve opaque encrypted reasoning items (`reasoning.encrypted_content` ciphertext and summary items) without decryption, logging, or stripping.
  - Preserve recognized optional fields and admitted unknown fields (`json.RawMessage`) without universal Message/Tool conversions.
  - Never silently drop explicit generation controls or activate Lite-style prefix/context construction.
  - Ensure adapted JSON output is valid, has no duplicate keys, and stays within the 1 MiB body limit.

## Acceptance

- [x] In `ModeNative`, request payload bytes are preserved exactly byte-for-byte; no fields are added, stripped, or reordered.
- [x] In `ModeTranslation`, the original `core.ExecutionRequest` and `req.Payload.Body` are immutable.
- [x] Translation applies documented defaults: sets `stream: true`, `store: false` when omitted, and appends `reasoning.encrypted_content` to `include` if missing.
- [x] Multi-turn conversation history, tool definitions, tool call IDs/arguments, tool outputs (`function_call_output`), and opaque encrypted reasoning ciphertext survive adaptation unaltered.
- [x] Unknown optional JSON fields are preserved without re-serializing through a universal message or tool struct.
- [x] Lite prefix/context item layouts are not activated and no meaningful generation controls are silently removed.
