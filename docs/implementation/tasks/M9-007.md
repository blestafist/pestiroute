# M9-007 — Enforce Chat stream idle timeout, test mixed protocol isolation, and clarify opaque routing

## Outcome

Enforce configured `stream_idle_timeout` during Chat SSE and JSON streaming reads, add deterministic stall tests, test mixed protected protocol configuration isolation without violating payload opacity, clarify route-isolation claims in M9 binding/cards, and evaluate duplicate usage extraction. Resolves cumulative review rejection on PR #17 (commit `254f276`). See [registry](../TASKS.md#m9--chat-completions-client-compatibility) and [milestone](../M9-CHAT-COMPLETIONS.md).

## Scope

- **P2 Stream Idle Timeout Enforcement**:
  - Thread parsed duration configuration (`stream_idle_timeout`) into `pestiroute.chat-completions.native` connector settings and runtime invocation.
  - In `internal/connector/chatcompletions/execute.go` (`sseStream.Next`) and `internal/connector/chatcompletions/jsonstream.go` (`jsonStream.Next`), enforce the configured idle timeout during `body.Read`.
  - When an upstream read exceeds `stream_idle_timeout`, close the response body, cancel upstream request context, and finalize the stream with `core.CompleteFrame{Outcome: core.OutcomeIncomplete, Error: upstream_timeout}`.
  - Add deterministic stall tests for both SSE and JSON streams in `internal/connector/chatcompletions/execute_test.go` verifying timeout closing, context cancellation, and incomplete attempt classification.
- **P3 Protocol Isolation and Opacity Clarification**:
  - Add mixed protected gateway configuration test in `cmd/gateway/chat_protected_test.go` configuring both `/v1/responses` and `/v1/chat/completions` routes. Verify `/v1/chat/completions` dispatches exclusively to Chat connector and `/v1/responses` dispatches exclusively to Responses connector, with zero cross-routing.
  - Clarify claims in `docs/implementation/M9-BINDING.md` and `docs/implementation/tasks/M9-003.md`: routing is strictly path/protocol-based; opaque byte preservation means `/v1/responses` does not reject Chat-shaped payloads with matching models, and neither adapter inspects foreign protocol schemas.
- **P3 Duplicate Usage Extractor Assessment**:
  - Evaluate `jsonUsage` in `execute.go` versus `usageObserver` in `jsonstream.go`. As no defect was demonstrated, apply the smallest safe reuse if straightforward or record explicit justification to defer and avoid gratuitous rewrite of tested parsers.
- **Limits**:
  - No changes to `CONTRACT.md` or Core interfaces.
  - No alteration of body byte opacity or introduction of cross-protocol schema inspection.
