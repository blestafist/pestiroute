# M10-030 — Support optional credential_id in Antigravity connector settings and resolve execution credential projection

## Outcome

Allow protected gateway configuration of `pestiroute.antigravity.v1internal` to specify an optional SQLite `credential_id` in connector settings (`settings: {project: ..., model: ..., account_id: ..., credential_id: ...}`), defaulting to `"oauth"` when omitted or empty, and projecting it to the runtime credential reference. This aligns Antigravity with the existing settings contract, resolving pre-dispatch unauthenticated failure when an account's credential row ID differs from `"oauth"` without forcing user re-authentication or implicit fallback. Links to [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [ROADMAP.md](../ROADMAP.md#phase-4--provider-expansion).

## Scope

- In `cmd/gateway/yaml_config.go`:
  - Allow `credential_id` in `allowed` mapping for `pestiroute.antigravity.v1internal` connector settings.
  - Permit optional string `credential_id` in `validateAntigravitySettings` without failing validation.
- In `cmd/gateway/protected_startup.go`:
  - Project `component.CredentialEnv = strings.TrimSpace(s.CredentialID)`.
  - Default `component.CredentialEnv = "oauth"` when omitted or empty.
  - Return startup validation error if `s.CredentialID` is non-empty but whitespace-only (`connector %q: Antigravity credential_id cannot be whitespace`).
- In independent `cmd/gateway/antigravity_credential_test.go` (leave M10-028's composition/runner regressions untouched):
  - Verify execution with custom `credential_id` against a sealed SQLite credential record with matching row ID.
  - Verify default fallback to `"oauth"` when `credential_id` is omitted.
  - Verify rejection of whitespace-only `credential_id` during protected startup validation.
  - Verify strict account scope isolation and fail-closed behavior on mismatched/missing credential (no implicit account fallback).
- Credential safety: never read, dump, echo, or log secret values, byte lengths, or hashes. A separate credential-store preflight probe is not required for this offline regression.
- Explicit limits:
  - Zero live network or provider calls in this task; all verification is offline and deterministic.
  - M10-028 remains frozen and BLOCKED until this fix is reviewed, committed, and separately authorized.
  - No changes to Core CONTRACT or SQLite schema; existing `credential_id` contract is preserved.
