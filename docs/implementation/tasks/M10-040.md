## Scope

- Documentation and specification design only: draft ADR DEC-031, update M10 candidate bindings, and specify offline synthetic fixture tests (zero Go implementation, zero live requests, zero key/token disclosure).
- Standard client carrier binding:
  - Require explicit client opt-in `include: ["reasoning.encrypted_content"]`; this gateway privacy rule is stricter than OpenAI's stateless default.
  - Emit encrypted content only on completed reasoning item events, never on added/delta; visible text and summary remain incremental.
- Critical cryptographic guardrails:
  - Gateway `MasterKey` NEVER passed to connector or broad storage.
  - Core provides NO provider-reasoning API.
  - Composition root derives purpose-separated continuation key or supplies a scoped seal/open closure with fixed AAD namespace; connector receives ONLY this scoped codec/closure, never general database/master decryption capabilities.
- Strict AAD metadata & authentication:
  - Strict version-1 plaintext retains one signed part's original kind/content/function name/args/IDs, opaque signature bytes, part positions, association, and Responses IDs; do not encrypt whole upstream bodies.
  - Bind account ID, selected credential project, model, schema/key version, suite, times and exact part association with a purpose-derived AES-GCM codec; injected clock, maximum TTL 24h, future-issued skew <=5m, expiry with no grace, aggregate 1 MiB carrier bound.
  - Current master key only (`current-master/v1`); key rotation invalidates old carriers, no keyring or old-key fallback. Reject tampering, expiry and wrong account/project/model before provider dispatch with fixed `invalid_request` / `continuation_scope_mismatch`; no route-account fallback.
- Turn binding & replay semantics:
  - Do not promise stateful replay protection within stateless Core design unless defined via authenticated turn binding.
  - Non-idempotent retry remains prohibited; legitimate resubmission of reasoning items in multi-turn history must not be rejected.
- Exact signature association:
  - `signature_only` diagnostic does not prove a separate frame/trailer. Direct signatures bind to their actual ordered part; a signature-only part may bind only to its single immediately preceding unsigned actual part in the same complete ordered `content.parts[]` array. Ambiguous/non-adjacent/cross-frame cases fail terminally after commit; never invent provider input.
  - Preserve signed ordinary text visibly plus an adjacent continuation reasoning item; signed thought and function-call placement/association remain exact; no signature merge.
  - Bounded forward semantics: preserve signed thinking and signed tool calls; do not forward or normalize arbitrary unsupported media.
- Identify unavailable product decisions exceeding offline scope as explicit Unknowns.
