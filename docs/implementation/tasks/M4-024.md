# M4-024 — Translate stop reasons and committed stream failures truthfully

## Outcome

Translate stop reasons and committed stream failures truthfully for the Anthropic Messages connector, ensuring accurate Responses SSE terminal events and Core `CompleteFrame` outcomes (succeeded, incomplete, failed). One bounded deliverable in the [M4 registry](../TASKS.md#m4--first-translation-connector) toward the original [M4](../ROADMAP.md#m4--first-translation-connector).

## Read First

- [Stream, completion and resource policy](../M4-TRANSLATION.md#stream-completion-and-resource-policy).
- [Error model](../CONTRACT.md#error-model).
- [Usage and retry decisions](../M4-TRANSLATION.md#usage-and-retry-decisions).
- Existing stream execution and error handling in `internal/connector/anthropic/execute.go`, `internal/connector/anthropic/responses_emitter.go`, and `internal/connector/anthropic/http_error.go`.
- Complete frame and GatewayError definitions in `internal/core/execution.go`.
- Responses stream terminal events in `internal/connector/responses/sse.go`.

## Scope

- In `internal/connector/anthropic/execute.go`:
  - Distinguish incomplete stream endings (premature EOF, `max_tokens` truncation) from stream failures (SSE `event: error`, malformed event ordering, unparseable payloads).
  - Map `stop_reason` values: `end_turn` and `stop_sequence` -> `OutcomeSucceeded`; `tool_use` -> `OutcomeSucceeded` (without gateway tool execution; client owns the next tool round); `max_tokens` -> `OutcomeIncomplete` with `output_truncated` GatewayError; unknown or refusal stop reasons -> conservative non-success (`OutcomeFailed` or `OutcomeIncomplete` with client-safe GatewayError, no Messages JSON leak).
  - Handle Anthropic SSE `event: error` (e.g. `api_error`, `overloaded_error`, `rate_limit_error`) -> `OutcomeFailed` with sanitized GatewayError classification; do not classify in-stream errors as `OutcomeIncomplete`.
  - Ensure committed streams (where Head frame has already been emitted) never attempt fallback, resend, or replacement HTTP status; emit terminal event or close cleanly.
  - Prevent duplicate terminal frames or duplicate usage accounting on repeated stops, malformed post-terminal events, or subsequent read calls.
- In `internal/connector/anthropic/responses_emitter.go`:
  - Support terminal frame emission matching stop reasons: `response.completed` for normal stops (`end_turn`, `stop_sequence`, `tool_use`), `response.incomplete` for `max_tokens` with `incomplete_details.reason = "max_output_tokens"`, and `response.failed` or close on committed stream failures.
  - Prevent duplicate terminal event emission or state mutation once closed/finished.
- In `internal/connector/anthropic/execute_test.go` and `responses_emitter_test.go`:
  - Add unit and lifecycle tests covering the stop reason profile table (`end_turn`, `stop_sequence`, `tool_use`, `max_tokens`, unknown/refusal).
  - Add tests for in-stream SSE `event: error` delivery resulting in `OutcomeFailed`.
  - Add tests for premature EOF without `message_stop` resulting in `OutcomeIncomplete`.
  - Add tests verifying repeated stops, post-terminal events, and closed stream idempotency.
- Out of scope:
  - Asynchronous cancellation and timeout cleanup under races (M4-025).
  - Buffer reconstruction limits and backpressure exhaustion (M4-026).
  - Real-Connector retry and account-affinity boundaries (M4-027).
  - Durable admission / SQLite settlement verification (M4-028).

## Acceptance

- [x] Max-token truncation and early EOF produce `OutcomeIncomplete` with sanitized `GatewayError` (`output_truncated` / `incomplete_response`); in-stream SSE errors produce `OutcomeFailed`; normal ends (`end_turn`, `stop_sequence`) and `tool_use` produce `OutcomeSucceeded` without executing tools.
- [x] Repeated stops, malformed ordering, and post-terminal events cannot duplicate usage or outcomes; committed failures never produce replacement HTTP status or retry.
- [x] Unknown or refusal stop reasons fail closed conservatively without leaking raw Messages JSON or promoting HTTP 200 to success.
