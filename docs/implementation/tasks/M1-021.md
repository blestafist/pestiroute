# M1-021 — Header isolation and encoded bytes gate

## Outcome

The complete native path preserves identity body bytes and Content-Length while strictly isolating transport headers, downstream credentials, and Accept-Encoding, and failing non-identity response encodings pre-Head. See [registry](../TASKS.md#m1--transparent-responses-proxy-planning-candidates) and [M1](../ROADMAP.md#m1--transparent-responses-proxy).

## Scope

- Add end-to-end integration tests in `cmd/gateway/main_test.go` verifying the complete HTTP request and response path against a controllable fake upstream.
- Verify request header isolation: downstream client `Authorization`, `Cookie`, proxy headers, and `Connection`-nominated tokens are stripped; upstream receives only the runtime-configured synthetic Bearer token.
- Verify request compression isolation: downstream client `Accept-Encoding` (absent, explicit `gzip`, `br`, `*`) is overridden to `Accept-Encoding: identity` upstream.
- Verify request body encoding rejection: downstream requests with non-identity `Content-Encoding` are rejected pre-execute with 400 Bad Request (`CategoryUnsupportedFeature`) without reaching upstream.
- Verify upstream response encoding gate: non-identity upstream `Content-Encoding` (e.g. `gzip`, `identity, gzip`, `deflate`) on either HTTP 200 or HTTP rejections fails pre-Head with sanitized 503 (`CategoryUnavailable`), closes the upstream body immediately, forwards zero response body bytes, and finalizes once as incomplete/failed.
- Verify identity response byte and length preservation: upstream responses with absent or `identity` `Content-Encoding` preserve exact raw bytes and valid `Content-Length`.
- Verify response header filtering: upstream hop-by-hop headers, `Connection`-nominated headers, `Set-Cookie`, and `Authorization` are stripped and never leak downstream.
- Stop at assembled-path regression tests and any focused fixes in `cmd/gateway` or component packages; do not implement M1-022 documentation/scaffold assembly or M2 features.

## Acceptance

- [x] Captured upstream request headers contain only the runtime-selected Bearer credential; client Authorization, cookies, proxy headers, and Connection-nominated headers are absent.
- [x] Captured upstream request header has `Accept-Encoding: identity` regardless of downstream client Accept-Encoding (absent, gzip, or custom).
- [x] Downstream request with non-identity Content-Encoding returns 400 Bad Request before execution and generates zero upstream requests.
- [x] Upstream response with non-identity Content-Encoding (tested on both 200 and rejection status) fails pre-Head with 503 GatewayError, releases upstream transport, sends no raw encoded body downstream, and finalizes once without claiming success or safe replay.
- [x] Upstream response with absent or identity Content-Encoding delivers exact byte-preserving body with matching Content-Length.
- [x] Upstream hop-by-hop headers, Connection-nominated response headers, Set-Cookie, and upstream Authorization do not leak downstream.
