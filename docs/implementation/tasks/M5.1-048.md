## Scope

- Staged live gateway execution:
  - Stage 1: Protected gateway native Lite single-function roundtrip (turn 1 prompts function call, local client executes synthetic mock tool in-memory, turn 2 posts tool result and receives text answer). At most 2 upstream requests.
  - Stage 2: Staged conditional run. Only if Stage 1 succeeds (HTTP 200/200, terminal completed), execute protected gateway native Lite custom Lark grammar roundtrip (turn 1 prompts custom tool call, local client executes synthetic grammar echo in-memory, turn 2 posts custom tool result and receives text answer). At most 2 upstream requests.
  - Default stage plan `both`: at most 4 upstream requests. Explicit `PESTIROUTE_GATEWAY_TOOL_STAGE=custom` skips the already-passed function stage and permits at most 2 custom requests. Other stage values are rejected. Stops immediately if browser reauthentication is required or on HTTP 400/401/403/429/5xx.
- Zero forced refresh, zero browser re-auth, zero cross-account fallback, zero automatic retry.
- Real Core + Codex connector + transport routing: Client -> Gateway HTTP handler -> Core Router/Pipeline -> Codex Connector -> Upstream Codex Responses endpoint.
- Client-side mock execution only: In-memory fixed local map / synthetic fixtures. No shell, file, or provider-driven external I/O.
- Privacy and security:
  - Local credentials used in-memory read-only from authorized paths (`/tmp/opencode/pestiroute-auth.pQ8lCE/gateway.db`, `master.key`, account `selected-A`). No persistent writes to source DB, no key duplication.
  - Zero bearer tokens, account IDs, raw tool arguments/prompts, ciphertexts, or provider outputs persisted or logged.
- Output artifacts written with exclusive mode `0600` containing only sanitized metadata (HTTP status, code/field if error, usage counts, dispatch counts).
- Target dispatches are reported only from completed gateway POST responses; transport `DialContext` attempts are separately labeled `network_dial_attempts`. Unknown delivery never becomes an invented dispatch count.
- Operational limits: 30s per-request deadline, 1 MiB body bound, 256 tool argument/output limits. Byte preservation maintained; no whole-response buffering.
- Explicit non-scope: Standard profile tools remain Unknown (fail-closed zero-send). Parallel tool calls remain Unknown (fail-closed zero-send). M5.1-043 milestone closure audit remains separate.
