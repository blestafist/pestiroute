# M2-027 — Add cancellation and partial-Close conformance cases

## Outcome

Both producers stop outstanding work and release resources after cancellation or abandoned consumption. Conformance suites for native-loopback and scripted connectors verify pre-Head cancellation, blocked-Next cancellation, abandoned mid-stream partial Close, idempotent repeated Close, and clean single-attempt finalization without replay. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Scope

- Expand `internal/conformance/` (e.g. `internal/conformance/cancellation_test.go`) with conformance scenarios executed across both native-loopback and scripted connector fixtures, directly and through Core Dispatch:
  - Pre-Head cancellation:
    - Calling `Execute` with an already-cancelled context, or cancelling context before the initial `Head` frame is delivered.
    - Connector / Core Dispatch returns `*GatewayError` with Category `CategoryCancelled` (e.g. `execution_cancelled` or context error).
    - No stream frames are delivered.
    - Core Dispatch records exactly one uncommitted failed attempt (`Committed == false`, `Outcome == OutcomeCancelled`).
  - In-flight cancellation while `Next` blocks:
    - Consumer blocks on `Next(ctx)` waiting for subsequent frames on a gated stream.
    - Consumer context is cancelled while blocked.
    - `Next` releases within a bounded test deadline (<2s) returning context cancellation.
    - Core Dispatch finalizes the attempt exactly once as `OutcomeCancelled`.
    - Underlying producer halts work and cleans up.
  - Abandoned consumption / partial Close:
    - Consumer reads `Head` or partial body frames and abandons the stream by calling `stream.Close()` without consuming terminal `EOF` or `Complete`.
    - Producer halts outstanding work and frees resources.
    - Attempt is finalized exactly once as `OutcomeIncomplete` or `OutcomeCancelled`.
    - Any usage reported prior to abandonment is retained on the finalized attempt record (`UsageReport`).
  - Idempotent repeated stream Close:
    - Calling `stream.Close()` multiple times on the same stream is safe, returns `nil` (or consistent error), does not panic, and underlying producer stream/connection cleanup happens exactly once.
  - Follow-up execution isolation:
    - Cancellation or abandoned teardown of an attempt does not poison connector or dispatcher state.
    - A subsequent healthy execution on the same connector/dispatcher instance succeeds cleanly.
  - Observable producer cleanup and remote compute boundary:
    - Native HTTP fixture asserts upstream request context cancellation or closed connection (local transport abort).
    - Scripted fixture asserts gate release and stream removal from active streams.
    - Conformance keeps local teardown assertion separate from proof that remote provider compute stopped (contract requirement).
- Explicit limits:
  - Do not implement automatic retry or cross-account fallback on cancellation (CONTRACT: cancellation is never safe to replay).
  - Do not implement bounded backpressure conformance (M2-028).
  - Do not implement routed multi-connector runtime failures (M2-029).
  - Synthetic local fixtures only (`fakeupstream` and `scripted`); no live credentials or external network access.

## Acceptance

- [x] Pre-Head cancellation returns a classified cancellation `*GatewayError` (Category `CategoryCancelled`) and Core Dispatch records exactly one uncommitted attempt with `OutcomeCancelled` without delivering stream frames.
- [x] In-flight cancellation while `Next` is blocked unblocks within a bounded deadline (<2s), halts upstream/scripted producer activity, and finalizes the attempt as cancelled/incomplete.
- [x] Abandoned consumption (partial `Close()` after `Head` or initial body delivery without reading to terminal `EOF`) cleanly tears down the producer stream, releases resources once, and finalizes the attempt as `OutcomeIncomplete` or `OutcomeCancelled`.
- [x] Calling `stream.Close()` repeatedly is idempotent and safe, executing producer teardown exactly once without panics or leaks.
- [x] Usage observed prior to cancellation is retained on the finalized `AttemptResult` without concealing the cancellation; no cancellation triggers replay or fallback; a subsequent healthy execution succeeds on the same connector/dispatcher.
- [x] Conformance checks run against both native-loopback (verifying HTTP client/upstream abort) and scripted fixtures under race detection with zero goroutine leaks or timeouts.
