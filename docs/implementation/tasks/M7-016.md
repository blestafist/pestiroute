## Scope

- Update Core types and coordinator (`internal/core/`):
  - Add `CallbackInput string` to `core.AuthRequest`.
  - Update `validAuthUserAction`: strictly enforce two valid mutually exclusive alternatives:
    1. Browser redirect: `UserCode == ""` AND `PollInterval == 0`, with valid HTTPS `VerificationURI` (1–2048 printable ASCII, no spaces/controls, no userinfo).
    2. Device code: `UserCode` (1–256 printable ASCII) AND `PollInterval > 0`, with valid HTTPS `VerificationURI`.
    - Reject all mixed/partial pairs (e.g. non-empty code with zero interval, or empty code with positive interval).
  - Update `AuthCoordinator.Continue(ctx, sessionID string, callbackInput string)`:
    - Allow empty `callbackInput == ""` unchanged for existing legacy continuations (e.g. device auth polling).
    - When non-empty, enforce bound: strictly 1–4096 printable ASCII bytes; reject oversized, non-printable, or control characters before session claim/invocation.
    - Forward `callbackInput` to connector invocation; never log, persist, or treat it as opaque session state.
- Update Admin CLI boundary (`cmd/gateway/admin_auth.go`):
  - Update admin `auth continue` command to pass callback input to `coordinator.Continue`.
  - Safe non-commandline-secret input mechanism: read pasted callback URL from bounded `stdin` (or `--callback-stdin`) to prevent secret exposure in process argv (`/proc/<pid>/cmdline`) or shell history (`.bash_history`).
  - Redaction & diagnostics hygiene: ensure no callback URL, authorization code, or secret is written to stdout, stderr, debug diagnostics, or persistent logs.
- Update IPC bridge (`internal/ipc/`):
  - Update `connector.proto` to convey `callback_input` in `AuthRequest`.
  - Regenerate / map fields in `internal/ipc/values.go` and external supervisor/child.
- Limits: Generic runtime, admin CLI, and IPC plumbing only. No connector-specific OAuth logic, no live network calls.

## Acceptance

- [ ] `core.AuthRequest` carries `CallbackInput` across in-process and IPC connector boundaries.
- [ ] `validAuthUserAction` accepts exact browser-redirect (empty code, zero interval) and device-code (non-empty code, positive interval) pairs, and strictly rejects mixed/partial pairs.
- [ ] `AuthCoordinator.Continue` accepts empty input for legacy continuations, enforces 1–4096 printable ASCII bound for non-empty input, and fails closed without session claim on invalid inputs.
- [ ] Admin CLI `auth continue` accepts callback URL via bounded stdin without exposing secrets in argv, command output, or logs.
- [ ] Unit, IPC codec, and admin auth tests prove round-trip fidelity, bounds enforcement, input validation, and non-logging hygiene.
