## Scope

- Update Core types and coordinator (`internal/core/`):
  - Add additive `CallbackInput string` to `core.AuthRequest`. Empty on `start` and `refresh`; reject non-empty `CallbackInput` on `start`/`refresh` before connector invocation.
  - Update `validAuthUserAction`: strictly enforce two valid mutually exclusive alternatives:
    1. Browser redirect: `UserCode == ""` AND `PollInterval == 0`, with valid HTTPS `VerificationURI` (1–2048 printable ASCII, no spaces/controls, no userinfo).
    2. Device code: `UserCode` (1–256 printable ASCII, spaces allowed) AND `PollInterval > 0`, with valid HTTPS `VerificationURI`.
    - Reject all mixed/partial pairs (e.g. non-empty code with zero interval, or empty code with positive interval).
  - Update `AuthCoordinator.Continue(ctx context.Context, sessionID string, callbackInput string)`:
    - Empty legacy preservation: allow empty `callbackInput == ""` unchanged for existing legacy continuations (e.g. device auth polling).
    - Enforce bounds: when non-empty, strictly 1–4096 printable ASCII bytes (`0x20` to `0x7e`, spaces allowed); reject oversized, non-printable, or control characters before session claim/invocation.
    - State separation and non-logging: forward `callbackInput` to connector invocation; never log, persist, or treat it as opaque session state (`State` remains exclusively the runtime-loaded opaque continuation bytes). Exclude `callbackInput` from all log entries, errors, diagnostics, and session state.
    - Replay protection & single-use claim: invalid bounds or actions fail closed before session claim; once claimed, session is consumed/advanced under existing durable one-invocation claim (DEC-007); reject stale/consumed sessions before connector work; never retry or replay ambiguous or failed outcomes.
    - Zero connector-specific branches in Core: coordinator remains strictly generic without branching on connector IDs or OAuth specifics.
- Update Admin CLI boundary (`cmd/gateway/admin_auth.go`):
  - Update admin `auth continue` command to pass callback input to `coordinator.Continue`.
  - Safe non-commandline-secret input mechanism: read pasted callback URL from bounded `stdin` (or optional flag `--callback-stdin`) to prevent secret exposure in process argv (`/proc/<pid>/cmdline`) or shell history (`.bash_history`).
  - Redaction & diagnostics hygiene: ensure no callback URL, authorization code, or secret is written to stdout, stderr, debug diagnostics, or persistent logs.
  - UserAction presentation: cleanly format both device-code actions (displaying code and poll interval) and browser redirect actions (displaying verification URI without user code / interval).
- Update IPC bridge & protobuf regeneration (`internal/ipc/` and `internal/connector/external/`):
  - Update `connector.proto`: add `string callback_input = 4;` to `AuthRequest`.
  - Regenerate `internal/ipc/gen/connector.pb.go` and `connector_grpc.pb.go` using pinned protobuf tooling (`protoc -I internal/ipc/proto ...`).
  - Map `callback_input` in `internal/ipc/values.go` (`AuthRequestTo`, `AuthRequestFrom`) with round-trip fidelity, preserving exact ASCII bytes.
  - Update external connector host/child bridge (`internal/connector/external/authenticate_linux.go` and child dispatch) to propagate `CallbackInput`.
- Limits: Generic runtime, admin CLI, and IPC plumbing only. Zero connector-specific core branches, zero live authentication or network calls, zero real credential handling/persistence, capability promotion, or production routing.

## Acceptance

- [x] `core.AuthRequest` carries additive `CallbackInput string`, empty on start/refresh and rejected if non-empty on start/refresh across in-process and IPC connector boundaries.
- [x] `validAuthUserAction` accepts exact browser-redirect (empty code, zero interval) and device-code (non-empty code, positive interval) pairs, and strictly rejects mixed/partial pairs.
- [x] `AuthCoordinator.Continue` accepts empty input for legacy continuations, enforces 1–4096 printable ASCII bound for non-empty input, and fails closed without session claim on invalid inputs.
- [x] Opaque session state remains strictly separated from transient `CallbackInput`; callback input is never logged, persisted, or returned in presentation.
- [x] Admin CLI `auth continue` accepts callback URL via bounded stdin without exposing secrets in argv, command output, or logs, and handles both device-code and browser redirect action presentation.
- [x] Protobuf schema updated and regenerated with pinned tooling; `internal/ipc` codecs round-trip `callback_input` with exact ASCII fidelity and external connector child/host propagates it.
- [x] Unit, IPC codec, external connector, and admin auth tests pass under race detector; `go vet ./...` and `git diff --check` pass clean.
