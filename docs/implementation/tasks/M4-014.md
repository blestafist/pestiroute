## Scope

- Introduce only the reviewed non-secret Anthropic settings shape and explicit translation route selection. Keep connector settings private to its implementation; avoid a universal provider configuration schema.
- Validate implementation/protocol/mode/account/model, bounds and references; update the owning configuration specification for the additive profile.
- Enforce route estimate budget floor: for routes targeting Anthropic translation connectors with `unknown_estimate: reserve`, require `conservative_tokens >= 4096` (matching the sent `max_tokens` ceiling from M4-008) so that conservative reservations cannot be less than the effective output limit admitted by Core, fulfilling M4-TRANSLATION:75-76 at the configuration boundary without violating Core payload opacity.
- Preserve schema/version policy and all native/legacy validation. A stored-API-key profile must not require a dummy credential_env; native compatibility must not be weakened to achieve that.

## Acceptance

- [ ] Valid translated YAML normalizes predictably; unsupported modes/protocols, wrong implementation references, duplicate/unknown/null fields and missing budgets fail startup.
- [ ] Translation routes configured with `unknown_estimate: reserve` require `conservative_tokens >= 4096`; configurations with `conservative_tokens < 4096` (e.g. 1) fail startup/validation with a clear error.
- [ ] Native protected YAML and legacy/M2 JSON keep existing accepted/rejected behavior; secret values cannot be placed in new settings.
