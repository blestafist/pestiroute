# M2-006 — Gate registry availability on Init and Health

## Outcome

Only successfully initialized, healthy components are admitted as execution candidates. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Init/Health obligations](../CONTRACT.md#component-descriptor-and-lifecycle) and [Component API](../M2-BINDING.md#component-api).
- Existing `internal/core/registry.go` and `internal/core/component.go` implemented in M2-002 and M2-005.

## Scope

- Track component lifecycle states in `internal/core` (`uninitialized`, `ready`, `unavailable`, `failed`).
- Provide an initialization operation on the registry/component (`Init(ctx, id, config)`) that calls component `Init`; on failure, invoke component `Close` to release partial resources and mark instance failed/unavailable.
- Allow `Lookup` / `Descriptor` queries before initialization; gate execution admission on successful initialization and `HealthReady`.
- Support observational `Health(ctx)` queries reporting `HealthState` (`ready`, `unavailable`, `unknown`) with bounded diagnostics without background polling.
- Ensure concurrent queries, health checks, and admissions are race-free. Do not implement shutdown/draining (deferred to M2-007) or model eligibility (deferred to M2-013).

## Acceptance

- [x] Lookup/admission cannot execute an uninitialized or failed component; pre-init `Descriptor` lookup remains accessible.
- [x] Failed initialization calls component `Close` to release partial resources and marks the instance unavailable/failed.
- [x] Health state changes (`unavailable`, `unknown`) prevent execution admission without replaying active work; concurrent admission/health queries are race-free.
