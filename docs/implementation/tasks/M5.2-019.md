# M5.2-019 — Prove cancellation, backpressure and shutdown

## Outcome

Prove client cancellation, consumer backpressure, and graceful shutdown lifecycle for protected local-compatible routes without requiring local engine processes or model downloads. One bounded deliverable in [the M5.2 registry](../TASKS.md#m52--local-runtime-connectors), under [ROADMAP M5.2](../ROADMAP.md#m52--local-runtime-connectors).

## Scope

- Add deterministic tests in `cmd/gateway` (e.g. `cmd/gateway/local_cancellation_test.go` or `cmd/gateway/local_protected_test.go`) exercising protected local-compatible routes (`/v1/responses`).
- Use controlled real-socket / loopback fake upstreams to simulate client disconnect, slow/stalled consumers, and gateway shutdown drain.
- Verify client disconnect cancels upstream HTTP/SSE requests and releases in-flight resources.
- Verify stalled consumer backpressure bounds buffering and preserves chunk order once consumption resumes.
- Verify graceful gateway drain permits active eligible requests to complete within timeout, while expiry aborts lingering attempts.
- Verify no automatic retry or fallback occurs after response stream commit or unknown delivery.
- Limits: transport-level cancellation does not imply remote engine compute cancellation; do not launch real background runtimes or download model weights.

## Acceptance

- [x] Disconnect cancels upstream I/O; a stalled client bounds memory and stream ordering survives resumed consumption.
- [x] Graceful drain completes eligible work; expiry cancels outstanding attempts.
- [x] No automatic generation restart/fallback after commit or unknown delivery.
- [x] Transport cancellation is not claimed as proof of remote inference-engine compute cancellation.
