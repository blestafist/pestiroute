## Scope

- In `cmd/gateway` (and `internal/core` if needed):
  - Add end-to-end race and barrier-controlled fallback accounting tests using real file-backed SQLite database instances and multi-candidate `core.Dispatcher` execution:
    - Attempt 1 safe pre-Head or rejected-Head failure releasing/reconciling reservation without admitting a second RPM slot for Attempt 2 (releasing zero charge when proven undispatched, conservative charge when intent was dispatched);
    - Attempt 2 exact usage versus incomplete/unknown usage settling properly into `usage_records` and `reservations` (verifying actual vs conservative charges);
    - Concurrent synchronization races across stream cancellation, caller stream `Close()`, and producer completion/error on fallback executions verifying exactly-once finalization without double-refund or double-charge;
    - Second-attempt reservation failure (e.g., TPM budget exhaustion or storage failure during candidate 2 `BeginAttempt`) halting fallback without executing candidate 2, leaving attempt 1 settled and no dangling held reservations;
    - Post-execution restart/recovery verification: verifying ledger queries show consistent request, attempt ordinals, and terminal reservations.
- Explicit limits:
  - Does not change Core contracts, schema migrations, or retry policy rules;
  - Pure verification of existing fallback accounting semantics under race conditions with real SQLite and controllable mock connectors.

## Acceptance

- [x] One client request consumes exactly one RPM admission across fallback attempts while each executed attempt receives a distinct attempt ID, monotonic ordinal, and dedicated TPM reservation.
- [x] A safe uncommitted first-attempt failure rolls over to the next candidate and reconciles its reservation per normative rules (releasing zero charge when proven undispatched, or settling conservative charge when dispatched before pre-Head failure); terminal fallback usage (exact tokens or conservative/unknown) settles correctly in the durable SQLite ledger.
- [x] Synchronized races between stream cancellation, attempt completion, and caller `Close()` on fallback streams finalize exactly once: no double settlement, no duplicate charge, and no corrupted or double-decremented limit counters.
- [x] When reservation or admission for a subsequent fallback candidate fails (e.g. TPM budget exhaustion or storage error), that candidate is not executed; the request terminates cleanly with attempt 1 finalized and no orphaned held reservations.

## Completion Evidence

`cmd/gateway/accounting_fallback_race_test.go` composes real multi-candidate `core.Dispatcher` execution, SQLite policy/account records, `sqliteAccountingStore`, and file-backed SQLite. Barrier-controlled races deliver Complete+EOF or a producer error while caller `Close()` and context cancellation compete. Each run asserts one request/two unique ordinal attempts, the safe primary's reconciled reservation, exactly one usage row and terminal reservation per attempt, exact vs conservative effective charges, aggregate charge conservation after closing/reopening SQLite, and rejection of a second RPM admission. A low-TPM run verifies candidate 2 is not executed, attempt 1 is terminally reconciled, and no held attempt-2 reservation exists. The updated `TestSQLiteAccountingStorePersistsFallbackAttemptWithoutSecondRPM` additionally proves zero-charge release for reservations proven undispatched, nullable partial usage/lower-bound settlement, unknown settlement, and idempotent finalization races.

The synchronized reproducer exposed a Core completion race: a competing `attemptStream.finalize` waited only for attempt publication, which occurs before durable accounting persistence, so `Close()` could return while the SQLite reservation remained held. `internal/core/dispatch.go` now makes competing finalizers wait for persistence acknowledgment (`persisted` channel). After the fix, the composed reproducer passes repeated race runs. Safe pre-Head failure after acknowledged dispatch intent is conservatively charged per the M3 limit contract; only proven undispatched work is released.
