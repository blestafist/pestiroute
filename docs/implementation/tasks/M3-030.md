## Scope

- In `cmd/gateway`:
  - Wire YAML protected mode startup in `runWithFinalize` and `composeHandlerWithFactory`:
    - Open SQLite database at configured `database_path` via `sqlite.Open` with schema validation (`sqlite.SchemaVersion(ctx, db) == sqlite.CurrentSchemaVersion()`).
    - Acquire exclusive gateway process lock via `sqlite.AcquireProcessLock(c.DatabasePath)` prior to listening; fail closed if already held.
    - Run SQLite crash recovery via `sqlite.NewLedger(db).Recover(ctx)` under `BEGIN IMMEDIATE` transaction prior to binding/serving; settle interrupted attempts and reservations before readiness.
    - Validate referenced topology accounts against SQLite before binding listener: ensure referenced account IDs and model/connector mappings exist and are enabled in `sqlite.Accounts`.
    - Wire `sqlite.VirtualKeys` for Bearer token auth (`core.KeyStore`), `sqlite.KeyPolicies` for policy snapshots (`core.PolicyStore`), `sqlite.Accounts` for account authorization (`core.AccountAuthorizer`), `core.PersistentServices` with `sqlite.Credentials` (decrypted via loaded `secure.MasterKey`), and `sqlite.Ledger` in `sqliteAccountingStore` for durable intent and settlement.
    - Wire graceful shutdown: drain active requests up to `shutdown_timeout`, close component registry, release process lock, and close SQLite database cleanly on SIGTERM / context cancellation.
    - Ensure failed startup cleans up resources (database connection, process lock) without leaks or orphaned locks.
    - Preserve legacy single-target and strict M2 JSON behavior in development mode (`c.Format == "json"`).
- Explicit limits:
  - Does not implement CLI usage inspection commands (reserved for [M3-031](M3-031.md)).
  - Does not implement end-to-end multi-process crash injection tests (reserved for [M3-032](M3-032.md)).
  - Does not implement multi-target fallback routing (reserved for [M3-037]–[M3-041]).

## Acceptance

- [x] Protected gateway startup (`-config-format yaml`) opens SQLite database, verifies schema version, acquires exclusive process lock, executes `Ledger.Recover`, and validates referenced accounts before opening HTTP listener and signaling readiness.
- [x] Startup fails closed without listening if database cannot be opened, schema version is unmigrated, master key is missing or invalid, an account reference in topology does not exist in SQLite, or another gateway process holds the process lock.
- [x] Out-of-band CLI operations (`pestiroute admin ...`) successfully update accounts, virtual keys, and policies against the database while the gateway is actively running, with new admissions immediately observing updated state without gateway restart or topology reload.
- [x] Graceful shutdown (SIGTERM / context cancellation) drains active requests up to `shutdown_timeout`, closes component registry, releases process lock, and closes SQLite database cleanly once.
- [x] Failed startup (e.g. invalid config or reference validation failure) releases all acquired resources and closes DB/lock without leaks.
- [x] Legacy and M2 JSON configuration paths continue to pass all existing tests and regressions.
