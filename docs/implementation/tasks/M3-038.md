# M3-038 — Implement the bounded safe-retry decision

## Outcome

Implement the pure, bounded safe-retry decision in Core, evaluating whether an attempt failure qualifies for fallback to an alternative candidate. This is one bounded deliverable in the [M3 registry](../TASKS.md#m3--access-accounts-and-accounting) toward [M3](../ROADMAP.md#m3--access-accounts-and-accounting).

## Scope

- Implement pure decision structures and evaluation logic in `internal/core/retry.go` (and unit tests in `internal/core/retry_test.go`).
- Input model: request attempt state (attempt index, max attempts, deadline), client commitment state (`Committed` / Head handed off), error classification (`Retryable`, `RetryDisposition`, optional `RetryAfter`), candidate availability, and context cancellation.
- Output model: retry decision (allowed vs denied, reason for denial, candidate selection or next candidate index, validated backoff delay).
- Respect connector-classified `RetryAfter` only when within remaining deadline and cancellable context. Default/empty disposition is unknown and default policy is 1 attempt (no retry).
- Pure decision only: does not execute HTTP requests, does not loop or schedule retries, does not perform token accounting, and does not inspect provider response bodies.

## Acceptance

- [x] Decision allows retry only when all conditions hold: `Retryable == true`, `RetryDisposition == RetrySafe`, uncommitted (`!Committed`), attempt index < max attempts, context uncancelled, within deadline, and at least one eligible candidate remains.
- [x] Decision strictly denies retry if: error is not retryable, disposition is `RetryUnsafe` or `RetryUnknown` (including empty/unspecified), response has committed, attempt limit is reached, context is cancelled, or candidate list is exhausted.
- [x] Connector-reported `RetryAfter` delay is capped by remaining deadline; if `RetryAfter` exceeds the remaining deadline or context is cancelled during wait evaluation, retry is denied without busy looping.
- [x] Deterministic unit tests with controllable fake clock cover every branch of the decision matrix, including individual and combined negative conditions.

## Completion Evidence

Implemented `internal/core.DecideRetry` as a pure decision over typed Connector retry metadata, response commitment, zero-based attempt bounds, an injected `Now` and absolute deadline, cancellation state, and caller-supplied remaining eligible candidate indexes. It returns a candidate index and validated RetryAfter delay, denying unknown/unsafe dispositions, exhausted attempts/candidates, committed responses, cancelled contexts, invalid/missing/expired deadlines, negative delays, and delays beyond the remaining deadline. It does not wait, execute, schedule, re-evaluate eligibility, or perform accounting; the caller must wait cancellably and recheck the candidate before later execution.
