# M4-023 — Normalize cumulative usage and cache components

## Outcome

Normalize cumulative usage and cache components in the Anthropic Connector for both client Responses SSE output and Core `UsageReport`. One bounded deliverable in the [M4 registry](../TASKS.md#m4--first-translation-connector) toward the original [M4](../ROADMAP.md#m4--first-translation-connector).

## Scope

- In `internal/connector/anthropic/execute.go`:
  - Parse `cache_creation_input_tokens` and `cache_read_input_tokens` from Anthropic `message_start.message.usage`.
  - Calculate total input tokens without double counting: `total_input = input_tokens + cache_read_input_tokens + cache_creation_input_tokens`.
  - Track `cached_tokens` from `cache_read_input_tokens` without introducing new Core cache-write fields or public abstractions.
  - Support cumulative `message_delta` output token updates; replace rather than sum repeated snapshots.
  - Distinguish known zero (`0`) from missing/unknown (`nil`). Reject negative counters and arithmetic overflow conservatively.
  - Populate `core.CompleteFrame.Usage` (`core.UsageReport`) with normalized input, output, and cached tokens.
  - On stream interruption or premature error, retain partial/unknown usage parsed prior to termination with `core.UsagePartial` completeness.
- In `internal/connector/anthropic/responses_emitter.go`:
  - Update `responseUsage` to include `input_tokens_details` (`cached_tokens`) and `output_tokens_details` when known, matching Responses protocol conventions.
  - Ensure client-facing `response.completed` usage and internal `core.UsageReport` agree on token counts.
- In `internal/connector/anthropic/execute_test.go` and `responses_emitter_test.go`:
  - Add unit tests covering zero/missing, cache read/write, repeated/updated cumulative snapshots, invalid/overflowing counts, and premature interruption.
- Out of scope:
  - Stop reason classification and committed stream errors (M4-024).
  - Timeout and cancellation cleanup under races (M4-025).
  - Core admission / SQLite settlement verification (M4-028).
  - Thinking / reasoning token policy (M4-029, M4-030).

## Acceptance

- [x] Known fixture arithmetic matches client `response.completed` usage and `CompleteFrame.Usage`; total input equals base input plus cache-read and cache-creation tokens; cached tokens equals cache-read tokens; repeated cumulative snapshots are not added together.
- [x] Missing counters remain unknown (`nil`), zero counters are preserved as known (`0`), negative or overflowing counters fail closed with client-safe local error.
- [x] Interrupted streams preserve partial usage parsed prior to termination with `core.UsagePartial` completeness.
- [x] No new public fields are added to Core `UsageReport` or SQLite storage; cache-write details remain internal to the Connector.
