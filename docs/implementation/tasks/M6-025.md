# M6-025 — Compose external instances in protected startup

## Outcome

Compose and supervise external connector instances in protected gateway startup via strict opt-in process configuration and registry wiring. External connector instances are declared with launch tuples (`executable`, literal `args`, `working_directory`, empty `environment_allowlist`) in protected YAML, supervised via `external.StartSupervisor`, and registered with `core.Registry` under existing virtual-key, account, and policy routing rules. In-process connectors and legacy startup remain unaffected. See [registry](../TASKS.md#m6--external-plugin-runtime) and [milestone](../ROADMAP.md#m6--external-plugin-runtime).

## Scope

- Protected YAML configuration in `cmd/gateway/yaml_config.go`:
  - Add optional `process` block to `protectedConnector` with strict validation: `executable` (required absolute path), `args` (`[]string`, no shell expansion), `working_directory` (required absolute existing directory), and `environment_allowlist` (must be empty).
  - Enforce M6-BINDING launch validation: reject relative paths, non-existent directories, non-empty environment allowlists, duplicate connector IDs, and missing executables.
- Protected startup and registry wiring in `cmd/gateway/protected_startup.go` and `cmd/gateway/main.go`:
  - When a connector config includes `process`, instantiate and supervise it via `external.StartSupervisor(ctx, cfg)`.
  - Pass the supervised connector instance to `core.Registry` under its configured `core.InstanceID`.
  - Retain existing virtual-key, account, and policy validation: route targets, account existence, policy connector allowlists, RPM/TPM, and budget rules apply identically to external connector instances.
  - Wire supervisor lifecycle into gateway shutdown so `closeComponents` cleanly drains, terminates, reaps, and unlinks sockets for all external instances.
- Deterministic tests in `cmd/gateway/`:
  - Valid external connector YAML startup and readiness with dummy/helper child binary (`cmd/responses-connector-child`).
  - Validation rejection for invalid process configs (relative executable, missing working directory, non-empty environment allowlist, unknown fields).
  - Safe failure when child executable does not exist or fails startup handshake: gateway fails to start or reports unready cleanly without orphan processes or leaked sockets.
  - Regression parity: in-process connectors and legacy startup configuration continue to operate identically.
- Limits:
  - End-to-end HTTP client-to-gateway JSON/SSE delivery belongs to M6-026.
  - Fault injection, fallback accounting, and SQLite transaction rollback belong to M6-027.
  - Multi-account concurrent isolation belongs to M6-028.
  - Core runtime remains provider- and transport-agnostic (no IPC imports in `internal/core`).
