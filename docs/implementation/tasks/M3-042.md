## Scope

- In `cmd/gateway` (e.g. `cmd/gateway/access_admission_e2e_test.go`):
  - End-to-end HTTP tests with file-backed SQLite and running protected gateway handler/server against loopback fake upstream:
    - Key validity lifecycle: valid key succeeds; missing/invalid bearer format or revoked key via `runAdmin("key", "revoke", ...)` fails with 401 Unauthorized before reaching upstream (0 upstream calls).
    - Scope authorization: forbidden model or connector in policy fails with 403 Forbidden before reaching upstream (0 upstream calls).
    - Account disablement: account disabled via `runAdmin("account", "disable", ...)` or store rejects requests before dispatch (0 upstream calls).
    - Live policy update: policy updated via `runAdmin("policy", "update", ...)` takes immediate effect on subsequent requests at the admission boundary without gateway restart.
    - Concurrent RPM and TPM admission races: concurrent client HTTP requests contending on bounded RPM and TPM limits (using concurrency synchronization/barriers); exactly available budget reaches upstream, excess receives 429 Too Many Requests.
    - Clean failure semantics: rejected requests (401, 403, 429) leave no partial reservation or counter changes in `reservations` or `usage_records`.
    - Quota recovery: newly admitted traffic succeeds after limit window rollover or authorized quota update.
    - Credential isolation: upstream receives only configured connector credentials; master key and client virtual key secrets never leak to upstream headers or error responses.
- Explicit limits:
  - No new CLI commands or schema migrations; exercise existing `cmd/gateway/admin.go` subcommands and `internal/storage/sqlite`.
  - Single file-backed SQLite database in WAL mode; no distributed coordination.
  - Deterministic loopback fake upstream; no real provider credentials or paid inference.

## Acceptance
