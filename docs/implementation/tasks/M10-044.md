# M10-044 — Promote Antigravity llm.tools capability for admitted Responses models and verify gateway tool admission

## Outcome

Promote `llm.tools: core.Supported` in the Antigravity connector strictly for admitted Responses models (`gemini-2.5-pro`, `gemini-2.5-flash`) under `openai.responses.v1` translation mode, resolving the pre-dispatch HTTP 400 `unsupported_capability` blocker discovered in M10-043 while preserving opaque payloads, absent-include signature guards, and unadvertised parallel tool capabilities. Verify actual production gateway composition admission and end-to-end two-turn tool calling against a fake TLS upstream without live provider calls. Links row in [TASKS.md](../TASKS.md#m10--google-antigravity-connector) and [ROADMAP.md](../ROADMAP.md#m10--google-antigravity-connector).

## Scope

- `internal/connector/antigravity/component.go`:
  - Update `Capabilities` to declare `llm.tools: core.Supported` when `c.state == core.HealthReady`, `scope.Protocol == "openai.responses.v1"`, `scope.Mode == core.ModeTranslation`, and `scope.Model` is exactly an admitted model (`gemini-2.5-pro` or `gemini-2.5-flash`); empty model scope is not supported.
  - Explicitly restrict `llm.tools: core.Supported` so that unsupported models, native mode, or other protocols return `Unknown` (or omitted).
  - `llm.tools.parallel` remains unadvertised / Unknown.
  - `auth.oauth` and `usage.exact` remain Unknown.
- Documentation and Architecture Decisions:
  - Update `docs/implementation/M10-BINDING.md` capability section to document scoped `llm.tools: supported` for admitted models.
  - Record ADR `DEC-032` in `docs/project/DECISIONS.md` documenting scoped enablement of `llm.tools` for Antigravity translation without parallel tool support or core bypass.
- Tests:
  - Unit tests in `internal/connector/antigravity/execute_test.go` (or `component_test.go`) verifying `Capabilities` matrix:
    - `Supported` for `openai.responses.v1` / `ModeTranslation` / `gemini-2.5-pro` and `gemini-2.5-flash`.
    - Not `Supported` for `ModeNative`, other protocols, unsupported models (e.g. `unknown-model`, `gpt-4o`), or `llm.tools.parallel`.
  - Standalone gateway composition test in `cmd/gateway/antigravity_tool_admission_test.go` (isolated from M10-043 frozen files):
    - Spin up production gateway with real configuration, router, Responses adapter, core dispatch, Antigravity connector, and a loopback fake TLS provider.
    - Dispatch `/v1/responses` with `gemini-2.5-flash`, `stream: true`, nonempty `tools`, `tool_choice`, `include: ["reasoning.encrypted_content"]`.
    - Verify request passes Core capability check and reaches fake provider (no HTTP 400 `unsupported_capability`).
    - Turn 1: fake provider returns candidate function call with signed carrier; gateway translates and streams `function_call` item + encrypted carrier.
    - Turn 2: client replays function output + preserved in-memory carrier; gateway translates and executes replay; fake provider returns final text delta; stream completes HTTP 200.
    - Negative tests: request with `tools` on an unsupported model rejected with HTTP 400 `unsupported_capability`; absent `include` guardrail unchanged (fails closed on upstream signed part).
- Explicit limits:
  - Standalone tests must NOT edit or depend on frozen uncommitted M10-043 files (`cmd/gateway/antigravity_tool_runner_test.go`, `scripts/antigravity-live-tool-smoke.sh`, etc.).
  - Zero live provider calls or budget consumption.
  - No Core runtime capability bypass or provider-specific Core logic.
