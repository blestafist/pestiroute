# M2-003 — Bind model, estimate and authentication support operations

## Outcome

The common Connector API retains its v1 support operations without pretending that M3 authentication or tokenization exists. See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Connector support operations](../CONTRACT.md#connector-contract), [usage semantics](../CONTRACT.md#usage-and-scoped-runtime-services).
- [Capability scope and support operations](../M2-BINDING.md#capability-scope-and-support-operations), [support operations table](../M2-BINDING.md#support-operations).
- Shared types in `internal/core/component.go` produced by [M2-002](M2-002.md).

## Scope

- Define `ModelQuery`, `ModelInfo`, `ModelsResult`, `UsageQuery`, `EstimateResult`, `AuthRequest`, and `AuthResult` types in `internal/core`.
- Define `Connector` interface with `Component`, `Execute`, `Models`, `EstimateUsage`, and `Authenticate` signatures, along with required `InvocationServices` boundary types (`CredentialAccess`, `HTTPDoer`).
- Represent configured model metadata/availability, unknown estimates, and unsupported authentication steps explicitly without model HTTP discovery, tokenizers, credential persistence, or provider-specific methods.

## Acceptance

- [x] Unknown estimate (`Known: false` or nil `Usage`) is distinguishable from known zero usage (`Known: true` with zero counters).
- [x] Scoped model availability (`Available *bool`) and missing metadata stay unknown; `Models` never fabricates IDs or synthetic availability.
- [x] Unsupported authentication cannot report success or persisted credentials (`Supported: false`); authentication operations represent single state-machine steps without secret persistence.
- [x] Minimal/fake compile-time implementation satisfies `core.Connector` without real network discovery or external dependencies.
