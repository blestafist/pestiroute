# M2-021 — Drain and cancel managed components on shutdown

## Outcome

Managed components and registered instances obey bounded gateway shutdown: admission cutoff, readiness withdrawal, up-to-`shutdown_timeout` active-work drain, then a separate up-to-`shutdown_timeout` Close grace (maximum two configured intervals). See [registry](../TASKS.md#m2--connector-api-and-conformance-baseline) and [M2](../ROADMAP.md#m2--connector-api-and-conformance-baseline).

## Read First

- [Shutdown/cancellation](../CONTRACT.md#component-descriptor-and-lifecycle), [M1 shutdown evidence](M1-019.md#completion-evidence).
- `cmd/gateway/main.go` (`run`, `composeHandler`, `composeHandlerWithFactory`, `handlerWithLifecycle`), `internal/core/registry.go` (`Close`).

## Scope

- In `cmd/gateway/main.go`, integrate explicit admission stop, readiness withdrawal, active-request drain, deadline cancellation, and component Close across all registered components in that order.
- Give component Close its own bounded grace after drain; document the total process budget as at most two `shutdown_timeout` intervals. `Registry.Close(ctx)` attempts every registered component concurrently so one non-cooperative Close cannot strand the others.
- Extend test coverage in `cmd/gateway/main_test.go` with multi-instance topology (two connector/adapter instances) plus blocked streaming under real-socket SIGTERM/drain; assert upstream cancellation, single attempt finalization, and repeated Close safety.
- Exclude hot reload, background supervisors, deployment packaging, or non-deterministic real-provider tests.

## Acceptance

- [x] New inference is rejected with 503 during drain; existing admitted work can complete within the configured shutdown budget.
- [x] Expired drain deadline cancels in-flight provider and stream requests and closes all registered components once.
- [x] Process exits cleanly within its documented budget, and a failed Close on one component does not prevent or strand closing remaining components.
- [x] Attempt finalization records exactly one terminal outcome per attempt during shutdown.
