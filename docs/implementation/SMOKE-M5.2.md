# M5.2 local-runtime smoke procedure

This is the operator procedure for the independent [Ollama M5.2-024](tasks/M5.2-024.md), [vLLM M5.2-025](tasks/M5.2-025.md), and [llama.cpp M5.2-026](tasks/M5.2-026.md) live gates. It compares local direct Responses requests with the protected PestiRoute `/v1/responses` route; it does not assert generated-text equality or promote support by itself. The [source-scoped policy and pins](M5.2-LOCAL.md#versioned-request-semantic-policy-m52-005) and [M5.2-007 environment inventory](M5.2-LOCAL.md#local-execution-environment-and-inventory-m52-007-observed-2026-10-11) remain authoritative.

## Authorization, isolation, and bounds

Run only the one runtime card after its operator has provisioned that exact local runtime, model artifact, and (where applicable) GPU, template, parser, and gateway route. Each card is independently runnable: a missing executable, daemon, model, compatible hardware, or resource capacity blocks only that runtime card. Do not substitute another runtime/model, use Ollama cloud or any hosted endpoint, install/build/download/pull anything as part of the smoke, or launch a daemon without separate operator setup authorization. Bind both inference services to loopback and verify their actual listening addresses before sending a request. Never put credentials in command history, request files, logs, or evidence.

Use CPython **3.14.7** with `http.client`; the checked-in runner below enforces the one-request pair, monotonic 30-second deadline, 1 MiB response-byte ceiling, and opaque body equality. Record `python3 --version` and `git rev-parse HEAD`. Each individual scenario is a direct/gateway pair with exactly one request per leg, one attempt, zero retries, and at most 4096 requested/output tokens. The runner stops at the byte ceiling plus one sentinel byte and closes connections on every outcome; it never reconnects or replays. `max_output_tokens: 4096` is a requested generation ceiling, not proof of provider enforcement. If any bound cannot be enforced, do not run.

Use only harmless synthetic prompt text and fixed synthetic function results. Save no prompt, raw request/response, tool arguments, headers, IDs, credentials, or free-form generated text. Retain only validator-approved observations and sanitized run notes. Artifacts are mode 0600 in a private temporary directory; keep only reviewed sanitized artifacts and remove temporary request/output files. For the same scenario, direct and gateway requests must use the same model artifact, exact request bytes/options, runtime settings, and equivalent history. IDs generated by the backend remain within their own leg; never splice direct IDs into gateway history or compare stochastic prose.

### Exact matched-pair runner command

Prepare a private body file with no credential or private prompt; only its `model` value is replaced by the exact configured model. Keep the body identical for both legs:

```sh
umask 077
RUNTIME=ollama
mkdir -m 700 -p "$HOME/.local/share/pestiroute/m52-$RUNTIME"
MODEL=qwen3:8b # Replace only with the already-provisioned exact runtime model.
BODY="$HOME/.local/share/pestiroute/m52-$RUNTIME/text-sse.json"
printf '{"model":"%s","input":"Reply with the word OK.","max_output_tokens":4096,"stream":true}' "$MODEL" >"$BODY"
```

Run from repository root after `python3 --version` confirms CPython 3.14.7. Set both auth environment variables through the operator's secret-safe shell mechanism. Set `GATEWAY_PORT`, `MODEL_REVISION`, `TEMPLATE_ID`, and `PARSER_ID` to the exact provisioned values; the immutable identifiers must have `sha256:` followed by 64 lowercase hex digits (or a `git:` SHA-1 for model revision). For the selected Ollama row, for example:

```sh
python3 scripts/smoke-m5.2-artifacts.py --run-pair \
  --profile ollama \
  --direct-url http://127.0.0.1:11434/v1/responses \
  --gateway-url "http://127.0.0.1:$GATEWAY_PORT/v1/responses" \
  --body "$BODY" --stream true \
  --direct-auth none \
  --model-revision "$MODEL_REVISION" \
  --template "$TEMPLATE_ID" --parser "$PARSER_ID" \
  --gateway-dispatches 1 \
  --output-dir "$HOME/.local/share/pestiroute/m52-ollama/sse-artifacts"
```

For vLLM and llama.cpp, replace `--profile` with `vllm` / `llama.cpp`, the direct URL with the row endpoint, `--direct-auth` with `none` or `bearer` matching the actual direct-server setting, and output directory with its runtime name. With `bearer`, set only `PESTIROUTE_M52_DIRECT_BEARER` in the environment; always set `PESTIROUTE_M52_GATEWAY_VKEY` separately. `--gateway-dispatches 1` is not guessed: in a quiet isolated runtime, take a trusted local `/v1/responses` ingress request-counter/access-log count immediately before and after the paired run. The runner sends direct first and gateway second, so require exactly two new ingress records in that order and supply the observed gateway-leg delta (one). Count only method/path records; do not retain request bodies, prompts, headers, or generated text. If the provisioned runtime exposes no trustworthy body-free count, stop and leave dispatch evidence unverified instead of fabricating this argument. The command writes mode-0600 direct/gateway artifacts and invokes the strict validator after successful SSE completion. It does not print or persist response bodies.

For JSON, use the same command and body with `--stream false`; runner enforces the same request/deadline/byte/token/auth rules and emits only a sanitized success line. JSON is intentionally not written as a validator artifact because schema v1 requires `stream:true`. Change the body field to `"stream":false`; never submit a body whose flag disagrees with `--stream`.

## Matched text requests

Run each JSON and SSE scenario as a separate one-request pair. Use CPython's standard `http.client` against each URL, POST the exact same UTF-8 JSON body, and set `Content-Type: application/json`; add only the gateway virtual-key Authorization header on the gateway leg. The JSON shape is:

```json
{"model":"<exact configured model>","input":"Reply with the word OK.","max_output_tokens":4096,"stream":false}
```

For the SSE scenario, change only `stream` to `true`. Parse the event stream incrementally and record status, first text-delta latency, event categories/order, terminal observation, reported usage presence, end-to-end latency, response bytes, and exactly-one dispatch. Require first delta before terminal for a successful incremental-delivery observation. Do not infer compute cancellation from closing the client connection. No tool call, reasoning, parallel call, state continuation, or structured-output behavior is implied by text success.

The checked-in `scripts/smoke-m5.2-artifacts.py` now provides the bounded loopback-only `--run-pair` request runner as well as strict artifact validation and an offline fake harness. For each successful SSE direct/gateway pair, the runner constructs one validator-schema JSON artifact per leg from sanitized observations; it never writes request bodies, prompts, response bytes, or credentials. Keep identical profile/runtime/model revision/template/parser/client/limits/request/outcome fields across the pair; only `leg`, capture time, and measured observations may differ. The validator intentionally requires a single streamed HTTP 200 request, one dispatch, zero retries, matched terminal/outcome, immutable identities, and output tokens either within the ceiling or `"unknown"`; it cannot validate JSON (`stream:false`) artifacts. For JSON pairs, runner emits only a sanitized success line; keep any additional status/latency observations as sanitized operator notes, not fake validator artifacts.

```sh
umask 077
PROFILE=ollama # Or vllm / llama.cpp for the selected independent gate.
OUT="$HOME/.local/share/pestiroute/m52-$RUNTIME/sse-artifacts"
python3 scripts/smoke-m5.2-artifacts.py "$OUT/$PROFILE-direct.json" "$OUT/$PROFILE-gateway.json"
```

Each artifact's `limits` must be `{"max_requests":1,"max_latency_ms":30000,"max_output_tokens":4096,"deadline_seconds":30,"max_response_bytes":1048576}`. `requests` contains exactly `{ "attempt": 1, "status": 200, "stream": true }`; observations include actual `dispatches: 1`, `retries: 0`, bounded integer `latency_ms`/`first_delta_ms`, observed `terminal`/matching `outcome`, and bounded `output_tokens` or `"unknown"`. For text first-delta latency, `first_delta_ms` is measured only on `response.output_text.delta`, not reasoning or function-argument deltas. Artifact `profile` is the validator's **short key**: `ollama`, `vllm`, or `llama.cpp`; `runtime` is respectively `Ollama v0.40.3`, `vLLM v0.31.0`, or `llama.cpp v0.6.0`. These short keys map to connector profile IDs `ollama-responses-http-sse-v1`, `vllm-responses-http-sse-v1`, and `llamacpp-responses-http-sse-v1` in the profile table; do not put the long IDs in artifact `profile`. `client` is `{"name":"Python http.client","version":"3.14.7"}`. Tool/parser fields identify actual immutable SHA-256 values; where no parser applies, record the actual selected no-parser configuration identity, not `default` or an invented hash. `captured_at_utc` is the actual UTC capture time in `YYYY-MM-DDTHH:MM:SSZ` form. Keep notes/provenance separate from validator artifacts; artifact fields are strict and credentials/prompts are forbidden.

## Optional client-owned function call

Only probe after exact protocol/mode/model/account tool support has been independently reviewed and the protected route declares it supported. Model-dependent tool capabilities otherwise remain Unknown and Core must reject with `unsupported_capability`; do not force or bypass admission. `--tool-capability-reviewed` acknowledges that prior review but cannot alter route configuration. The bounded `--tool-roundtrip` mode sends the identical initial body to both legs, accepts one fixed `smoke_lookup` call with only `alpha`/`beta` arguments, retains each leg's returned item/call IDs in memory, and builds a separate continuation for each leg using its own IDs and the fixed synthetic marker. It makes at most two requests per leg, no retries, executes no model instructions, and writes only a private sanitized summary of call/result link counts and terminal categories. Missing/unsupported capability, invalid or multiple calls, or incomplete continuation stops the mode without a success summary. Never enable parallel calls or server-executed tools.

Example request body:

```json
{"model":"<exact configured model>","input":"Call smoke_lookup once with key alpha.","tools":[{"type":"function","name":"smoke_lookup","description":"Return a fixed synthetic marker.","parameters":{"type":"object","properties":{"key":{"type":"string","enum":["alpha","beta"]}},"required":["key"],"additionalProperties":false}}],"max_output_tokens":4096,"stream":true}
```

After capability review and operator authorization, use the same identity/auth arguments as the text pair, with `--tool-roundtrip --tool-capability-reviewed`, and require two gateway dispatches from the independent trusted ingress counter. The total ingress order is direct, gateway, direct, gateway; retain only method/path counts, not bodies or headers.

```sh
python3 scripts/smoke-m5.2-artifacts.py --tool-roundtrip --tool-capability-reviewed \
  --profile "$PROFILE" --direct-url "$DIRECT_URL" --gateway-url "$GATEWAY_URL" \
  --body "$TOOL_BODY" --stream true --direct-auth "$DIRECT_AUTH_MODE" \
  --model-revision "$MODEL_REVISION" --template "$TEMPLATE_ID" --parser "$PARSER_ID" \
  --gateway-dispatches 2 --output-dir "$TOOL_OUT"
```

## Zero-send rejection checks

Do not probe the backend directly with unsupported fields. For each selected probe, write the exact body below to a mode-0600 private file, substituting the configured model only. Send exactly once to the protected gateway using:

```sh
python3 scripts/smoke-m5.2-artifacts.py --check-rejection \
  --gateway-url "http://127.0.0.1:$GATEWAY_PORT/v1/responses" \
  --body "$BODY" --expected-code "$EXPECTED_PROTECTED_CODE" --gateway-dispatches 0
```

The tool sends only the gateway virtual key, reads the response under the 30-second/1 MiB limits, retains no response bytes, and requires HTTP 400 plus the exact `--expected-code` for that probe. Connector semantic preflight rejects as `unsupported_semantics`; protected Adapter/Core capability admission rejects as `unsupported_capability`; `unsupported_target` applies when no route candidate exists or Core must reject unsafe multi-candidate affinity, not merely because a stateful field is present on a single-target route. The procedure assigns one exact code per body; do not accept another code as a substitute. Before and after **each single request**, read the quiet runtime's trusted local incoming `/v1/responses` access counter; the count must remain unchanged (delta zero). The counter must report method/path only, contain no body, prompt, credential, or generated text, and have no other concurrent users. If unavailable, mark the zero-send proof unverified and stop.

## Gate result, cleanup, and limits

M5.2-024, -025, and -026 have independent readiness and evidence. Missing resources or a failed runtime stop only that runtime's card; do not fabricate artifacts from the offline fake, and do not block another independently provisioned runtime. On any timeout, byte/token cap hit, unexpected status/terminal, auth ambiguity, non-loopback endpoint, secret exposure, unexpected dispatch, or inability to establish immutable provenance: stop that scenario, close the connection, do not retry, preserve no raw payload, and record the concrete blocker/unblock condition in that runtime's card. Keep absent observations Unknown. Direct and gateway compare transport/event/usage observations, not generated text equality, billing parity, hardware performance, or backend compute cancellation.

The procedure is documentation only. M5.2-023 performs no daemon launch, package/model download, live request, or inference. `--self-test` for the artifact tool uses only synthetic loopback SSE and is not live evidence.
