# M5.1 Codex Subscription Connector Planning Brief

Planning input for [M5.1](ROADMAP.md#m51--agent-protocol-connectors), scoped to
Codex only. This is not an accepted binding or a support claim. The supplied
[research](../references/CODEX_CONNECTOR_RESEARCH.md) is preserved with trailing EOF whitespace normalized;
its proposals must be reconciled with the merged M4 implementation.

## Outcome and boundaries

Build an in-process Agent Protocol Connector for the ChatGPT subscription
backend, using Responses HTTP/SSE and device authorization. Reuse protected
accounts, encrypted storage, auth coordination, admission, reservations,
settlement and checked Head/Body/Complete/EOF. The client owns conversation
history and tool execution. Core stays free of provider payloads and token JWTs.

The candidate first profile accepts streaming Responses, client-owned function
tools and the M5.1-047 scoped custom grammar/Lark tool form, full client-supplied
history and opaque encrypted reasoning replay. Custom grammar remains opaque and
unexecuted; only its offline protected gateway flow is established, not a live
gateway custom-tool round.
Input adaptation is explicit translation; native request byte preservation must
remain available only when no body change is necessary. Output observations
must preserve original SSE bytes, item IDs, call IDs, order and extensions.

Claude Code, Gemini CLI and ACP remain separate roadmap spikes. Browser PKCE,
WebSockets, Lite features beyond the explicitly accepted profile, remote model
discovery, compaction, hosted tools, vision/audio, background/resources and
other northbound protocols are outside this slice. A source check finding Lite
mandatory must record a blocker or propose bounded follow-up work; never
silently switch profiles or disable parallel calls. Do not spawn a Codex/OpenCode
process inside Execute.

## Authentication and credential gates

M5.1-002 resolves device presentation, pending polling and deadline ownership.
User-visible URL/code must be a separate bounded safe projection; do not print
device_auth_id, PKCE material, tokens or arbitrary Connector state. Pending
polls use the existing continuation action and fixed runtime expiry, enforce
the provider interval and remain cancellable. The provider-specific flow
exchanges an authorization code/verifier; do not invent an RFC device-code grant.

M5.1-003 defines credential names, atomic revision, trusted account identity,
absolute access expiry, refresh margin, bootstrap and missing-refresh-token
policy. The existing one-row store may fit a versioned encrypted OAuth bundle;
that choice still needs an explicit binding and expiry-aware composition.
Runtime must not decode provider JWTs or silently merge candidate credentials.
Tokens are parsed only by the Connector from a trusted exchange. A refresh
waiter must re-check freshness under the account lock, even if it entered after
an earlier refresh committed. A rotating-token exchange is never retried after
an uncertain response or unacknowledged persistence.

Resolve any semantic gap through DECISIONS, CONTRACT and compatibility policy
before implementation. This planning commit accepts no new v1 semantics.
Record a concrete blocker only when an affected decision cannot be resolved
within existing authority; unrelated local cards may continue.

## Request stream and accounting gates

M5.1-004 defines the standard dialect, selected-account headers, unknown fields,
native versus translation mode, explicit model replacement, store/stream policy,
generation controls, tool namespaces, history chronology, encrypted replay,
limits and phase deadlines. Reject meaningful unsupported values before send;
never silently remove an explicit max_output_tokens or requested parallel tool
requirement. Preserve input items, phases and opaque reasoning extensions.

Start with one account/model/profile per Connector instance and a singleton
route for account-bound replay. Client account/auth/session headers never choose
the selected account or become trusted cache affinity. Do not fan out opaque
reasoning to another account or profile. Validate safe cache metadata separately
from previous-response resource ownership.

Observe SSE incrementally with bounded state and preserve original output bytes.
Completed, incomplete, failed, error and EOF-without-terminal have distinct
outcomes. Inclusive input/output totals contain cached/reasoning subsets; do
not double count. Missing usage is unknown, interrupted reported usage is
partial, and neither is zero. Quota windows are separate from token accounting;
quota dashboards/probes are not this slice.

Only conclusive no-send evidence may permit runtime-policy fallback. HTTP 401
does not authorize refresh-and-replay inside Execute. Unknown send, post-Head
failure and client disconnect must not create another inference attempt.
Finalize reservations/attempt/request closure exactly once on every path.

## Local versus live acceptance

All implementation cards use deterministic local fixtures and synthetic accounts.
M5.1-036 audits the offline gate and matrix; this does not complete live release
acceptance. M5.1-038/039 prepare bounded capture and validation offline.
M5.1-040/041 execute separately scoped live gates only with available selected
account access and authorization. If access is missing, mark the relevant card
BLOCKED with its unblock condition; preserve local evidence and proceed with
other eligible work. DEC-008 defers only the M4 Anthropic gate and does not
authorize Codex live deferral.

Pin client/profile/model/account scope for direct-versus-gateway text, tools,
parallel-call preservation and a scoped client-owned encrypted-reasoning
follow-up. This is not a requirement to demonstrate every reasoning/history form
live; broader forms remain unknown unless separately researched and verified.
Define request, elapsed-time and output safeguards without assuming an
unsupported token cap enforces them. Do not revoke a working credential to
manufacture a refresh test. Synthetic concurrency/restart proofs remain
separate from live auth.
M5.1-042 audits claims against evidence; 043 checks all acceptance and prepares
the next scoped handoff. Never call M5.1's other connectors implemented.

## Tooling

Keep Context7, official gopls MCP, shell/file/Git tools and the pinned Go checks;
see [M5.1 tooling gate](TOOLING.md#m51-tooling-gate). No new MCP, agent skill,
browser automation, WebSocket library or SDK is required by this initial slice.
The user's browser completes device authorization; the agent does not need a
browser MCP to implement or test its local state machine. This is a repository
configuration recommendation, not a new check of the user's running plugins.
