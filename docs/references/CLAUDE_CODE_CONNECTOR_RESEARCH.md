- **Client:** Anthropic Claude Code terminal CLI, distribution `@anthropic-ai/claude-code` **2.1.300**, published 2026-10-14. - **Candidate backend:** Anthropic's first-party Claude Code inference service using a user's Claude Pro/Max subscription sign-in (“Claude.ai subscription OAuth” in the official [authentication documentation](https://code.claude.com/docs/en/authentication)). This is distinct from Claude Console/API-key billing and third-party inference providers.
- **Backend version/revision:** not published or versioned in the cited materials; no service protocol version, endpoint contract, or backend source revision could be pinned. The client release is only the exact target for future research, not evidence of its wire compatibility.

## Evidence boundary

**Source evidence:** Anthropic documents subscription sign-in as a Claude Code authentication option, and separately identifies API-key, Console and cloud-provider modes. The published CLI release is pinned above. Official legal/compliance and terms pages describe restrictions on certain third-party subscription credential/login and service-use behaviors. This records published text, not its legal applicability to a proposed use.

**Published plan/usage and billing behavior (help-center pages checked 2026-10-15):** Pro and Max plans have a rolling five-hour session limit and weekly limit, shared across Claude surfaces including Claude Code. Max has an additional weekly Fable limit. Allowances differ by plan; usage also varies with model, conversation length/complexity, features and effort. The sources do not publish a fixed quota suitable for assuming an account's capacity; current account usage/model availability is surfaced in Settings or `/model` and can change. At the five-hour limit, a small, capped wrap-up may finish only an already-started response; it counts toward the weekly limit, is limited to once per weekly period on Pro and each five-hour limit on Max within the weekly limit, and is rolling out so may not be enabled for every account. Separately, when a user enables Usage Credits and funds/configures them, requests after included limits can continue on consumption-based standard API rates; these charges are separate from subscription fees and may use configured auto-reload/monthly spend cap. Choosing Claude Console/API-key authentication is also pay-as-you-go, not subscription-included usage. Monthly API credits included with Max/Team do not apply to Claude Code. These are published product descriptions, not observed runtime or entitlement evidence.

**Observed runtime evidence:** none. No Claude Code client was installed or run, no credential was inspected, and no provider/backend request was made. No wire capture or compatibility test exists.

**Unknowns / next research questions:** the subscription service endpoint/version and wire protocol; precise OAuth flow, token audience/refresh/expiry and account identity; request/response and stream framing, usage, errors, tool/reasoning fields; statefulness, retry safety and cancellation; account-specific included quotas and exact behavior/eligibility for optional credits; which published terms apply to a contemplated use and any necessary written authorization. The terms and policy entries above are source inventory, not legal advice or a determination of permission. Do not use leaked or unofficially republished client source. Resolve constraints and sources in later M7 research before implementation planning; live observation requires its own explicit authorization.

### Mapping to host-owned auth services

The existing contract provides a generic `Authenticate` start/continue/refresh state machine, opaque Connector continuation state, optional safe presentation action, candidate credential bundle, and optional absolute expiry sourced by the Connector from a trusted exchange ([CONTRACT auth operation and result](../implementation/CONTRACT.md#connector-contract)). Core owns session binding/expiry/claims and encrypted credential persistence; selected-account scope, serialized per-account refresh, revision-CAS replacement, expired-credential access only during refresh, and uncertain-outcome quarantine are specified in [M3-AUTH](../implementation/M3-AUTH.md). The runtime-assigned account ID is not supplied by client auth state.

This is structural alignment, not evidence the candidate service fits the contract. The published sign-in option could conceptually be represented by the generic auth operation, but the unpublished exchange, credential shape, trusted expiry source and account identity leave Connector conformance and safe credential persistence unestablished. In particular, host account isolation cannot by itself prove that a provider credential belongs to the selected subscription/account. Exact refresh/concurrency behavior cannot be mapped to the runtime protocol while the provider behavior remains unknown. These are feasibility gaps for later review, not a proposed contract change.

The [official legal/compliance page and terms inventory above](#dated-source-inventory-and-reuse-status) records Anthropic's published restrictions concerning third-party Claude.ai subscription login, credential/session-token handling and service use. This note makes no determination about applicability, authorization, or legal effect; the cited page's statements are not a permission or implementation plan.
